# Machinery

The scripts behind `pnpm prd` (`scripts/loops/`) that every session leans on: worktrees and leases, recorded sessions and the asks queue. Moved out of [orchestrator](orchestrator.md).

## Worktrees and leases

- `new.sh <kind>`: `prd <topic>` (`.loops/<topic>`, from `dev`, a stack), `slice <topic> <n>` (`.loops/<topic>-<n>`, from `prd/<topic>`, a stack only for `Stack: yes` or `--stack`), `plan <topic>` and `hotfix <name>` (stackless, from `dev`). Options: `--slot N`, `--stack`/`--no-stack`, `--base B`. An existing branch is checked out, resuming a removed worktree. Secrets come from the main checkout's env files.
- **Slots** (1–19) are lock directories in `.loops/.slots/<N>`, taken atomically; a slot is also busy while a `.env` names it or a port listens. Ports: [loop](loop.md#your-worktree-and-stack).
- **The shared test Postgres** (`pnpm prd test-db`, :5436, tmpfs, Compose project `caretook-shared-test`): a database per worktree, dropped by `rm.sh`; `test-db down` deletes them all. Older worktrees keep a `-test` container or switch with `test-db use`.
- `pnpm prd status` flags `merged:` slice worktrees and `stopped stack:`s (over `CARETOOK_GC_STOPPED_HOURS`, 24); `gc` removes them after a yes. **The disk guard** refuses a new stack or check build under `CARETOOK_MIN_FREE_GB` (10) free; `reclaim` frees merged worktrees, dangling volumes and images, check builds and Vite caches (never the main checkout's, a dirty worktree, or a running server's caches).
- **`pnpm prd tidy`** (`tidy.mjs` sorts, `tidy-cli.mjs` collects and acts) lists leftovers as **safe** (merged clean slice worktrees with nothing running in them, landed plan worktrees, dead lease and slot tickets, orphan test databases (owned by no worktree; worker copies are `caretook_tw_<stem>_<hash>_w<n>`, so no base can match one), stale remote refs, dangling `caretook` volumes, week-old browser-hang logs, ended records with no worktree) or **ask** (live sessions that look finished, branches with no worktree, items to archive, registry rows that look done; `hold` rows are skipped). `--yes` removes the safe ones and files the ask list as one `pnpm prd ask --report`; `--json` only lists. When `lsof` fails, every worktree's processes are unknown and it's kept. Never: a dirty worktree, live caches, the main checkout, an unmerged branch, a session. `pnpm prd prompt tidy` is a haiku brief that runs it every few hours with `/loop` and asks finished-looking sessions over SendMessage.
- `rm.sh <name>` removes the worktree, its stack, database files and slot, and deletes the branch if merged into its parent; it refuses uncommitted changes, or a PRD with slice worktrees left, unless `--force`.
- **`pnpm prd dev-sync`** (run by `land`) brings the main checkout's `dev` up to `origin`: a fast-forward, else it rebases unpushed backlog-tool commits, else a merge commit; it stops on uncommitted edits to files the landing changed.
- **Machine leases** (`lease.sh`, `lease.mjs`): `browser` 2, `check` 2, others 1 (`CARETOOK_<KIND>_SLOTS`), lock directories in `.loops/.lease/<kind>/<N>`, taken over from dead holders. Waits are bounded (`CARETOOK_<KIND>_WAIT`; browser 20 min, check 30) and give up with exit 75. `CARETOOK_LEASES=off` takes none.
- **`pnpm prd wait [check|browser|<kind>] [--timeout S] [--worktree W]`** (`lease.sh wait`) blocks until the worktree's lease, held or queued, is gone; 75 at the timeout (3600 s). Never `pgrep -f`.

## Recorded sessions

- **`session.sh <name> [--kind prd|plan] [--topic <t>] [--auto] [--managed] -- <claude args>`** runs `claude` (`CARETOOK_CLAUDE_BIN` in tests) in the foreground and keeps a record in the main checkout's `.loops/.sessions/<name>.json`: `pid` (claude's own), `kind`, `topic`, `started`, `command`, `auto`, `managed` (the dispatcher started it), `rotating`, and `ended` and `exit` once it exits (only while the record's `pid` is still its own: `sessions.mjs set --if-pid`). Names are `prd-<topic>` and `plan-<topic>`. Records outlive the session; `rm.sh` deletes the worktree's. Nothing is written inside a worktree.
- `pnpm prd start`'s printed command, the dispatcher, `prd plan --open` and the opener all start through it; `pnpm prd status` marks each session managed or by hand.
- **Live** means no `ended`, the pid exists and that process started within a minute of `started` (a reused pid isn't). `node scripts/loops/sessions.mjs self` prints the calling shell's session pid: its worktree's live record, else its ancestor `claude` process (a session started before the wrapper).
- **`pnpm prd end [<name>]`** ends a session (TERM, KILL after `CARETOOK_END_WAIT`, 10 s): the named record, or with no name the caller's own, so it works after `pnpm prd rm`. With neither a record nor an ancestor it refuses.
- **The opener** (`open-session.sh`) writes `cd <dir> && exec …` to the tab it made, so the tab closes with the session. It carries a record's `auto` and `managed` over (an `auto` planner reopens with `--auto`) and opens fresh, never `--continue`, after a `rotating` record. `--background` doesn't bring iTerm2 forward and reselects the earlier tab; `--command <line> --title <t>` opens any line.

## Rotation

- **`pnpm prd rotate [<topic>] [--mid-wave] [--reason <text>]`** (`rotate.sh`) finds the session to end (the live `prd-<topic>` record, else the calling shell's ancestor `claude` from that worktree) and opens `rotate-into.sh` in a background tab, then returns. It refuses with uncommitted plan changes, with slice worktrees left (unless `--mid-wave`), or with no session found. Without iTerm2 it prints the command and ends nothing.
- `rotate-into.sh <name> <pid>` sets `rotating`, ends the pid (TERM, KILL after `CARETOOK_ROTATE_WAIT`, 20 s), waits for its wrapper to record the end, then execs `session.sh` with `prompt.sh orchestrator <topic> --resume` (`--auto` from the record or _Status_): fresh, the same name.
- `rm.sh`, removing a merged `prd/` worktree whose _Status_ has no slice left, sets the registry's `done` flag (dropping `hold`), except for a `standing` topic.
- `pnpm prd status` adds the recorded sessions (live, rotating or ended, age, run-through; ended over a day ago left out) and the open asks (count, the oldest).

## The dispatcher

- **`pnpm prd dispatch`** (`dispatch.mjs`; the user starts it in a tab of its own; `--every <s>`, 60): each tick gathers the facts (`pnpm backlog prd list --json`, worktrees, session records, open asks, the load gate, its state), asks the pure pick (`dispatch-pick.mjs`) for one action and does it: **start** (`new.sh prd`, then a managed run-through orchestrator), **plan** (`new.sh plan`, a managed `--auto` planner on opus), **reopen** a dead managed session (the opener, counted), or **ask** after the third death. The record is written before the tab opens. `--once`, `--dry-run` (writes and opens nothing; shows every passed-over topic's reason), `--pause [<why>]`, `--resume`, `--stop` work from any shell. Without iTerm2 only `--dry-run` runs.
- **The pick**, in order: paused does nothing; reopens (not a record `rotating` under five minutes; a session live 30 minutes resets its count); busy stops starts and plans; then starts before plans, in row order, within `CARETOOK_MAX_PRDS` (unmanaged worktrees are only reported but take a slot and their hot files), skipping `hold`, `done`, an `After` not done, a hot-file collision (prefixes as plain text), `alone`, and a topic with a question awaiting an answer (a defaulted one doesn't count; each tick settles due asks first). A second fixes topic waits while one runs; a fixes topic with fewer than `CARETOOK_FIXES_MIN` (3) waiting items starts only when nothing else may; `idle` never starts. One planner at a time (`CARETOOK_MAX_PLANNERS`), a second only while the first waits on an ask. No hold after planning.
- **Its asks:** filed with `pnpm prd ask` (session `dispatch`), then a one-shot haiku helper tab sends the PushNotification and ends (a helper that fails is ignored). A later tick acts on the answer: "reopen again" resets the count, "hold the topic" flags the row `hold`.
- **Files** in the main checkout's `.loops/`: `.dispatch.lock` (pid; a dead one is taken over), `.dispatch.json` (paused and why, reopen counts, open asks, last tidy), `.dispatch.log`. On an idle tick every six hours it runs `pnpm prd tidy --yes`. No usage-limit handling: pause and resume. `pnpm prd queue <topic>` only moves the row first.

## The load gate

- `load-gate.mjs`: busy when the 5-minute load is above `CARETOOK_LOAD_BUSY` (twice the cores); `CARETOOK_LOAD_GATE=off` and an unreadable load are never busy; `CARETOOK_LOAD_FILE` stands in for the reading in tests; the `tooling:unit` project sets the gate off (its own tests set it back). A check (inside its check lease, which it holds while waiting) and a slice worktree's creation wait while busy, polling every `CARETOOK_LOAD_POLL` (15 s), at most `CARETOOK_LOAD_WAIT` (600 s), then proceed and say so; the check-times line's 12th field is the seconds waited. `pnpm prd start` only warns, the dispatcher starts and plans nothing, `pnpm prd status` prints the gate line.

## The asks queue

- One place for the user to answer: `.loops/.asks/<id>.json` in the main checkout (`CARETOOK_ASKS_DIR`), ids `a1`, `a2`…, created exclusively. A question awaits an answer until answered, dismissed or defaulted; a report is listed until dismissed.
- `pnpm prd ask --topic <t> --question <text> --option <a>… --recommend <a>` or `--report <text>` (the topic and session default to the worktree's) prints the id and, for a question only, a "Now send a PushNotification" line (a report is never pushed); it shows a macOS notification and runs `$CARETOOK_ASK_NOTIFY <id> <kind> <topic> <text>` when set (failures and hangs ignored, `CARETOOK_ASK_NOTIFY_TIMEOUT`).
- `pnpm prd ask --wait <id> [--timeout <s>]` prints the answer (exit 0; 75 at the timeout, 1 if dismissed). `pnpm prd asks [--json]` lists them oldest first; `pnpm prd answer <id> <n|text>`; `pnpm prd asks --done <id>` dismisses.
- **Defaults** (`asks.mjs`): a question with `--recommend` must say `--defaults` or `--waits` (neither files nothing and names the [never list](preferences.md#planning-and-slices)). A defaulting one takes its recommendation `CARETOOK_ASK_DEFAULT_MIN` (30) minutes after it was asked, settled only by `--wait` and the dispatcher's tick, never by the listing; answering and settling share one lock per ask, so the first wins. The push line and listing show when (`due` once past, still answerable); a defaulted ask is listed under _decided for you_ until dismissed and can't be answered. The dispatcher's own question waits.

## The notice board

- One-way and advisory (`notices.mjs`, `notice.mjs`): `.loops/.notices/<id>.json` in the main checkout (`CARETOOK_NOTICES_DIR`), ids `n1`, `n2`… never reused. `pnpm prd notice "<text>" [--for <min>] [--topic <t>]` (one line, 200 characters; 60 minutes, 24 hours at most), `pnpm prd notices [--json]`, `notices --done <id>`; expired ones go on every write and list.
- `check`, `sync`, `slice`, `browser`, `pr`, `ready` and `land` print other sessions' live notices to stderr first (five lines at most; a slice counts as its orchestrator's session); `pnpm prd status` prints all. Nothing blocks on a notice, and a broken board never changes a command's exit.
- A code landing posts "landed `<branch>` in dev as `<sha>`: sync at your next wave boundary" for six hours; a failure to post only warns.

## Landing reports

- After merging a `prd/` or `hotfix/` branch (fix topics included) whose diff isn't Markdown only (`docs_only` in `lib.sh`), `land.sh` writes `to-test/<date>-<HHMM>-<topic>.md` in the main checkout (gitignored), itself, so it exists even if the session dies: the topic's title, what changed and landed, the commit and PR, the dev URL and seed accounts, and what wasn't checked (browser checks land can't see). The user reads and deletes them; agents only add. A failure writing it never fails the landing.
