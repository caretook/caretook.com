One contained fix in its own worktree, outside the PRD rules, when the user asks for it there rather than straight onto `dev`: `.loops/hotfix-<name>` on `hotfix/<name>` from `dev`, stackless, worked by the session the user asked in; no PRD, plan, orchestrator, slices or fields, and it doesn't count toward the PRD cap.

- **Ask the user before every step that takes time or changes shared state**, unless they say not to: a long test (`pnpm check`, `pnpm prd check`, component tests, a browser check, `stack up`), committing, syncing, landing and removing. Reads, edits, a typecheck, one unit-test file and making the worktree need no ask.
- One change the size of a small change on `dev`; bigger, parallel, a hot file or a migration is a PRD or a fixes slice. Screens still get component tests. Update the docs the fix makes stale on the branch (a hotfix may edit `docs/` and AGENTS.md), and write any new hotfix rule you and the user settle on into this doc. A small tooling change the user asks for may ride along as its own `chore(loops): …` commit.
- Commit only when asked. Then, each on the user's go-ahead: `pnpm prd browser --changed` once (needs `pnpm prd stack up`), `pnpm prd sync` if `dev` moved. No local quick check when a CI tier follows; with no tier, `pnpm test:tooling`. **It lands on the [gate](orchestrator.md#the-check-gate)'s proposed CI tier, or the user's word** for a lower one (`--tier <t> --why "<reason>"`); docs and tooling need none. Before landing, ask the user **"PR or local?"** every time. PR: `pnpm prd pr hotfix/<name>`, Codex review as for a PRD ([orchestrator](orchestrator.md#landing-a-wave)), then `pnpm prd land hotfix/<name> --pr -m "fix(<area>): …"`. Local: `land … --local` (no PR or Codex, the same gate). Then `pnpm prd rm hotfix-<name>`.
- **A dev server on the dev data**, when the user asks (the worktree has no stack):
  - **Env files:** agents can't read `.env` files, so the user runs one command, given with absolute paths: `! ln -s <main>/apps/web/.env <worktree>/apps/web/.env && ln -s <main>/packages/data/.env <worktree>/packages/data/.env`.
  - **Port and start:** the user's own server holds :5173, so start on :5174 in the background, with Node 24, with the auth origin overridden for the process only (Better Auth trusts only `BETTER_AUTH_URL`; real env vars beat the files): `BETTER_AUTH_URL=http://127.0.0.1:5174 APP_URL=http://127.0.0.1:5174 pnpm --filter @caretook/web exec react-router dev --port 5174 --strictPort`.
  - **Ready:** wait for `Local:`, check that `/sign-in` returns 200, and tell the user to open `127.0.0.1`, not `localhost`.
  - **Cleanup:** stop the server before `pnpm prd rm`, which removes the links with the worktree.
