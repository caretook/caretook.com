# Sync: PowerSync

- Postgres is the truth. Each device keeps a SQLite copy; writes upload through **our** API (`sync.upload`), so permissions, validation and audits apply. Last write wins per row; live notes merge (Yjs).
- **Hosting:** PowerSync Cloud; locally the `journeyapps/powersync-service:1.28.3` container on :8080, with bucket storage in its own Postgres.
- **Sync Streams** (`powersync/sync-config.yaml`, edition 3). **Queries list their columns explicitly**, so a new column must be added there too. Then `docker compose restart powersync`.
  - `care_groups`: one bucket per group the user belongs to, carrying the care tables (most with soft-deleted rows), and the link tables `medication_condition`, `condition_manager` and `timeline_entry_todo` (hard deletes; [todos](todos.md)). `care_recipient` carries `no_known_allergies_at` and `no_known_conditions_at`, `note_document` `todo_id`, `care_group` `details_outside_allowed` ([calendars](calendars.md)).
  - `member_profiles`: co-members' `PUBLIC_PROFILE_FIELDS`.
  - `care_group_writers`: `care_recipient_details` for writers' groups. PowerSync 1.28.3 rejects `role IN (...)`, so it lists the roles it excludes (`viewer`, `easy_helper`, `easy_viewer`): **every new non-writer role must be excluded there too**.
- **Publication** (`powersync`): the care tables plus `user`'s public columns (no email, role, preferences). To change them, drop and re-add `user`; never `SET TABLE`.
- **Local JWKS:** `PS_JWKS_URL` (default `http://host.docker.internal:5173/api/auth/jwks`; Vite allows that Host). `pnpm datastore:reset` ends with `datastore:powersync` (stop, drop the slot, empty storage, restart, wait ≤ 60 s). Admin token and port: `powersync/service.yaml`.
- **Upload** (`sync.upload`, `packages/api/src/sync.ts`): up to 100 ops, in order, onto **services** through `UPLOAD_REGISTRY` (`syncRegistry.ts`); any other table, `__proto__` included, → `sync:readOnlyTable`.
  - One `softDelete(spec)` handler for `timeline_entry`, `provider`, `medication`, `medication_pass`, `recipient_allergy`, `recipient_condition`, `care_period`, `todo`, `appointment_series`: PUT → `upsert`, PATCH → `update` (`remove` when it sets `deleted_at`), DELETE → `remove`. A changed group or recipient → `immutable`; a reader who can't write → `permissions:unauthorized` on every op (one more read tells them from a missing row, `:notFound`). Booleans arrive as 1/0, JSON as text. A dose's PUT and PATCH have their own upload rules ([medications](medications.md)).
  - Each entry exports its column lists (`content`, `fixed`, `handled`, `serverSet`); a PATCH naming a column in none → `sync:unknownColumn`. `syncRegistry.test.ts` checks they match the device schema and streams. `via`, `connectors_enabled` sync down only.
  - `todo` hooks: a PATCH of only `done_at`/`done_by` is `complete`/`reopen` (a viewer's tick passes, [todos](todos.md)); the twin is `put`. Live notes: PUT → `create`/`appendUpdate` (the device's `subject`), else read-only. Link tables (`linkTable`): PUT → link (a repeat is one row), DELETE → unlink, PATCH → `sync:readOnlyTable`. `condition_manager`: a PATCH of only `updated_at` is the unlink at that save's time (`changedAt`). `care_recipient`: only the no-known PATCHes.
  - **A PUT is create-if-absent** (services' `upsert` returns `Upserted { created, row }`): an existing row stays as it is; its follow-ups (`deleted_at` → remove, `afterPut`) run only with the create, in one transaction.
  - **Results:** `applied`; `rejected` (a 4xx: recorded, the next sync restores the server's copy); `failed` (`sync:failed`, a throw or a non-4xx error): the server probes the database and stops there with a 200, or answers 500 when the probe fails too (an outage counts no try). A NUL character → `sync:invalid`.
- **Timestamps:** PowerSync sends `…T21:45:25.229000Z`; local writes match (`toLocalTimestamp`) so strings sort.
- **Device:** the plumbing is `apps/web/app/lib/sync/`; device queries and local writes are `lib/<area>/<name>.sync.ts` (guard: `libLayout.test.ts`). Local writes validate with the shared Zod schemas, check the role set (`canWrite`, `canLog`: a refused upload is never queued), and write only changed columns (`lib/core/changedColumns.ts`, JSON by value; device fixtures seed JSON as Postgres sends it, `pgJson`).
  - `schema.ts`: the Drizzle sqlite tables; `LOCAL_ONLY_TABLES` (`localOnly`, never synced, cleared with the copy): `unsaved_change`.
  - `uploader.ts` (`uploadQueued`): records each rejected op in `unsaved_change` (data, code, issues, a label), acknowledges up to a `failed` op and counts its tries (`uploadTries.ts`, `caretook:upload-tries`); after 5 over ≥ 2 min it's set aside (`outcome = 'set_aside'`) and the queue moves on. A 400 for a whole request resends it op by op; one refused alone is recorded (`sync:invalid`). Settings → "Changes not saved" lists both; a set-aside line has Try again (`retryUnsaved`). The indicator says "Can't sync, retrying · N waiting".
  - **No background upload** (B-805): uploads run while the app is open.
  - `client.ts`: the database and connector, **loaded lazily** (never imported statically).
    - One user's data per device: the owner is in localStorage; another user's open wipes the file.
    - A wipe runs `disconnectAndClear`, then `VACUUM`, and **keeps the IndexedDB file** (a `deleteDatabase` blocked by PowerSync's shared worker blocks every later sign-in); OPFS files are removed. `closeKept` closes without clearing (`caretook:sync-kept`); `countWaiting` counts `ps_crud`, even with no database open.
    - `fetchCredentials` calls `/api/auth/token` (always the live session: auth.md). A 401 leaves the device local-only.
  - `pageCache.ts` (`releaseSyncLocksWhenCached`, before PowerSync opens): a page in the back/forward cache holds PowerSync 2.7's `tab-close-signal-*` and `shared-connection-*` Web Locks, so the next page's database never opens. It releases them on `pagehide` into the cache and reloads on `pageshow` out of it; recheck its lock names on a PowerSync upgrade.
  - `index.ts`: `openSync`, `getSync`, `closeSync`, `countWaiting`, the first-sync helpers, `useLiveQuery` (nothing with no database open; new loader data keeps live rows), `useSyncState` (`waiting`, `notSaved`, `uploadFailed`).
  - **The first sync:** `waitForFirstSync(db)` waits at most 1 s (`FIRST_SYNC_WAIT_MS`) and resolves to `isFirstSyncDone(db)` (PowerSync's `hasSynced`, which persists with the local copy). `useFirstSyncDone()` is the hook (below the /app layout only).
    - A loader whose group isn't on the device throws `notOnDevice(db)`: a 404 once the first sync is done, else a 503 that `/app`'s `ErrorBoundary` shows as `FirstSyncPending` (it reruns the loaders when the sync lands).
  - **Session:** `lib/auth/session.ts` `requireSession(request)` is the one shared session check and DB open. Every confirmed online check records `caretook:session-confirmed:<userId>`. The server's answer is sorted by the pure `sessionOutcome` (`lib/auth/sessionRules.ts`):
    - A session is ok. No session, 401 or 403 is **signed out**: `endSession()`, then sign-in. `wipeDevice()` clears the database and forgets the cached user, settings, last group and recent searches.
    - **Unsent changes are never wiped unasked** (`localCopyFate`, `localCopyRules.ts`): a session that ends with changes waiting keeps the copy for its owner (`closeSync({ keep: true })`; their next sign-in uploads them; another user's open, or 30 days, `expireKeptCopy`, wipes it). Sign-out with changes waiting asks first (the user menu). An offline sign-out wipes, then leaves `caretook:sign-out-pending`, finished before any session check or sign-in ([auth](auth.md)).
    - A 429: `askSession` retries once after `X-Retry-After` (≤ 2 s); still 429 with nobody cached → `/sign-in?reason=rate-limited`.
    - Anything else (offline, 5xx), and a 429 with a cached user, is unknown: the cached user carries on only within 3 days of the last confirmed check (`offlineAllowed`), else `/sign-in?reason=offline` **without** wiping, so unsynced writes still upload after sign-in.
    - **The device answers first:** a session confirmed within 15 min returns at once, rechecked after a minute; the first check per page load or sign-in waits (≤ 3 s).
    - The /app layout's `clientMiddleware` calls it once per navigation and sets `sessionContext`; every /app loader and action reads `context.get(sessionContext)`, never `requireSession` again.
  - **Tile cache** (`useRememberedQuery`): in memory per user, group and name; `{ value, fresh }`; cleared by `closeSync`.
  - **Settings cache:** `lib/app-shell/me.ts` caches settings per user (not synced). **Change them with `saveSettings(userId, change)`**: it caches, queues (`caretook:settings-pending:<userId>`) and calls `updatePreferences` (`"saved"`, or `"pending"` offline; other errors drop it). `loadSettings` is cache-first (`settingsPlan`), refreshing in the background; with no cache it waits ≤ 3 s, then defaults. `cachedSettings(userId)` reads both offline. **The avatar queues apart** (`myAvatar.ts`, `caretook:avatar-pending:<userId>`, `null` clears), never through `updatePreferences`; only a 4xx drops it.
- ✅ **Production** (settings in `powersync/service.production.example.yaml`, setup in [`ops/runbook.md`](../../ops/runbook.md)): PowerSync Cloud (US) on Neon's direct URL with `sslmode: verify-full`, as `caretook_replication` (REPLICATION). Client auth is the JWKS at `<APP_URL>/api/auth/jwks` with the audience `POWERSYNC_URL`; no admin token in the service config. The deploy Action pushes `sync-config.yaml`.
  - **Grants come from `sync-config.yaml`** (`packages/data/src/db/roles/syncConfig.ts`): the replication role's SELECT and the `powersync` publication list exactly the columns the streams read. The parser refuses `*`, unknown columns and functions.
  - **The snapshot runs `SELECT *`**: a synced table lists every column in its stream or is in `REPLICATION_WHOLE_TABLES` (a table-level grant; other columns reach PowerSync's storage, never devices). `roles.int.test.ts` and `rolesSql.test.ts` guard it.
