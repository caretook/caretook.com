# Sync: PowerSync

- Postgres is the truth. Each device keeps a SQLite copy; writes upload through **our** API (`sync.upload`), so permissions, validation and audits apply. Last write wins per row; live notes merge (Yjs).
- **Hosting:** PowerSync Cloud; locally the `journeyapps/powersync-service:1.28.3` container on :8080.
- **Sync Streams** (`powersync/sync-config.yaml`, edition 3). **Queries list their columns explicitly**, so add a new column there too, then `docker compose restart powersync`.
  - `care_groups`: one bucket per group the user belongs to, carrying the care tables (most with soft-deleted rows), and the link tables `medication_condition`, `condition_manager` and `timeline_entry_todo` (hard deletes; [todos](todos.md)). `care_recipient` carries `no_known_allergies_at` and `no_known_conditions_at`, `note_document` `todo_id`, `care_group` `details_outside_allowed` ([calendars](calendars.md)).
  - `member_profiles`: co-members' `PUBLIC_PROFILE_FIELDS`.
  - `care_group_writers`: `care_recipient_details` for writers' groups. PowerSync 1.28.3 rejects `role IN (...)`, so it lists the roles it excludes (`viewer`, `easy_helper`, `easy_viewer`): **every new non-writer role must be excluded there too**.
- **Publication** (`powersync`): the care tables plus `user`'s public columns (no email, role, preferences). To change them, drop and re-add `user`; never `SET TABLE`.
- **Local JWKS:** `PS_JWKS_URL` (default `http://host.docker.internal:5173/api/auth/jwks`). `pnpm datastore:reset` ends with `datastore:powersync` (stop, drop slot, empty storage, restart).
- **Upload** (`sync.upload`, `packages/api/src/sync.ts`): ops in order onto **services** via `UPLOAD_REGISTRY` (`syncRegistry.ts`); other tables, `__proto__` too, → `sync:readOnlyTable`. **A write** (consecutive ops sharing `write`, the device's transaction id; none: its own) runs in one `withTransaction`, `tx` in the context. ≤ 100 ops, or the limit in one write.
  - Scrubbed rows sync as ordinary updates. The device scrubs its own todo copy on delete, so a restore PATCH carries content; local mappers (`toProvider`, `toPass`) keep a deleted row with an empty name and drop only a nameless live (half-synced) one.
  - One `softDelete(spec)` handler for `timeline_entry`, `provider`, `medication`, `medication_pass`, `recipient_allergy`, `recipient_condition`, `care_period`, `todo`, `appointment_series`: PUT → `upsert`, PATCH → `update` (`remove` when it sets `deleted_at`), DELETE → `remove`. A changed group or recipient → `immutable`; a reader who can't write → `permissions:unauthorized`. Booleans arrive 1/0, JSON as text. Dose PUT and PATCH: [medications](medications.md).
  - Each entry exports its column lists (`content`, `fixed`, `handled`, `serverSet`); a PATCH naming a column in none → `sync:unknownColumn`. `syncRegistry.test.ts` checks them. `via`, `connectors_enabled` sync down only.
  - `todo` hooks: a PATCH of only `done_at`/`done_by` is `complete`/`reopen` (a viewer's tick passes, [todos](todos.md)); transitions lock the row (`FOR UPDATE`) first; the twin is `put` (a tick's never creates); `parent_id` is `createOnly`. Live notes: PUT → `create`/`appendUpdate` (the device's `subject`), else read-only. Link tables (`linkTable`): PUT → link (a repeat is one row), DELETE → unlink, PATCH → `sync:readOnlyTable`. `condition_manager`: a PATCH of only `updated_at` is the unlink at that save's time (`changedAt`, which keys the derived entry id; `occurred_at` is the earlier of it and now). `care_recipient`: only the no-known PATCHes.
  - **A PUT is create-if-absent** (services' `upsert` returns `Upserted { created, row }`): an existing row stays as it is; its follow-ups (`deleted_at` → remove, `afterPut`) run only with the create.
  - **Results**, one per op: `applied`; `rejected` (a 4xx rolls it back: that op its code, the rest `sync:writeRefused` + `refusedId`; the loop goes on); `failed` (`sync:failed`, a throw: at the write's first op; then a database probe: a 200 and stop, or a 500, no try counted). `40P01`/`40001` retries the write once. A NUL → `sync:invalid`.
- **Timestamps:** PowerSync sends `…T21:45:25.229000Z`; local writes match (`toLocalTimestamp`).
- **Device:** plumbing: `apps/web/app/lib/sync/`; device queries and local writes are `lib/<area>/<name>.sync.ts` (guard: `libLayout.test.ts`). Local writes validate with the shared Zod schemas, check the role set (`canWrite`, `canLog`), and write only changed columns (`lib/core/changedColumns.ts`, JSON by value).
  - **One save, one transaction:** every multi-row `*.sync.ts` save, ≤ `SYNC_WRITE_LIMIT` (1000, `@caretook/data/domain`) ops; a series split: 437 (pinned).
  - `schema.ts`: the Drizzle sqlite tables; `LOCAL_ONLY_TABLES` (never synced, cleared with the copy): `unsaved_change`.
  - `uploader.ts` (`uploadQueued`) sends whole writes (`write`: the entry's `transactionId`): ≤ 100 ops, or one write ≤ the limit; one over it goes 100 at a time without `write`. A refused write's ops go in `unsaved_change` (data, code, issues, label, `write_id`, `write_seq`; a multi-op write shares `line_key` `write:<id>`). A `failed` write: acked up to it, tries on its first entry (`uploadTries.ts`); 5 over ≥ 2 min sets it aside whole. A whole-request 400 resends write by write. "Changes not saved": a line per `line_key` (first op's label, the refusing op's reason); Try again resends a write whole (`retryUnsaved`).
  - **No background upload** (B-805): the service worker only caches; it uploads only while the app is open.
  - `client.ts`: the database and connector, **loaded lazily** (never a static import).
    - One user's data per device: the owner is in localStorage; another user's open wipes the file.
    - A wipe: `disconnectAndClear`, `VACUUM`, **keeps the IndexedDB file** (a blocked `deleteDatabase` blocks sign-ins); OPFS files go. `closeKept` closes without clearing (`caretook:sync-kept`).
    - `fetchCredentials` calls `/api/auth/token` (the live session: auth.md); a 401 keeps the device local.
  - `pageCache.ts` (`releaseSyncLocksWhenCached`): a back/forward-cached page holds PowerSync 2.7's `tab-close-signal-*` and `shared-connection-*` Web Locks; released on `pagehide`, reload on `pageshow` (recheck names on upgrade).
  - `index.ts`: `getSync`, `closeSync`, `countWaiting` (`ps_crud`), first-sync helpers, `openSync` (prefetches WASM), `useLiveQuery` (loader data keeps live rows; one watch per SQL+params; `sameRows` drops repeats; batched per frame), `useSyncState` (`waiting`, `notSaved`, `uploadFailed`).
  - **The first sync:** `waitForFirstSync(db)` waits at most 1 s (`FIRST_SYNC_WAIT_MS`) for `isFirstSyncDone(db)` (PowerSync's `hasSynced`); hook: `useFirstSyncDone()`.
    - A loader whose group isn't on the device throws `notOnDevice(db)`: a 404 after the first sync, else a 503 shown as `FirstSyncPending` (reruns loaders when it lands).
  - **Session:** `lib/auth/session.ts` `requireSession(request)` is the one shared session check and DB open. Every confirmed online check records `caretook:session-confirmed:<userId>`. The server's answer is sorted by the pure `sessionOutcome` (`lib/auth/sessionRules.ts`):
    - A session is ok. No session, 401 or 403 is **signed out**: `endSession()`, then sign-in. `wipeDevice()` clears the database and forgets the cached user, settings, last group and recent searches.
    - **Unsent changes are never wiped unasked** (`localCopyFate`): a session that ends with changes waiting keeps the copy for its owner (`closeSync({ keep: true })`; their next sign-in uploads; another user's open, or 30 days, wipes it). Sign-out with changes waiting asks first. An offline sign-out wipes, then leaves `caretook:sign-out-pending` (JSON `{at, session}`), finished before any session check or sign-in ([auth](auth.md)): `finishPendingSignOut` signs out only the confirmed `session` (`caretook:session-id`), drops the marker for a different one or none, stays pending offline.
    - A stale tab now another user's closes its handle uncleared (`forgetOpen`, `closeHandle`); `open`'s owner rule decides the wipe.
    - A 429: `askSession` retries once after `X-Retry-After` (≤ 2 s); still 429, none cached → `/sign-in?reason=rate-limited`.
    - Else (offline, 5xx, a 429 with a cached user) unknown: the cached user carries on within 3 days of the last confirmed check (`offlineAllowed`), else `/sign-in?reason=offline` **without** wiping.
    - **The device answers first:** confirmed within 15 min returns at once, rechecked after a minute; the first check per load or sign-in waits (≤ 3 s).
    - /app's `clientMiddleware` calls it per navigation into `sessionContext`.
  - **Tile cache** (`useRememberedQuery`): in memory per user, group, name; cleared by `closeSync`.
  - **Settings cache** (`lib/app-shell/me.ts`, per user, not synced): **change with `saveSettings(userId, change)`** (caches, queues `caretook:settings-pending:<userId>`, calls `updatePreferences`: `"saved"`, `"pending"` offline; other errors drop it). `loadSettings` is cache-first (`settingsPlan`); none waits ≤ 3 s. **The avatar queues apart** (`myAvatar.ts`, `caretook:avatar-pending:<userId>`, `null` clears), never through `updatePreferences`; only a 4xx drops it.
- ✅ **Production** (settings in `powersync/service.production.example.yaml`, setup in [`ops/runbook.md`](../../ops/runbook.md)): PowerSync Cloud (US) on Neon's direct URL with `sslmode: verify-full`, as `caretook_replication` (REPLICATION). Client auth is the JWKS at `<APP_URL>/api/auth/jwks` with the audience `POWERSYNC_URL`; no admin token. The deploy Action pushes `sync-config.yaml`.
  - **Grants come from `sync-config.yaml`** (`packages/data/src/db/roles/syncConfig.ts`): the replication role's SELECT and the `powersync` publication list exactly the columns the streams read. The parser refuses `*`, unknown columns and functions.
  - **The snapshot runs `SELECT *`**: a synced table lists every column in its stream or is in `REPLICATION_WHOLE_TABLES` (a table-level grant; other columns reach PowerSync's storage only). `roles.int.test.ts` and `rolesSql.test.ts` guard it.
