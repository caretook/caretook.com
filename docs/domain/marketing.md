# Marketing site

The marketing site's rules and decisions. PRDs: [`marketing`](../../plans/marketing-prd.md), [`marketing-2`](../../plans/marketing-2-prd.md).

- **Web only:** a `marketing` layout route (`routes/marketing/layout/`) in `routes.ts`'s web-only list, with `/`, `/features`, `/faq`, `/about`, `/contact`, `/privacy`, `/terms`, `/health-data-privacy`, plus `sitemap.xml` and `robots.txt` resource routes. Native's `/` still redirects to `/app`. Marketing code never imports from `routes/app/`, `lib/sync/` or the editor.
- **Prerendered:** `react-router.config.ts` prerenders `PRERENDER_PATHS` for the web target only.
- **One page list:** `site/pages.ts` `MARKETING_PAGES` feeds the header, footer, sitemap and prerender. A new page is an entry there, a route in `routes.ts`, and a folder with `route.tsx` and `content.ts`.
- **Copy lives in typed content modules** (`<page>/content.ts`), rendered by `sections/` components; icons are named by string (`sections/icons.tsx`).
- **The lockup** (home's hero, `hero.lockup`): the full logo (`FullLogo size="hero"`: the mark, "Caretook", and the tagline "Care, taken." tucked under it) is the page's only `h1`, then the descriptor "A care notebook for families, made by caregivers who've been there.", then the lead; no supporting heading (B-855). The name and tagline live in `BRAND` (`components/brand/`). The full logo and descriptor are also the share image's drawing, words and alt: `og-default.svg` is the source, `node scripts/build/share-image.mjs` renders the PNG (Playwright, the site's typeface), and `site/meta.test.ts` holds the four together.
- **Price:** "Free for families" and the one promise sentence live in `site/price.ts`; home's band and the FAQ's cost answer both read it.
- **Claims rule:** copy says only what the app does today, checked against the area docs; a doubtful claim is left out, never hedged, and nothing is listed as coming. `site/claims.test.ts` bans "early access", "HIPAA", "free forever", any "secure" form and "export anytime" outside the legal pages (B-852: its gaps). About's founder story and bios are the user's text, verbatim and test-held: never reword them.
- **SEO:** `site/meta.ts` `marketingMeta({ title, description, path, siteUrl, image?, jsonLd? })`; the layout's loader gives `siteUrl` from `APP_URL` (default `https://caretook.com`). `robots.txt` disallows `/app /admin /invite /join /api /rpc /dev` by prefix, so public files that must stay crawlable avoid those prefixes (icons live in `/icons/`).
- **Brand assets** (drafts, in `apps/web/public/`): `favicon.svg`, `logo.svg`, `icons/*.png`, `og-default.png`, `site.webmanifest`. The PNGs are rendered from the SVG; regenerate them if it changes. `root.tsx` links the icons for both targets. `LogoMark` and `FullLogo` (the mark, the name and the tagline under it; `components/brand/`, used by the marketing header and footer, the `/app` header and home's hero; the index imports nothing else) draw the same mark inline in the theme's `primary`: change them together with the SVG and PNGs.
- **Theme:** the existing `THEME_SCRIPT`, unchanged; a stored app theme applies on the site.
- **No third-party requests and no analytics:** `MarketingAnalytics` is an empty hook point. The site makes public privacy promises, so anything that changes them updates the privacy page in the same change.
- **Inner pages:** features, FAQ and about render `sections/PageSections.tsx` (`PageIntro` with the page's only `h1`, `Showcase`, `Gallery`, `Prose`, `FaqList`). The FAQ's `FAQPage` JSON-LD (`faqPageJsonLd`) is built from the same content as the visible list.
- **Screenshots are SVG placeholders** (`public/screenshots/<name>.svg`, listed in `site/screenshots.ts`) until launch (B-40). `scripts/browser-checks/marketing-screenshots.mjs` generates real ones from seed data (viewport-only WebP); it isn't in use yet.
- **Legal pages** (`/privacy`, `/terms`, `/health-data-privacy`) are drafts rendered by `sections/LegalPage.tsx` from content modules (`sections/legal.ts` types): a DRAFT banner (keep it until the user says the text is reviewed), the last-updated date, a table of contents, heading anchors, and a plain summary above the formal text. `[Placeholders]` show as written. Their promises match the FAQ (encryption in transit and at rest; staff see care data only with permission, recorded; deletion by request) but keep the older "early access" price wording until B-54. `/privacy` and `/health-data-privacy` have an `own-assistant` section (connecting your own AI assistant; [connectors](connectors.md)), echoed in the FAQ: change them with the connector tools.
- **In-page hash links use React Router `Link`**, not a plain `<a href="#…">`: a native hash jump makes `ScrollRestoration` restore an old position and jump back.
- **Waitlist and contact**: tables `waitlist_entry` (email unique and lowercase, so repeats update the entry; first name, `caring_for`, `heard_from`, `source` jsonb with the page and `utm*`) and `contact_message` (name, email, topic, message ≤ 5,000). **No IP or user agent is stored** with the entry. Written by the system only (`waitlistService.join`, `contactMessageService.send`), read and deleted by staff only. The pure rules are in `db/schema/marketing/publicFormRules.ts` (no imports, so Zod stays off marketing pages); the Zod schemas in `publicForms.ts`.
  - Public oRPC `public.waitlist.join` and `public.contact.send` (`packages/api/src/marketing/publicForms.ts`). Every accepted submit answers `{ ok: true }`, spam included. Spam rules: a honeypot field (`website`), at least 3 s on the page (`MIN_FORM_MS`), and 10 calls a minute per IP per form (`rateLimit.ts`, in memory; the 11th gets a 429). `routes/rpc.ts` passes the first `x-forwarded-for` (else `x-real-ip`) as `clientIp`, for the limit only (`clientIpOf` in `packages/auth/src/host.ts`). Since the limiter moved to Postgres (B-141), its `rate_limit_hit` keys hold the IP for about an hour, until the next sweep.
  - Contact queues the `contactMessage` email to `SUPPORT_EMAIL` in the message's transaction (`[Privacy]` in the subject for privacy topics). Production refuses to send without `SUPPORT_EMAIL`; elsewhere it defaults to `support@example.com`, and `new.sh` copies it into worktrees.
  - Both forms use `sections/PublicForm.tsx` (`usePublicForm`: one submit at a time, focus on the first error, a polite `role="status"` thanks); the waitlist is home's band at `/#waitlist`.
- **The admin waitlist**: `/admin/waitlist` in the `/admin` frame (staff with `waitlist.read`; others get the frame's 404). GET filters in the URL (`from`/`to` whole UTC days, `caringFor` or `none`, `source` matched in any page or UTM value), 50 a page, newest first, with a count. `admin.waitlist.list` and `admin.waitlist.export` (merged into the router's `admin` object). `/admin/waitlist/export` sends the filtered rows as CSV: RFC 4180, CRLF, UTF-8 with a BOM, and cells starting `= + - @`, tab or CR prefixed with `'` so spreadsheets don't run them. Contact messages aren't listed. `waitlistAdmin.int.test.ts` and `waitlistCsv.test.ts` cover it; the page is `admin/waitlist/waitlist.browser.test.tsx`.
- **Tests:** one-page behaviour (layout, menu, skip link, forms, legal pages) is component tests on `marketingWorld.tsx`'s `openMarketing`; the spec keeps only what needs the built site, real headers or the server (head, no third-party request, forms end to end via `page.clock`, no sleeps).
- **Browser check:** `marketing` (no sign-in; about 10 s; run it with `CARETOOK_BROWSER_SLOTS=4` so it doesn't queue behind app checks). Screenshots only with `MARKETING_SHOTS=1`, viewport-only; never `captureBeyondViewport` (it hung headless Chrome for over an hour).
- **Staging is noindex** (`APP_ENV=staging`, `lib/marketing/noindex.ts`): robots.txt is `Disallow: /`, the sitemap is empty (`robotsTxt`, `sitemapPaths` in `seo.ts`), `root.tsx` renders `<meta name="robots" content="noindex, nofollow">` on every page, and responses carry `X-Robots-Tag: noindex` ([security headers](security-headers.md)). Production and unset are unchanged.
