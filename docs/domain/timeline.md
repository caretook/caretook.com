# Timeline entries

- **Table:** one `timeline_entry` table with a `kind` column.
  - `group_id` and `recipient_id` are on the row (streams filter on them); the composite FK to `care_recipient` is `NO ACTION` (deleting a recipient with entries fails; deleting the group cascades).
  - `occurred_at` plus the device's IANA `time_zone`; optional `title`, `body`, and `details` jsonb (a Zod union per kind).
- **Rules:**
  - **Soft delete** (`deleted_at`), checked against the delete permission. Reads hide deleted rows unless `includeDeleted`, and `update` refuses them. A hard delete cascades to the entry's document.
  - **Keyset pagination** on `(occurred_at, id)`, because offline devices insert older entries.
  - `create` defaults `recipientId` and checks the group first (a non-member learns nothing). `update` validates the **merged** row.
  - `occurredAt` reads back as text: normalise at the API.
- **Kinds.** Place a new thing to log with these first:
  - **Note:** free text about the day. **Its text is its live document** (`body` always null, title optional), at `/entries/:id`.
  - **Symptom:** something the recipient **feels or reports**: free-text `name` plus `severity` 0-10. **Pain is a symptom.**
  - **Vital:** something **measured, counted or observed**, with a fixed unit or scale (without one, like mood, it's a symptom). Bowel movement, urine output and sleep are vitals.
  - **Dose:** a medication **given, skipped or refused** (`details`: `medicationId`, `status`; no title or body). The medication is in the entry's group; deleting it leaves its doses.
  - **Medication change:** **written automatically** (`SYSTEM_WRITTEN_KINDS`, like Condition change), never by hand; writers may delete one.
  - **Condition change:** written like a medication change ([profiles](profiles.md)).
  - **Event:** something that happened. Like a note, **its text is its live document**, at `/entries/:id`. A title is required: the device saves `"Event"` (`DEFAULT_EVENT_TITLE`) when none is given; the field shows "Add a title" (`isUnnamedEvent`). A future event is an appointment (_Appointments_).
- **Symptom catalog** (`symptom_type`; `symptomCatalog.ts`, the only fold): `symptomKey` folds case and spaces; id `symptomTypeId(group, key)`. New groups get 23 defaults; `symptomTypeService.backfill` (migrate, seed) adds them, live names and null pointers (raw SQL, `updated_at` kept). Any role reads; `LOGGERS` add (upload: idempotent PUT only). **`symptom_type_id`** (same-group FK): the server derives it on every symptom write (`serverSet`); devices write it with a new name's row in one write. **A new name** (sheet, Easy form, quick entry): an exact `similarSymptoms` match is reused; a similar one (reordered, a typo, a 2+-word name inside) asks "Use <name>" or "Add new"; an empty Easy form saves "Feeling" unasked. Summaries, visit prep, predictions group by `symptomKey`; the filter, the pointer.
- **Vitals** (`db/schema/timeline/vitals.ts`, the single spec):
  - `details = { readings: [...] }`, at most one per type (types in `VITAL_TYPES`; blood pressure needs diastolic < systolic).
  - **Adding a type is spec-only:** `VITAL_TYPES`, `VITALS` and one `reading(...)` line (new keys in `VitalFieldSpec["key"]`).
  - Stored canonically; shown and entered in the user's units (`fromDisplay`/`toDisplay`).
  - Hard limits reject; outside typical range warns but saves.
- **User preferences:** `user.preferences` jsonb (`userPreferencesZSchema`, all optional, so no migration): `units`, `timelineView` (`rows | cards`), `daySummary` (`off | highlights | full`, default `highlights`).
- **Timeline screen** (`/app/groups/:groupId/timeline`, `routes/app/groups/timeline/`):
  - The full view's header is `PageHeader` "Timeline" (no recipient card) with `EasyModeToggle` ("Easy mode") on its right, not in View options ([app-shell](app-shell.md)).
  - Condensed or Full, both from `entrySummary()`. `KIND_META`: icon, accent, look (no status colours). `DayHeader` (date, period, copy link, + at right, `summary`; sticky) uses `dayLabel`. Copy link (`useCopyLink`, `timelineLinks.ts`): the day's button (not easy), an entry's ⋯ item (all roles, both views); a day's `?day=`, a note or event's page, else its day. A row's ⋯ and author chip: `[data-entry-aside]`.
  - **Filters live in the URL** (`?kind=&author=<userId>`; `?vital=<type>` under `kind=vital`, repeated `?symptom=<typeId>` under `kind=symptom`; changing the kind drops them), owned by the pure `lib/timeline/timelineFilters.ts`. **Every filter control is a `Link` built by it**. **One toolbar row** (`FilterChips`): magnifier, Filter ("Filter, N on", a badge), View options at the end (full view). Filter opens `FilterSheet` (Kind; a vital type under Vitals, logged symptom types under Symptoms; the period while searching; Clear keeps `q`); each filter on is a removable chip ("Filters on").
  - **Kind icon** and **author control** (`components/entry/KindIcon.tsx`): filter links ("Show only …") above the row's open target, all roles.
  - ✅ **Open-todo mark** (`OpenTodosMark`; note and event rows, cards): "1 todo", "2 todos", none at 0; one `openTodoCountsQuery` per list; not in easy mode.
  - **The Today card** (`TodayCard`, full view, ignores filters): latest vitals, next appointment, medications due (Given all for writers), overdue or due-today todos, steps too (mine first), each hidden if empty; "See all ›" (`/planner`). `todayStatus`: a row's hue, icon, screen-reader text. **Collapsed on every load** to `todaySummary`'s line, led by `attentionCounts`: red "N overdue", orange "N due soon" (doses, todos or the next appointment due now or within 1 h; untimed: 19:00), then the rest. `LiveNowBanner` sits beside it (**Join**).
  - **Tiles never pop in:** the Today card's rows and easy mode's blocks read through the tile cache (sync.md): a remembered answer shows dimmed (`data-stale`, actions off); else a skeleton.
  - **Adding** (`QuickAddMenu`): a + "Add to <day label>" by each day heading; writers, not easy mode. Other days' adds carry `?at=` (`START_AT_PARAM`, `dayStartAt`): 12:00 there, viewer's zone.
  - **Sheets.** Note and Event open `/entries/new?kind=…`. Symptom and Vitals open the **add-sheet route** `timeline/new/:kind` (`symptom | vital`, `?type=<vitalType>`; `appUrls.newSheet`) in the timeline's `Outlet` (`newSheetGuard`). **Editing** is `timeline/:entryId/edit` (`appUrls.editSheet`); `editSheetGuard` sends a note or event to its page, anything else uneditable to the timeline. **Sheet links use `prefetch="render"`** (offline after a load).
  - **Row taps** (`EntryOpenTarget`): Notes and events open `/entries/:id`; symptoms and vitals open their edit sheet for whoever may change the entry, nothing for others (`openRule`). ⋯: Delete and Edit by ownership (`canChangeEntry`: writers any, Easy helpers their own), **Print** (notes, events) and Copy link for all. Tags: compact `QuickTags` ([tags](tags.md)). On `/entries/:id` `canWrite` is that rule; `canSetUp` (writers) gates series, cancel, repeat and links.
  - **The quick-entry box** (`canLog`: loggers): [assistant](assistant.md).
  - **Empty Today** (writer, full view, unfiltered): "Nothing logged today yet.", "Add an entry" (focuses the box).
  - **Day summaries** (`DaySummaryLine` in `DayHeader`, tap to expand; `daySummary.ts`): vitals (a range with an arrow), symptoms (highest severity, "(new)" against the baseline), events, who logged. No notes or doses; no vitals, symptoms or events, no summary. **Highlights**: vitals with an arrow, new or severe (`SEVERE_SYMPTOM`) symptoms, events. The `daySummary` setting (View options) picks the collapsed line; expanded is always full. **Any kind, author, vital or search filter hides every summary** (`summariesOff`).
  - **Infinite scroll** (`historyWindow`): `OlderEntries` grows the limit by `PAGE_SIZE`; the old window shows till the new arrives (`useLiveRows`); Back restores it (`timelinePaging.ts`); older rows get `content-visibility: auto`.
  - **Jump to a day** (`?day=`, the viewer's day; `timelineJump.ts`, `timelineNewer.ts`): a date button, or quick entry's Go to. Entries, links, medications and summaries share one exclusive bound; an empty day shows the nearest earlier one and says so. Only `JUMP_LINK_STATE` or a fresh load scrolls; the landed day then stays at the top while cards above settle, till the reader acts (`useJumpLanding`, B-779). Scrolling up moves the bound by whole days, holding the row. A filter change clears it; a jump ends a search.
  - **The route only composes** (`route.tsx`): `useTimelineData`, `useTimelineView`, `useEntryRemoval`.
- **Seeds** (`seeds/timelineEntries.ts`):
  - **Ids follow position** (a change needs `pnpm datastore:reset`); `timelineEntries.test.ts` checks them.
  - A note's or event's seed `body` becomes its document (`seedContentOf`); the entry's `body` stays null.
- **Tests:** beside the route (`timelineWorld.tsx`); browser checks only for the server.
- **The easy view** (`EasyTimeline.tsx`, chosen by `useEasyMode`), in order: the header, the setup card, Upcoming, My todos, the tiles with Remove last, `QuickEntryBox size="md" passChips={false}` (loggers), the full view's `FilterChips`, then `TimelineEntryList easy`: rows only, full type scale, ⋯ menus by owner, sheets for loggers; `EasyModeToggle` in the header; no filter links, period markers, adding, strips.
  - **Upcoming** (`EasyNow.tsx`): loggers get each due pass as a big Given all, Undo; the next item opens the Planner's next 5 (`EasyNext`; no doses), See all.
  - **My todos** (`EasyTodos.tsx`, `easyTodoTrees.ts`): trees matching mine, `TodoTree` `easy` look, Undo; `EASY_TODOS_CAP` counts mine, never cuts a tree. `EasyNext`: day trees, no ticks.
  - **Tiles** (loggers, `EasyTiles.tsx`; pure `lib/assistant/easyTiles.ts`): four links: fixed, learned (most-logged in 30 days) or the group's picks (`care_group.easy_tiles`, via `useEasySetup`). Each opens its sheet's **easy variant** (`TimelineOutlet.easy`). While `easy_tiles` is null, owners and admins get "Choose the tiles" (to Details).
  - **Remove my last entry** (loggers, `removeLast.ts`): your latest entry of the last 30 minutes (not system-written), after a confirm.
