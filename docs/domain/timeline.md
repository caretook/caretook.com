# Timeline entries

- **Table:** one `timeline_entry` table with a `kind` column.
  - `group_id` and `recipient_id` are on the row (streams filter on them); the composite FK to `care_recipient` is `NO ACTION` (deleting a recipient with entries fails; deleting the group cascades).
  - `occurred_at` plus the device's IANA `time_zone`; optional `title`, `body`, and `details` jsonb (a Zod union per kind).
- **Rules:**
  - **Soft delete** (`deleted_at`), checked against the delete permission. Reads hide deleted rows unless `includeDeleted`, and `update` refuses them. A hard delete cascades to the entry's document.
  - **Keyset pagination** on `(occurred_at, id)`, because offline devices insert older entries.
  - `create` defaults `recipientId` and checks the group first, so a non-member learns nothing. `update` validates the **merged** row.
  - `occurredAt` reads back as text: normalise it at the API.
- **Kinds.** Place a new thing to log with these first:
  - **Note:** free text about the day. **Its text is its live document**: `body` is always null, the title optional. Written at `/entries/:id`.
  - **Symptom:** something the recipient **feels or reports**: free-text `name` plus `severity` 0-10. **Pain is a symptom.**
  - **Vital:** something **measured, counted or observed**, with a fixed unit or scale (without one, like mood, it's a symptom). Bowel movement, urine output and sleep are vitals.
  - **Dose:** a medication **given, skipped or refused** (`details` has `medicationId` and `status`; no title or body). The medication must be in the entry's group; deleting it leaves its doses.
  - **Medication change:** **written automatically** (`SYSTEM_WRITTEN_KINDS`, as is Condition change), never by hand; writers may delete one.
  - **Condition change:** written like a medication change ([profiles](profiles.md)).
  - **Event:** something that happened. Like a note, **its text is its live document**, written at `/entries/:id`. A title is required: the device saves `"Event"` (`DEFAULT_EVENT_TITLE`) when none is given, and the field shows "Add a title" (`isUnnamedEvent`). A future event is an appointment (_Appointments_).
- **Symptom catalog** (`symptom_type`; `symptomCatalog.ts`, the only fold): `symptomKey` folds case and spaces; id `symptomTypeId(group, key)`. New groups get 23 defaults; `symptomTypeService.backfill` (migrate, seed) adds them, live names and null pointers (raw SQL, `updated_at` kept). Any role reads; `LOGGERS` add (upload: idempotent PUT only). **`symptom_type_id`** (same-group FK): the server derives it on every symptom write (`serverSet`); devices write the same id, and a new name's row, in one local write. **A new name** (sheet, Easy form; `useSymptomGate`): an exact `similarSymptoms` match is reused, a similar one asks "Use <name>" or "Add new"; an empty Easy form saves "Feeling" unasked. Summaries, visit prep and predictions group by `symptomKey`; the filter matches the pointer only.
- **Vitals** (`db/schema/timeline/vitals.ts`, the single spec):
  - `details = { readings: [...] }`, at most one per type (types in `VITAL_TYPES`; blood pressure needs diastolic < systolic).
  - **Adding a type is spec-only:** `VITAL_TYPES`, `VITALS` and one `reading(...)` line (new keys in `VitalFieldSpec["key"]`).
  - Stored in canonical units; display and entry use the user's units (`fromDisplay`/`toDisplay`).
  - Hard limits reject; outside the typical range warns but saves.
- **User preferences:** `user.preferences` jsonb (`userPreferencesZSchema`, every field optional, so new settings need no migration): `units`, `timelineView` (`rows | cards`), `daySummary` (`off | highlights | full`, default `highlights`).
- **Timeline screen** (`/app/groups/:groupId/timeline`, `routes/app/groups/timeline/`):
  - The full view's header is `PageHeader` "Timeline" (no recipient card) with `EasyModeToggle` ("Easy mode") on its right, not in View options ([app-shell](app-shell.md)).
  - Rows or cards, both from `entrySummary()`. `KIND_META`: icon, accent, look (no status colours). `DayHeader` (date, period, then + far right, `summary`; sticky on `day-band`) uses `dayLabel` (schema `core/`). A row's ⋯ and author chip: `[data-entry-aside]`;
  - **Filters live in the URL** (`?kind=&author=<userId>`; `?vital=<type>` under `kind=vital`, repeated `?symptom=<typeId>` under `kind=symptom`; changing the kind drops them), owned by the pure `lib/timeline/timelineFilters.ts`. **Every filter control is a `Link` built through it**. **One toolbar row** (`FilterChips`): magnifier, Filter ("Filter, N on", a badge), View options at the end (full view). Filter opens `FilterSheet` (Kind; one vital type under Vitals, symptom types with entries under Symptoms; the period while searching; Clear keeps `q`); each filter on is a removable chip ("Filters on").
  - **Kind icon** and **author control** (`components/entry/KindIcon.tsx`) are filter links ("Show only …") above the row's open target, for all roles.
  - **The Today card** (`TodayCard`, full view only, ignores filters): latest vitals, next appointment, medications due (Given all for writers), overdue or due-today todos (mine first), each hidden if empty; "See all ›" (`/planner`). `todayStatus` picks a row's hue, icon and screen-reader text. **Collapsed on every load** to `todaySummary`'s line, led by `attentionCounts`: red "N overdue", orange "N due soon" (doses, todos or the next appointment due now or within 1 h; untimed todos are due 19:00), then the rest. `LiveNowBanner` sits beside it (**Join**).
  - **Tiles never pop in:** the Today card's rows and easy mode's blocks read through the tile cache (sync.md): a remembered answer renders dimmed (`data-stale`), actions off until fresh; else a skeleton.
  - **Adding** (`QuickAddMenu`): a + button "Add to <day label>" beside each day's heading; writers, not in easy mode. Another day's adds carry `?at=` (`START_AT_PARAM`, `dayStartAt`): 12:00 that day in the viewer's zone. Vitals is one `ui/Menu` group, expanding in place to its types.
  - **Sheets.** Note and Event open `/entries/new?kind=…`. Symptom and Vitals open the **add-sheet route** `timeline/new/:kind` (`symptom | vital`, `?type=<vitalType>`; `appUrls.newSheet`) in the timeline's `Outlet`, guarded by `newSheetGuard`. **Editing** is `timeline/:entryId/edit` (`appUrls.editSheet`); `editSheetGuard` sends a note or event to its page, anything else uneditable to the timeline. **Sheet links use `prefetch="render"`** (offline after a full load).
  - **Row taps** (`EntryOpenTarget`): Notes and events open `/entries/:id` for everyone; symptoms and vitals open their edit sheet for whoever may change the entry and nothing for others (`openRule`). ⋯ has Delete and Edit by ownership (`canChangeEntry`: writers any, an Easy helper their own) and **Print** (notes and events, everyone). On `/entries/:id` `canWrite` is that rule; `canSetUp` (writers) gates series, cancel, repeat and links.
  - **The quick-entry box** (`canLog`: loggers): `components/quick-entry/`, rules in [assistant](assistant.md).
  - **Empty Today** (writer, full view, unfiltered): "Nothing logged today yet." and "Add an entry" (focuses the box, `fieldRef`).
  - **Day summaries** (`DaySummaryLine`, one truncated line in its `DayHeader`, tap to expand; pure `daySummary.ts`): vitals (a range with an arrow), symptoms (highest severity, "(new)" against the baseline), events, who logged. No notes or doses; a day without vitals, symptoms or events has no line. **Highlights**: vitals with an arrow, new or severe (`SEVERE_SYMPTOM`) symptoms, events. The `daySummary` setting (View options) picks the collapsed line; expanded is always the full breakdown. **Any kind, author, vital or search filter hides every summary** (`summariesOff`).
  - **Infinite scroll** (to now: `historyWindow`): `OlderEntries` grows the limit by `PAGE_SIZE`; the previous window shows until the larger one arrives (`useLiveRows`); Back restores it (`timelinePaging.ts`); older rows get `content-visibility: auto` (`offscreenRows.ts`).
  - **Jump to a day** (`?day=`, the viewer's day; `timelineJump.ts`, `timelineNewer.ts`): a date button, or quick entry's Go to. Entries, links, medications and summaries share one exclusive bound; an empty day shows the nearest earlier one and says so. Only `JUMP_LINK_STATE` or a fresh load scrolls. Scrolling up moves the bound by whole days, holding the row by measurement. A filter change clears it; a jump ends a search.
  - **The route only composes** (`route.tsx`): data from `useTimelineData`, the view from `useTimelineView`, deletes from `useEntryRemoval`.
- **Seeds** (`seeds/timelineEntries.ts`):
  - **Ids follow position** (a change needs `pnpm datastore:reset`); `timelineEntries.test.ts` validates each.
  - A note's or event's seed `body` becomes its document (`seedContentOf`); the entry's `body` stays null.
- **Tests:** beside the route (`timelineWorld.tsx`); browser checks only for the server.
- **The easy view** (`EasyTimeline.tsx`, chosen by `useEasyMode`), in order: the header, the setup card, Upcoming, My todos, the tiles with Remove last, `QuickEntryBox size="md" passChips={false}` (loggers), the full view's `FilterChips`, then `TimelineEntryList easy`: rows only, full type scale, ⋯ menus by ownership and sheets for loggers; `EasyModeToggle` in the header; no filter links or period markers. No adding or strips.
  - **Upcoming** (`EasyNow.tsx`): loggers get each due pass as a big Given all with Undo; the next item opens the Planner's next 5 in place (`EasyNext`; no dose slots) and See all.
  - **My todos** (`EasyTodos.tsx`, `useEasyTodos`): my open todos, at most `EASY_TODOS_CAP`, each with a large tick and Undo.
  - **Tiles** (loggers, `EasyTiles.tsx`; pure `lib/assistant/easyTiles.ts`): four links: fixed, learned (most-logged over 30 days) or the group's picked tiles (`care_group.easy_tiles`, via `useEasySetup`). Each opens its sheet's **easy variant** (`TimelineOutlet.easy`). While `easy_tiles` is null, owners and admins see a "Choose the tiles" link to Details.
  - **Remove my last entry** (loggers, `removeLast.ts`): your own latest entry from the last 30 minutes (never a system-written kind), after a confirm.
