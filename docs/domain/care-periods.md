# Care periods

The care periods area's rules and decisions, moved out of AGENTS.md (whose core rules still apply). An orchestrator folds a landing's lasting decisions for this area in here.

PRD: [`plans/care-periods-prd.md`](../../plans/care-periods-prd.md). Where the recipient is (home, hospital, rehab, hospice…), over time.

- **One track per group, stored by start only** (`care_period`, migration `0018_care_periods`): a period's end is the next period's start; the latest has none and is current. Gaps and overlaps can't be stored, and care never ends on the track. Editing a start moves the previous period's end; a (soft) delete extends the previous one. Order is `(started_at, created_at, id)`; two periods with one start both stay (the earlier-created one has zero length and still shows, so it can be deleted).
- **Columns:** `group_id`, `recipient_id` (composite FK to `care_recipient`), `type`, `label`, `place_provider_id` (composite FK to `provider`, `NO ACTION`; any type; a provider deleted later stays linked and shows greyed "(removed)"), `place_detail` (room, bed), `started_at`, `date_only`, `deleted_at`; unique `(group_id, id)`. Keep the hand-written `ALTER PUBLICATION` at the end of its migration when regenerating.
- **Types** (`CARE_PERIOD_TYPES`, append only): `home`, `emergency`, `hospital`, `rehab`, `assistedLiving`, `memoryCare`, `nursingHome`, `hospiceHome`, `hospiceFacility`, `other` (needs a label: "Say what this is"). An unknown type displays as Other.
- **Start:** a date-only start is midnight in the **recipient's** zone and shows without a time; times show in the recipient's zone. Future starts are refused (device now + 5 min, server now + 1 h; the issue is on `startedAt`). "Day N" counts calendar days in the recipient's zone, the start day being day 1.
- **Write through `carePeriodService`** (create idempotent on id, update validating the merged row, soft remove; the place rule and the start rule are checked only when they change). Any member reads; writers write. A period's notes are a `note_document` with subject `carePeriod` (`care_period_id`).
- **Pure modules, one home each:** the track (`db/schema/care-periods/carePeriodTrack.ts`, client-safe: `periodSpans`, `periodAt` (start included, end excluded), `currentPeriod`, `periodDay`, `periodLengthDays`, `periodRange` (an open period runs to now), `neighbours`); the wording (`lib/care-periods/periodDisplay.ts`: type labels and icons, `currentLineText`, `menuNowText`, `markerText`/`markerSentence`, start, until and length text, `suggestionText`); markers (`lib/care-periods/periodMarkers.ts`); suggestions (`lib/care-periods/periodSuggestions.ts`); search choices (`lib/care-periods/periodSearch.ts`); sheet guards and prefills (`lib/care-periods/periodSheets.ts`).
- **Device** (`lib/care-periods/carePeriods.sync.ts`): `carePeriodsQuery`, `carePeriodQuery`, `placeChoicesQuery`, `createCarePeriod`/`updateCarePeriod` (an optional new place, inserted as a practice in the same transaction), `removeCarePeriod`, `createCarePeriodDocument`. `lib/care-periods/currentPeriod.sync.ts` has `useCurrentCarePeriod(groupId, timeZone)` (the group menu).
- **Screens** (children of the group route; **not a group section**: reached from the timeline line, the group menu and period pages; `appUrls.periods`, `newPeriod(groupId, { type, startedAt, dateOnly, place })`, `period`, `editPeriod`):
  - `periods`: every period newest first (type icon, label, place, start, until or Now with day N, length); "Add period" for writers.
  - `periods/new` and `periods/:periodId/edit`: `PeriodForm` (type `ChoiceGroup`, label, `PlacePickerField` with "Add "<typed>" as a new place", room, a `DateTimeField` in the recipient's zone (its `timeZone` prop) with a maximum of now, "Date only"). Prefills come from the URL. Open them with `PERIOD_SHEET_STATE` so closing returns to where they were opened; a deep link closes to the list. Guards send viewers and missing, deleted or other-group periods to the list.
  - `periods/:periodId` (banded, [ui-kit](ui-kit.md#bands)): a `DetailHeader` (a Now badge; Edit and a ⋯ Delete for writers), Dates, the Place with its contact actions, Other care periods, and live notes (read-only for viewers). Delete confirms what happens to the track ("Rehab will continue until …"). Missing, deleted and other-group periods are the 404.
- **The timeline:** each sticky day header (`DayHeader`, `[data-day-header]`, beside the day's `h3`) shows the period in effect that day, with no place ("In hospital · day 4"; the period's page has it), linking to the period (B-105). Today shows the current period (ticking each minute) and writers get a Change icon button (the period sits right, before the +); a past day shows the period at its newest row (`periodAt`; a marker counts as a row, so a day the period changed shows the new one); a day before the first period, or with no rows, shows nothing. There is no add prompt on the timeline: periods are added from the group menu's Care periods page. The day count is in the recipient's zone. The main header no longer shows a period. **Markers are drawn, never written** (no entry kind): `periodMarkers` picks those in the loaded window (all of them once the beginning is loaded), `withMarkers` (`timelineDays.ts`) places each inside its day at its moment, and `PeriodMarkerItem` renders an `li[data-marker]` linking to the period, read as one sentence, with no place. Markers show under kind and author filters, and hide when a filter or search matches nothing. **Checks that count timeline rows use `ol > li:not([data-marker])`.**
- **Suggestions** (entry page, writers, stored live events only; `PeriodSuggestionChip` in `EntryHeader`'s `suggestion` region): whole-word keyword rules per type ("admitted", "ER", "discharged home", "rehab", "hospice"…; "from", "not", "no" or "outpatient" before a word cancels it), suppressed when the period at the event's time already has that type, and never for future events. The chip opens the add sheet prefilled with the type, the event's time (all-day → date only) and its first linked practice; Home and Hospice at home get no place.
- **Search within a period:** the search page's "When" field (`?period=` beside `q`) and the timeline Filter sheet's Period section and "During <period>" chip (`?period=` in `lib/timeline/timelineFilters`, read only while `q` is set; clearing the search clears it). Both resolve the period through `periodRange` and narrow `occurred_at`. With a period picked, search shows timeline entries only (providers and medications have no dates).
- **Seeds** (`seeds/carePeriods.ts`, own ids): Grandma Pat's Home → Emergency room → Hospital (Mercy General Hospital, appended to `seeds/providers.ts`; "Room 412, bed B", with notes) → Rehab → Home over eight weeks; none for Dev Family 2.
- **Tests:** no area check (`care-periods.mjs` was moved, B-123). Component tests share a fictional track in `periods/periodWorld.tsx`: the periods page and sheets (`periods.browser.test.tsx`), a period's page (`period.browser.test.tsx`), the suggestion chip (`entryPeriodSuggestion`), the group menu (`groupMenuPeriod`) and the timeline's line and markers (`timelineCarePeriods`). A new place uploaded with its period in one batch is `syncCarePeriods.int.test.ts`; the rows reaching a second device are the sync matrix (`care_period`).
