# Todos

The todos area's rules and decisions. An orchestrator folds a landing's lasting decisions for this area in here.

PRD: [`plans/tasks-prd.md`](../../plans/tasks-prd.md) (B-55); renamed todos by [`tasks-2`](../../plans/tasks-2-plan.md) (B-222). A todo is a to-do for the group: a title, an optional assignee, an optional due day and time, done or open, optional notes, and up to one link each to a provider, a medication and an appointment. **Never written as entries:** completing a todo writes no timeline entry; the Planner, strip and easy view work todos out.

## The table and its rules

- **Table `todo`** (`0022_tasks` as `task`, renamed by `0032_todos`): `id` (UUID, device-made), `group_id`, `recipient_id` (composite FK to `care_recipient`), `title`, `assignee_id` (user, nullable, set null when the account is deleted), `assignee_name` (text, nullable), `due_on` (date), `due_time` (`HH:MM`), `done_at`, `done_by`, `provider_id`, `medication_id` (composite FKs, `NO ACTION`), `event_id`, `deleted_at` (soft delete), timestamps and audits; unique `(group_id, id)`.
  - Three DB checks: never both `assignee_id` and `assignee_name`; `due_time` only with `due_on`; `done_at` and `done_by` both or neither.
  - **Two hand edits in the SQL, kept when regenerating:** `event_id`'s composite FK to `timeline_entry` is `ON DELETE SET NULL ("event_id")`, and the `ALTER PUBLICATION` adding the table.
  - `note_document.todo_id` (the `todo` subject; see [live-notes](live-notes.md)).
- **The due time is wall-clock in the recipient's zone**, like medication slots. State and order are worked out, never stored: `db/schema/todos/todoRules.ts` (pure, tested, used on both sides) has `todoState` (done, overdue, today, upcoming, undated), `todoOrder` (overdue first, then by day and time, undated last), `doneOrder` (newest first), `assigneeOf`, `localTime`, `TODO_WRITER_ROLES`/`isTodoWriter`, `canCompleteTodo` and `completionOnly`.
- **Permissions** (`PERMISSIONS.todo`): read any member; create writers; update writers and viewers; delete writers (soft). **The service limits viewers and both easy roles** to `completionOnly` changes on todos assigned to them (`todoService:completionOnly`, 403; one rule for all three). A free-text assignee's task is completed by writers only.
- **`todoService`** (`todoModel`): checks the assignee is a member (when set or changed) and the links are in the group (`todoService:badLink`). `create(ctx, input, { via })`: `via` is server-only, `SYSTEM_ONLY` on update; rows show `ViaTag` ([connectors](connectors.md)).
  - **The leaver:** `releaseAssignee`, from `careGroupMemberService.remove` in the same transaction, turns a removed or leaving member's open todos into `assignee_name` = their display name ("Former member" if none) with `assignee_id` null.
  - **A deleted appointment:** `releaseEvent`, from `timelineEntryService.remove` (now one transaction), clears `event_id` on its todos, done ones included. Entries are soft-deleted, so the FK's `SET NULL` only covers hard deletes. The device's `removeEntry` does the same locally.
- **Sync:** see [sync](sync.md) (`todo` in `care_groups`, soft-deleted included; `todoOp`).

## Repeating todos (planner-2, B-248)

- **Columns** (`0033_todo_repeats`): `repeat_rule` (RRULE text, `appointment_series.rule`'s grammar), `repeat_starts_on` (the anchor) and `repeat_id` (the chain; the first todo's id). Checks: all three or none (`todo_repeat_check`); a rule needs `due_on` (`todo_repeat_due_check`, `REPEAT_NEEDS_DAY_ISSUE`). `repeatColumnsFor` sets them on create and update: a new rule starts a chain on the todo; a changed rule or due day moves the anchor; no rule clears all three. `todoRepeatText` says the rule.
- **`todoRepeat`** (pure, only in `@caretook/data/series`; the device imports it dynamically): `nextDueDay` (the first rule day after both the due day and today, null once ended), `nextTodoId` (UUID v5 of chain and day), `nextOccurrence` (title, assignee, time, provider and medication links, the repeat; not the appointment link, notes or done), `isUntouchedNext` (open, live and as the tick made it, by content).
- **A repeating todo is one open row.** The server is the author of the next: `complete` makes it as the system in the same transaction, "today" being the tick's `doneAt` in the recipient's zone, unless a live row with its id exists (a soft-deleted one is restored). `reopen` soft-deletes an untouched next, else keeps both and the reopened todo stops repeating. `skip` (writers) soft-deletes and makes the next. Stop is the ordinary delete.
- **The screens:** `TodoRepeat` under the due day (a Repeat button, "Doesn't repeat" / "Repeats weekly on Monday", opening `RepeatSheet`, lazy so rrule stays out of first load; disabled without a due day, hint "Choose a due day to repeat"). Clearing the due day clears the repeat; off posts an empty rule, which clears all three columns (`todoFormData`: `FIELD.repeatRule`, `initialRepeat`, `repeatOnDay`). `components/repeat` takes `kind: "todo"` (counts "times"). `TodoRepeatMark` ("Repeats") is on `TodoRow`, `PlannerTodoRow`, `EasyTodos` and the Today card's todo line; `TodoDetails` shows `todoRepeatLine` (`todoDisplay.ts`: "Repeats weekly on Monday", "monthly on the last Friday · until Jan 31", "daily · 10 times"). `RepeatDeleteDialog` (native `<dialog>`: "Skip this one" = `skipTodo`, "Delete and stop repeating" = `removeTodo`, Cancel) opens only for an open repeating todo (`TodoActions`: `repeats`, `SKIP_INTENT`); others keep "Delete this todo?". Edge: a "last Friday" rule reopened in a four-Friday month can become "4th Friday" when re-saved (B-234-like).
- **The device's next is a twin** with the same id, written in the tick's local transaction (`completeTodo`, `reopenTodo`, `skipTodo`). `todoOp`: a PUT whose `repeat_id` is another todo's goes to `upsertOccurrence` (an existing row counts as done for any role; another open todo in the chain makes it a stale no-op; else a writer's skip); a PATCH of `deleted_at` to null restores; one with `done_at` ignores `repeat_rule`.
- Open edge cases (Codex): B-382–B-387.

## On the device (`lib/todos/todos.sync.ts`)

- `toTodo`/`todosQuery`/`doneCountQuery`/`todoQuery` read; `createTodo` (over `plannedTodo`, which quick entry uses too), `updateTodo`, `completeTodo`, `reopenTodo`, `removeTodo` write. A done-only change is a PATCH of `done_at`/`done_by` that the server maps to `complete` or `reopen`.
- `dueTodosQuery`, `dueTodosThrough` and `useDueTodos` (ticking every `DUE_TODOS_TICK_MS`) feed the Planner, the Today card and the easy view; `linkedTodosQuery`, `linkOf` and `TodoLink` serve links.
- Wording in `lib/todos/todoDisplay.ts` (`dueText`, `doneText`, `assigneeLabel`, `linkLabel`); the filter and sections in `lib/todos/todoList.ts`; the tick's Undo in `lib/todos/todoUndo.ts`: a list, newest first, each offer 10 s from its own tick; `TodoUndoStatus` shows a line per todo with its own "Undo <title>".

## Screens

- **The Todos tab** (`routes/app/groups/todos/`, `appUrls.todos`; the Planner's, see [app-shell](app-shell.md)): under `PlannerHeader`, with no header or Add button of its own (the Add menu's Todo opens the sheet). A row with `FilterMenu` (`TodoFilterRow`), one section "Assigned to" (Everyone, Mine, Unassigned; `?who=mine|unassigned`, default Everyone: `DEFAULT_WHO`, `whoOf`, `clearWho`); sections Overdue, Today, by day, No date; Done newest first, paged by 20. Rows open the todo page.
- **Sheets:** `todos/new` (`appUrls.newTodo`) and `todos/:todoId/edit` (`editTodo`; `TodoForm` with native date and time inputs, `AssigneeField`, `TodoLinkFields`). They close back through link state (`TODO_SHEET_STATE`, `openedFromApp` in `lib/todos/todoSheetLink.ts`), so a sheet opened from a Planner tab returns there. `todos/new` takes prefills (`TODO_PREFILL_PARAMS`, `lib/todos/urls.ts`): `providerId`, `medicationId`, `eventId`, `dueOn`, and from quick entry `title`, `assigneeId`, `dueTime`.
- **The todo page** (`routes/app/groups/todo/`, `todos/:todoId`, `appUrls.todo`): banded ([ui-kit](ui-kit.md#bands)): `TodoHeader` (a `DetailHeader`; `TodoActions` edit and delete for writers), Details, Linked to (a removed link reads "(removed)"), Status (`TodoCompletion`), Notes (`useTodoNotes`, the live-notes editor); a missing or deleted todo is a 404.
- **The tick** (`components/todos/TodoTick`, `useTodoTick`; `large` in the easy view) is shared by the list, the page, the Planner, the Today card and the easy view.
- **Links and backlinks:** pickers (`todos/todoLinks.ts`, `LinkPickerField`) choose one provider, one medication and one appointment. `LinkedTodos`/`useLinkedTodos` (`components/todos`) list open linked todos on an event's entry page, a provider's and a medication's page, with "Add todo" prefilled with the link. Hidden when empty, except writers keep a lone "Add todo".
- Elsewhere: todos in the Planner, under All and Todos (`?show=todos`) ([appointments](appointments.md)), the Today card and the easy view's My todos ([timeline](timeline.md)), the search results' Todos section ([search](search.md)), and `addTodo` in quick entry ([assistant](assistant.md)).
