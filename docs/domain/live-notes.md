# Live notes (collaborative documents)

The live notes area's rules and decisions (AGENTS.md's core rules still apply).

PRD: [`plans/live-notes-ux-prd.md`](../../plans/live-notes-ux-prd.md).

- **What they are:** the text of every **note and event** (`NOTE_DOCUMENT_KINDS`), a Yjs document. **Its id is the entry's id**, so two devices adding one offline make the same row and merge.
- **Tables:**
  - `note_document`: `snapshot` (compacted Yjs, base64), derived `text`, and `editors` jsonb `{ [userId]: lastEditAt }` (default `{}`, system-only writes; a forged one in an upload is ignored).
  - A deleted entry, provider, medication, period or todo has its note emptied ([data-layer](data-layer.md#scrub)).
  - **Its owner** is `subject` (`entry | provider | medication | carePeriod | todo`, default `entry`) with `entry_id` or `provider_id`: exactly one set, equal to `id`, each a cascading composite FK. A provider's notes are its document. A todo's notes are its document too (`todo_id`, `task_id` until migration `0032_todos`): `createTodoDocument` makes it on the device; `noteDocumentService.liveOwner` looks the todo up (missing or deleted: `todoNotFound`) ([todos](todos.md)). `useLiveDocuments` and the Live now banner join through `timeline_entry`, so provider documents never show there.
  - `note_update`: append-only, base64 `data`, at most 1,000,000 chars.
  - Composite FKs cascade from the entry. `timeline_entry` has a unique `(group_id, id)` for this.
- **Helpers** (`db/schema/live-notes/noteYjs.ts`, client-safe): base64, `isYjsUpdate`, `buildNoteDoc`, `encodeNoteDoc`, `noteText` and its inverse `noteDocFromText(text, mentions?)` (one paragraph per line, `• ` lines as a bullet list; each `NoteMention { id, label }` becomes a mention node at `@<label>`, longest first, else at the end; none leaves the output unchanged). The fragment is `NOTE_FRAGMENT = "default"`.
- **`noteDocumentService`** (write through it):
  - `create` is idempotent and requires a live note or event; an id another group's document holds is a 403 (checked as the system).
  - `appendUpdate` is idempotent on the update id.
  - `currentText` includes pending updates (for AI and workers); so do the timeline service's reads (`withDocumentText`, read-only), and search first compacts the group's pending updates (`compactPending`).
  - `compact` (system, row locked `FOR UPDATE`) folds pending updates into the snapshot and text, merges their authors into `editors` (`mergeEditors`, latest time per user), and deletes them.
- **Recent editors** (`db/schema/live-notes/noteEditors.ts`, client-safe): `recentEditors({ editors, pending, now, excludeUserId })` combines `editors` with pending `note_update` rows. The window is 2 min (`RECENT_EDITORS_WINDOW_MS`, edge inclusive, one window of future skew allowed), re-evaluated every 15 s (`useNow`). On the device, `lib/live-notes/editors.sync.ts` has `documentEditorsQuery`, `groupLiveEditorsQuery` and `useLiveDocuments` (the group's live notes and events, for the live dot and banner), `toRecentEditors` and `useRecentEditors`. `EditorAvatars` shows up to 3 initials then "+N", never the viewer. An update's `created_at` is the server's: offline edits count as "now" after upload.
  - `compactIfDue`: at 20 pending updates, or after 60 s.
- **Device** (`lib/live-notes/notes.sync.ts`):
  - `createNoteDoc` and `bindNoteDoc` are split so StrictMode's double effects can't destroy a live doc.
  - Typing bursts flush as one `note_update` 250 ms after the last keystroke, and at least every 1 s.
  - A viewer's changes are never written; an Easy helper writes only the documents of entries they created (`noteDocumentService.mayWriteOwner`, in SQL via `groupOwn`; never a provider's, medication's, care period's or todo's).
  - Previews rebuild locally (unsynced edits too), reading only the list window's documents (B-313); Full view cards show formatting (`noteRichText`, `entry/NoteRichText`, no Tiptap).
- **Entry page** (`routes/app/groups/entry/route.tsx`, `/entries/:id`; `/entries/new?kind=note|event` is a draft, the same route so the editor stays mounted):
  - Nothing is written until the first real change (`shouldMaterialize` in `lib/live-notes/liveEntry.ts`: text in the document, or a title). Then `materializeLiveEntry` (`lib/live-notes/liveEntry.sync.ts`) writes the entry and its document in one local transaction (idempotent on the id; for an older event it adds only the document), and the URL is **replaced** with `/entries/:id`.
  - `bindNoteDoc`'s `ensureSaved` holds a draft's Yjs changes in memory until then; leaving drops them.
  - **Quick entry's event draft** (`EventDraft` in history state, read once by `route.tsx`; `withEventDraft` in `entryPage.ts` applies title, time, zone, all-day, place and providers over the loader's data). `EntryPageData.withProviders` is a list (`?provider=` gives one id); a draft's providers show as removable chips in the With row (live in the group) and are linked when it saves; a time picked on a draft with providers saves it.
  - `EntryHeader` has four regions:
    - **title:** `EntryTitle`, editable by writers for both kinds. `commitTitle` saves a new draft, or renames an existing entry. While an event is unnamed (`isUnnamedEvent`) and nothing is typed, writers see `EventTitleChips`: up to 5 of the group's recent event titles (`suggestTitles`, `lib/live-notes/titleSuggestions.ts`: 14-day half-life, case-insensitive dedupe, no "Event" or deleted entries; read locally, so offline too). A tap goes through `commitTitle`.
    - **time:** `EntryTimeChip` for writers (a `DateTimeField` popover; saved on close if changed; a time picked on a draft is the saved time, `occurredAtRef`). Viewers get a plain `EntryTime`.
    - **editors:** `EditorAvatars`.
    - **actions:** once the entry exists, `ShareButton` for everyone, plus `EntryActions` (⋯ → Delete, with a `ConfirmDialog`, then back to the timeline) for writers.
  - **Share** (`share.ts` beside the entry route): the Web Share API when `canShare` allows it, else the clipboard with a "Link copied" status; a dismissed sheet shows nothing; a failed copy, the link. The origin is `VITE_API_ORIGIN || location.origin`.
  - Symptom or vital ids, and non-members, get a 404 that shows no title or text.
  - ✅ **Todos:** a stored note's or event's page has the Todos section (`EntryTodos`, [todos](todos.md)); a todo can show on several entries.
  - **The route only composes**: `loadEntry.ts` (the loader's reads and 404 rules), the `useLiveEntry` hook (`entry`, `stored`, `isNew`, `canWrite`, `deleted`, `ensureSaved`, `commitTitle`, `changeTime`, `remove`, `saveError`; no JSX), `EntryPageHeader` (fills `EntryHeader`'s regions and owns the delete dialog) and `EntryTitleRegion` (the title and chips; it owns the typed text). Pure, tested: `entryPage.ts` (`entryHeading`, `titleState`, `showTitleChips`). **`LiveNotesEditor` takes an optional `ref`** (`LiveNotesEditorHandle { focus() }`); a picked title chip focuses the editor through it, never by querying the DOM.
- **Visit prep** (B-58): `prependNoteSection(doc, lines)` (`schema/noteYjs.ts`; typed lines: heading, subheading, bullet) inserts at the start of a document in one transaction, never touching existing content; it syncs as an ordinary `note_update` (`insertNoteSection` in `lib/appointments/visitPrep.sync.ts`, writers only, creating the document in the same transaction if there is none). A rerun prepends a newer dated section ("(updated …)"). What goes in it: [appointments](appointments.md). `appendNoteSection` (paragraphs, bullets as their own list) is its twin at the end, for a connector's `append_to_entry`; `noteDocumentService.currentDoc` gives the document with pending updates.
- **Print** (everyone, notes and events): the entry page's `EntryPrintView` (title, time, place, With providers, text) shows only in print; the rest of the page is `print:hidden`. Rows elsewhere link to `appUrls.printEntry` (`?print=1`), which prints once and drops the parameter (`useEntryPrint.ts`).
- **Full screen:** a native dialog the editor frame moves into (same Tiptap and Yjs), edge to edge, safe-area aware, title and avatars in its bar beside Exit (B-962; toolbar on a second row on a phone); it closes on Escape itself (ProseMirror swallows it) unless the mention popup is open.
- **Editor:** `LiveNotesEditor` is Tiptap StarterKit (`undoRedo: false`, because Collaboration brings Yjs undo; `link: false`). Its chunk is about 140 KB gzipped and loads only on its route.
- **Mentions** (`@tiptap/extension-mention`, `@tiptap/suggestion`, in Vite's `optimizeDeps`; rules in [providers](providers.md)): an inline atom `MENTION_NODE` (`id`, `label`: the name when typed), always in the schema so any document opens; stored in Yjs like any node. `noteText` writes `@<label>`; `noteDocFromText` places the ones it's given. The editor takes optional `providers`, `onMention`, `onAdd`, `onImport`; no `providers` or write access, no popup. The popup (`MentionPopup`, `useMentionPopup`) is a listbox "Providers to mention" under the caret; focus stays in the editor; arrows wrap, Enter picks, Escape closes. An add or import inserts at its own @, mapped through later edits, or nowhere if that @ is gone.
- **Vite:** `optimizeDeps.include` pre-bundles yjs and Tiptap, and `resolve.dedupe` keeps one yjs, React and ProseMirror. Without both: "Yjs was already imported", broken hooks.
- **Latency:** a co-editor sees typing in about 0.5–0.8 s locally. Offline edits land about 2.5–3 s after reconnecting.
- ❓ Presence and cursors (a websocket relay such as Hocuspocus): decide after real use. 🟡 Not built: a compaction cron sweep, a snapshot size cap, an oRPC read for documents.
- **Tests:** the entry page is component tests (`entry/entry.browser.test.tsx`), and so are the Live now banner and live dot (`timeline/timelineStrips.browser.test.tsx`, with expiry). The `live-notes` check keeps what needs devices: uploads, Live now from another device and Join, who's typing across devices with convergence and compaction, offline then reconnect, a time change and delete reaching others, a link opened signed out, and a mention reaching the other devices as a chip and a With chip.
