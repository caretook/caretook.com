# Assistant (quick entry and its actions)

PRD: [`plans/assistant-prd.md`](../../plans/assistant-prd.md); plan: [`plans/assistant-plan.md`](../../plans/assistant-plan.md). **No remote AI, no new vendor, no new dependency:** everything runs on the device from local data, and voice is the keyboard's dictation. English only.

- **Actions** (`packages/data/src/db/schema/assistant/assistantActions.ts`, client-safe through `@caretook/data/schema`): `assistantActionZSchema`, a discriminated union `logVital | logSymptom | logDose | addNote | addEvent | givePass | addTodo`, built from the existing content schemas and limits. Every action but `addTodo` has `occurredAt`; `ACTION_KINDS` gives each kind; `addEvent` also carries `timeZone`, `providerIds`, `allDay`, `place`, `endsAt`; `addNote` carries `providerIds` (default `[]`, max 20). **Actions carry no ids and nothing device-only**, so the server runner (`assistantActionService.run`, [connectors](connectors.md)) carries out the same shapes.
- **The parser** (`schema/quickEntry.ts`, pure): `parseQuickEntry(text, context)` → `{ parts: [{ text, readings: [{ kind, label, actions, confidence, warnings }] }] }`. Context: units, medications, providers, `now`, the recipient's time zone.
  - Splits on `,` `;` "and" "then" and new lines (not inside `1,000`). `n: e: s: v: d:` force a kind; a line starting `n:` or `e:` stays whole.
  - Every part has at least a note reading. Hard limits, the BP order rule and a future time on a past-only kind are **blocking** warnings; unusual values only warn.
  - Medication names match by prefix, folding, a word in the directions or reason, and edit distance; providers by last or practice name. `HONORIFICS` lives here (`lib/providers/providerSuggestions.ts` re-exports it).
  - **The vocabulary** (`schema/assistant/quickEntryVocabulary.ts`, imported from its file): `QUICK_ENTRY_VOCABULARY` rows `{ phrase, role, name?, unlessNext? }`, roles `symptomIncident` (canonical name: "fell" → Fall), `noteIncident` (911, ER, urgent care…), `visitVerb` (saw, went to…), `contactVerb` (called, emailed…), `appointmentWord`; longest phrase first, `unlessNext` for exceptions ("fell asleep"). **A kind-picking word is always a row here plus a test row**, never a list elsewhere.
  - **Kinds:** a part keeps every plausible reading (symptom, event, note) so the cards can switch. A **clearly named** provider (a last name, title + name, a practice's full name, or its first word after at/to/from or a verb; a bare first name isn't) makes an event linked to it: title from the leftover words (time, provider words, verbs and filler dropped), else the provider's name; place from "at …", else the provider's address; no time → all-day today. A `contactVerb` or `noteIncident` ranks a note first (carrying the provider, its words rewritten to `@Name`), the event second; a `symptomIncident` gives its canonical symptom, severity null.
  - Time phrases (`schema/quickEntryTime.ts`, DST-safe, in the recipient's zone): clock times, relative (`30 min ago`, `in 2 hours`), named days (`yesterday 9pm`, `last night`, `tonight`), weekdays, month dates ("Nov 25") and days of the month ("25th", "on the 25th"; not before count words like "2nd dose"; a month without that day is skipped). **The reading picks the direction:** events and todos read forward (a passed day of the month → next month); notes and other past-only kinds read back (a bare weekday or day of the month is the last one); a `visitVerb` makes an event read back; "next"/"last" are explicit.
  - The table-driven test is `quickEntry.test.ts`; add a row for every new rule.
- **The runner** (`lib/assistant/quickEntry.sync.ts`): `runActions(db, groupId, actions)` validates the whole batch first (schemas, `futureRefusal`, writer role, live medication and providers in the group), then writes it in **one local transaction** through the timeline's building blocks (notes and events get their document and one `note_update` from `noteDocFromText`, with a note's providers as mentions; provider links by `entryProviderId`). It returns the ids in order, or `{ ok: false, index, error, issues }`; a refusal leaves nothing.
- **Preview wording** (`actionPreview`, `whenText`) is in `@caretook/data/schema` (`assistant/quickEntryPreview.ts`), shared with the connector's write tools.
- **The box** (`components/quick-entry/`, `QuickEntryBox` via its index; `useQuickEntry` owns state, `useQuickEntryData` reads live, `quickEntryCards.ts` the card rules):
  - A growing textarea; Enter saves, Shift+Enter adds a line. A card per part: its kind as a badge (`[data-quick-kind]`), the other kinds as "Make it a note" / "Make it an event" buttons (`kindChoices`, `makeItLabel`), same-kind alternatives as "Metoprolol 25 mg instead", Edit and Remove. Save writes every card ("Saved 3 entries", polite).
  - **Edit:** vitals and symptoms open the add sheet filled in, doses the Dose sheet (drafts in history state, `quickEntryDraft.ts`). Notes and events have no sheet, so Edit saves that card and opens its entry page; a provider event opens its draft (below) and writes nothing.
  - Name matches arrive a moment after mount (live queries); the box re-reads the line when they do, so tests wait for the expected kinds.
- **Suggestions:** nothing shows under an empty box. A Sparkles button inside the field's border (`QuickEntrySuggestButton`, only while the box is empty and some row has something) opens a `ui/Popover` (`QuickEntrySuggestions`): the due pass (below), "Usual around now" (`usualAtHour`: ±60 min of now on ≥ 3 of the last 14 days, not today), then "Your recent lines"; a chip fills the box and closes it. While typing, "Matching names" (`QuickEntryCompletions`; `lib/assistant/quickEntryCompletion.ts`, `completeName`: medications then providers, by word prefix, titles skipped) floats under the field on `SURFACE`; Escape or leaving the field hides it. A static placeholder (`QUICK_ENTRY_PLACEHOLDER`); the rules are the screen-reader description (`QUICK_ENTRY_RULES`). **A chip only fills the box; nothing saves until Save.**
- **Recent lines** are the last 8 distinct saved lines per user and group, in localStorage (`caretook:recentLines:<userId>:<groupId>`), recorded on Save as `recentLineFor(line, parsed)` gives it (nothing for notes and events, a vital's keys only: "bp hr "), cleared by `wipeDevice()` at sign-out (the `session-end` check asserts it).
- **Tests:** component tests (`timeline/timelineQuickEntry*.browser.test.tsx`); no assistant browser check.
- **Passes** (slice 7): `givePass` (`{ passId, occurredAt }`, kind dose) logs a pass as Given all does. The parser reads "gave evening meds", "evening meds given", "gave meds" / "gave all" with `context.passes` (`QuickEntryPass`): the longest pass name wins; "gave meds" picks a pass with something left, then the one nearest a time phrase, else due first, then nearest by the clock; `open: 0` blocks ("Nothing is left to give in X today."). The runner plans it from `duePasses` and `givenAllWrites` in the same transaction, and refuses a gone pass, one with no medications, or nothing left.
- **Todos** (tasks PRD): `addTodo` (`{ title, assigneeId?, dueOn?, dueTime?, providerId?, medicationId?, eventId? }`, a time only with a day) is asked for by a `t:`, `task:`, `todo:` (or `todo` alone), `to-do:` or `to do:` prefix, or by a note line that says a time ahead (below). The parser matches "for Sam" or "@Sam" against `context.members` and reads a due day forward ("Friday" is the next one). The runner writes it through `plannedTodo` (`lib/todos/todos.sync.ts`) in the same transaction, and `removeEntries` (Undo) removes todos too. A `todo:` line's Note alternative is dated now. The Saved line counts both ("Saved 2 entries and 1 todo"). A todo card's Edit opens `todos/new` with `title`, `assigneeId`, `dueOn` and `dueTime` prefilled. See [todos](todos.md).
- **Notes are past-only.** A line with `noteAhead` (a phrase pointing ahead: "tomorrow", "in 2 hours", "next friday"; a time beside an appointment word that isn't a visit; a time read back that is still to come today, like "tonight"; always beyond the 5-minute skew) gives `addTodo`: the title is the line without its time words, `dueOn`, `dueTime` when given, "for Sam" / "@Sam" assigns. Cards: Todo, then Note (dated now, whole line), then Event. A forced `n:` line ahead stays a note and is blocking ("Can't be in the future"), with the todo as its alternative. A bare time ahead with no provider or appointment word is only an event alternative (confidence 0.3). The server twin refuses a note ahead through `isTooFarAhead`.
- **Open after save:** a line that saved exactly one note or event opens its entry page (`openAfterSave`, pure). Its Undo goes with the box; the page has Delete.
- **The event draft:** the first card whose chosen reading is an event with a provider is the draft (`markDraft`, `draftCardOf`; `opensDraft`, the card's "Opens to finish · Dr. Elena Alvarez · Wed, Nov 25" line). Save writes every other card as one batch (Undo on the box's line), then pushes `entries/new?kind=event` with an `EventDraft` (`{ title, occurredAt, allDay, place, providerIds, timeZone }`) in history state. A draft alone writes nothing and offers no Undo; a later provider event in the line is written directly. The page: [live-notes](live-notes.md).
- **The runner's result** is `{ ids, byAction }`: every entry written (a pass writes one per medication) and each action's entries. **Undo after Save** uses the shared offer (`lib/medications/passUndo.ts`, 10 s; offers carry `entryIds` and a `place`): "Saved 3 entries · Undo" on the box's line, and Undo soft-deletes the whole batch through `removeEntries(db, ids)`.
- **The due pass** is the popover's first row ("Give evening meds (4)", one tap is Given all with Undo and closes it), and the button reads "Suggestions, a pass is due" with a dot; not in easy mode (`passChips={false}`), where the easy view's Upcoming card offers it. Pass names complete while typing. A pass card reads "Evening medications · Given all · 4 medications"; Edit opens the Dose sheet on that pass.
