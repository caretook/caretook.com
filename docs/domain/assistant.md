# Assistant (quick entry and its actions)

The assistant area's rules and decisions. An orchestrator folds a landing's lasting decisions for this area in here.

PRD: [`plans/assistant-prd.md`](../../plans/assistant-prd.md); plan: [`plans/assistant-plan.md`](../../plans/assistant-plan.md). **No remote AI, no new vendor, no new dependency:** everything runs on the device from local data, and voice is the keyboard's dictation. English only.

- **Actions** (`packages/data/src/db/schema/assistantActions.ts`, client-safe through `@caretook/data/schema`): `assistantActionZSchema`, a discriminated union `logVital | logSymptom | logDose | addNote | addEvent | givePass | addTask`, built from the existing content schemas and limits. Every action but `addTask` has `occurredAt`; `ACTION_KINDS` gives each action's kind (a timeline kind, or `task`); `addEvent` also carries `timeZone`, `providerIds`, `allDay`, `place`, `endsAt`. **Actions carry no ids and nothing device-only**, so `connectors` (B-104) can carry out the same shapes through the services.
- **The parser** (`schema/quickEntry.ts`, pure): `parseQuickEntry(text, context)` → `{ parts: [{ text, readings: [{ kind, label, actions, confidence, warnings }] }] }`. Context: units, medications, providers, `now`, the recipient's time zone.
  - Splits on `,` `;` "and" "then" and new lines (not inside `1,000`). `n: e: s: v: d:` force a kind; a line starting `n:` or `e:` stays whole.
  - Every part has at least a note reading. Hard limits, the BP order rule and a future time on a past-only kind (beyond the 5-minute skew) are **blocking** warnings; unusual values only warn.
  - Medication names match by prefix, folding, a word in the directions or reason, and edit distance; providers by last or practice name. `HONORIFICS` lives here (`lib/providerSuggestions.ts` re-exports it).
  - Time phrases (`schema/quickEntryTime.ts`, DST-safe, in the recipient's zone): clock times, relative (`30 min ago`, `in 2 hours`), named days (`yesterday 9pm`, `last night`, `tonight`), weekdays and month dates.
  - The table-driven test is `quickEntry.test.ts`; add a row for every new rule.
- **The runner** (`lib/sync/quickEntry.ts`): `runActions(db, groupId, actions)` validates the whole batch first (schemas, `futureRefusal`, writer role, live medication and providers in the group), then writes it in **one local transaction** through the timeline's building blocks (notes and events get their document and one `note_update` from `noteDocFromText`; provider links by `entryProviderId`). It returns the ids in order, or `{ ok: false, index, error, issues }`; a refused action leaves nothing.
- **Preview wording** is `lib/quickEntryPreview.ts` (`actionPreview`, `whenText`), on the existing display helpers; it moves to `packages/data` if `connectors` needs it on the server.
- **The box** (`components/quick-entry/`, `QuickEntryBox` via its index; `useQuickEntry` owns state, `useQuickEntryData` reads medications and providers live, `quickEntryCards.ts` the pure card rules):
  - A growing textarea; Enter saves, Shift+Enter adds a line. A card per part with alternatives as chips ("Note instead"), Edit and Remove. Save writes every card and says "Saved 3 entries" (polite status); the cards are read out by a separate polite region after typing stops.
  - **Edit:** vitals and symptoms open the add sheet filled in, doses the Dose sheet (drafts in history state, `lib/quickEntryDraft.ts`; `EntryForm` and `DoseForm` take an optional `draft`). Notes and events have no sheet, so Edit saves that card and opens its entry page.
  - Name matches arrive a moment after mount (live queries); the box re-reads the line when they do, so tests wait for the expected kinds.
- **Suggestions** (`QuickEntrySuggestions`, `{ groupId, text, onFill }`, below the field): while typing, "Matching names" (`lib/quickEntryCompletion.ts`, `completeName`: medications then providers, by word prefix, titles skipped); with the box empty, "Usual around now" (`lib/quickEntryPredictions.ts`, `usualAtHour`: ±60 min of now in the recipient's zone on ≥ 3 of the last 14 days, today excluded), then "Your recent lines" (`lib/recentLines.ts`), then the tips line (`showTips`; the simple view's `lg` box leaves it out and keeps only its dictation hint, B-157). **A chip only fills the box; nothing saves until Save.**
- **Recent lines** are the last 8 distinct saved lines per user and group, in localStorage (`caretook:recentLines:<userId>:<groupId>`, every access in try/catch), recorded when Save succeeds, cleared by `wipeDevice()` at sign-out (`session-end.mjs` asserts it).
- **Tests:** the box, cards, runner and suggestions are component tests (`timeline/timelineQuickEntry.browser.test.tsx`, `timelineQuickEntrySuggestions.browser.test.tsx`); there is no assistant browser check.
- **Passes** (slice 7): `givePass` (`{ passId, occurredAt }`, kind dose) logs a pass as Given all does. The parser reads "gave evening meds", "evening meds given", "gave meds" / "gave all" with `context.passes` (`QuickEntryPass`): the longest pass name wins; "gave meds" picks a pass with something left, then the one nearest a time phrase, else due first, then nearest by the clock (up to 3 alternatives); `open: 0` blocks ("Nothing is left to give in X today."). The runner's `givePass` plans from `duePasses` and `givenAllWrites` (open slots only, one round) inside the same transaction, and refuses a gone pass, a pass with no medications, or nothing left. Two `givePass` actions for one pass in a batch aren't deduplicated.
- **Tasks** (tasks PRD): `addTask` (`{ title, assigneeId?, dueOn?, dueTime?, providerId?, medicationId?, eventId? }`, a time only with a day) is only ever asked for, by a `t:`, `task:`, `todo:` (or `todo` alone) or `to-do:` prefix. The parser matches "for Sam" or "@Sam" against `context.members` and reads a due day forward ("Friday" is the next one). The runner writes it through `plannedTask` (`lib/sync/tasks.ts`) in the same transaction, and `removeEntries` (Undo) removes tasks too. The Saved line counts both ("Saved 2 entries and 1 task"). A task card's Edit opens `tasks/new` with `title`, `assigneeId`, `dueOn` and `dueTime` prefilled. See [tasks](tasks.md).
- **The runner's result** is `{ ids, byAction }`: every entry written (a pass writes one per medication) and each action's entries. **Undo after Save** uses the shared offer (`lib/passUndo.ts`, 10 s; offers carry `entryIds` and a `place`): "Saved 3 entries · Undo" on the box's line, and Undo soft-deletes the whole batch through `removeEntries(db, ids)`; `[data-quick-status]` holds only errors.
- **The due pass** comes first among the empty box's chips ("Give evening meds (4)", one tap is Given all with Undo; `useQuickEntryPasses` over `useDueDoses` and `duePasses`), except in simple mode's large box, where the Now block offers it. Pass names complete while typing (after medications, before providers). A pass card reads "Evening medications · Given all · 4 medications"; Edit opens the Dose sheet on that pass.
