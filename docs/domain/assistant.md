# Assistant (quick entry and its actions)

**No remote AI or vendor:** all on the device from local data; voice is the keyboard's dictation. English only.

- **Actions** (`db/schema/assistant/assistantActions.ts`, client-safe): `assistantActionZSchema`, a union `logVital | logSymptom | logDose | addNote | addEvent | givePass | addTodo`. All but `addTodo` have `occurredAt`; `addEvent` adds `timeZone`, `providerIds`, `allDay`, `place`, `endsAt`; `addNote` `providerIds`. **Actions carry no ids or device-only data**, so the server runner (`assistantActionService.run`, [connectors](connectors.md)) runs them too.
- **The parser** (`schema/quickEntry.ts`, pure): `parseQuickEntry(text, context)` → `{ parts: [{ text, readings: [{ kind, label, actions, confidence, warnings }] }] }`. Context: units, medications, providers, `now`, time zone, `page`.
  - Splits on `,` `;` "and" "then" and new lines (not inside `1,000`). `n: e: s: v: d:` force a kind; a line starting `n:` or `e:` stays whole.
  - Every part has a note reading. Hard limits, the BP order and a future time on a past-only kind **block**; odd values warn.
  - **A vital label reads after or before its number** (`o2 97`, `97 o2`, `97o2`; `7hr` stays hours); a number between two labels is the first's, unless `74 hr 97 o2`.
  - Medications match by prefix, folding, a directions or reason word, edit distance; providers by last or practice name.
  - **The vocabulary** (`quickEntryVocabulary.ts`): `QUICK_ENTRY_VOCABULARY` rows `{ phrase, role, name?, unlessNext? }`, roles `symptomIncident`, `noteIncident`, `visitVerb`, `contactVerb`, `appointmentWord`, `requestVerb`, `requestLead`, `reportWord`, `newMedication`, `newProvider` (`wholeLine`: not split), `repeatWord`; longest first. **Each kind-picking word is a row here plus a test row**.
  - **Kinds:** a part keeps every plausible reading so the cards can switch. A **clearly named** provider (last name, title + name, practice name or its first word after at/to/from or a verb; no bare first name) makes an event linked to it: title from the leftover words, else the provider's name (a keyword line: the words, else "Event with <provider>", else "Event"); place from "at …", else the provider's address; no time → all-day today. A `contactVerb` or `noteIncident` ranks a note first (the provider as `@Name`), the event second; a `symptomIncident` gives its canonical symptom, severity null. An exact match in context `symptoms` takes its spelling.
  - Time phrases (`schema/quickEntryTime.ts`, DST-safe, in the recipient's zone): clock, relative (`in 2 hours`), named days (`last night`), weekdays, dates. **The reading picks the direction:** events and todos read forward (a passed day → next month); notes and other past-only kinds read back (a bare weekday or date is the last one); a `visitVerb` makes an event read back; "next"/"last" are explicit.
  - **Words that aren't times:** "sat"/"sun" need on, last, next or this, a time after, or the line's end; an ordinal needs "on", a month, the line's end, a time word or "at" a place. "11/25" is month first; n/10, common fractions and a number before a unit are dates only after "on". Nor is a measurement's slash number. Forward, a bare hour is from 7:00. A period begun is now for past-only kinds (`periodUnderway`); `noteAhead` sees its usual hour; a time ahead on an opening request is a todo, above a vital or symptom.
  - **Doses:** a negation up to three words before give or take, or "not given", reads `skipped` (not a "no" opening a symptom); before skip or refuse, no dose; after the verb, note text; anywhere in a pass line, no `givePass`. A count or fraction beside a medication is the amount, in the usual unit; a number in its name, equal to its strength after it, or above 20, isn't; a whole number at strength with a usual dose over one unit asks (`asksAmount`, given doses only); a fraction or decimal at strength ("1/2") is a one-unit or same-measure usual dose, else as typed. Its words are never a symptom's name; where it's applied isn't its name.
  - Table tests (`quickEntry*.test.ts`): a row per rule.
- **The runner** (`lib/assistant/quickEntry.sync.ts`): `runActions(db, groupId, actions)` validates the batch first (schemas, `futureRefusal`, writer role, live medication and providers), then writes it in **one local transaction** via the timeline's building blocks (notes and events: a document and one `note_update`, providers as mentions). A symptom adds its catalog row. A refusal (`{ ok: false, index, error, issues }`) writes nothing.
- **Preview wording** (`actionPreview`, `whenText`, `@caretook/data/schema`) is shared with the connector's write tools.
- **The box** (`components/quick-entry/`, `QuickEntryBox`; `useQuickEntry` state, `useQuickEntryData` live reads, `quickEntryCards.ts` card rules):
  - A growing textarea; Enter saves, Shift+Enter a new line. A card per part: a kind badge (`[data-quick-kind]`), "Make it a note" / "Make it an event", same-kind alternatives Edit, Remove. Save writes every card.
  - **Edit:** vitals and symptoms open the add sheet filled in, doses the Dose sheet (history state, `quickEntryDraft.ts`). Notes and events: Edit saves that card and opens its page; a provider event opens its draft (below), writing nothing.
  - A near-match symptom saves as the closest name (`withSymptomGates`; other names, "Add … as new").
  - Card state only for current parts (`pruneCardState`).
- **Suggestions:** an empty box shows nothing. A Sparkles button opens a Popover: the due pass, "Usual around now" (`usualAtHour`: ±60 min on ≥ 3 of the last 14 days), recent lines; a chip fills the box. While typing, "Matching names" (`completeName`: medications then providers, by word prefix) opens above the field (below, in flow, with no room); Tab completes one name, or focuses the first chip. **A chip fills the box; Save saves.**
- **Recent lines:** the last 8 distinct saved lines per user and group (localStorage, `recentLineFor`: none for notes and events, a vital's keys only: "bp hr "); `wipeDevice()` clears them.
- **Tests:** component (`timelineQuickEntry*`, `quickEntrySheet`, `quickEntryShortcut`, `quickEntryCommand`).
- **Passes:** `givePass` (`{ passId, occurredAt }`, kind dose) logs a pass as Given all does. It reads "gave evening meds", "evening meds given", "gave meds" / "gave all" with `context.passes` (`QuickEntryPass`): the longest name wins; "gave meds" picks a pass with something left (nearest a time phrase, else due first); `open: 0` blocks. The runner plans it (`duePasses`, `givenAllWrites`); it refuses a gone or empty pass.
- **Todos:** `addTodo` (`{ title, assigneeId?, dueOn?, dueTime?, providerId?, medicationId?, eventId?, repeatRule? }`: a time or a `repeatRule` needs `dueOn`; `eventId` an event, else `todoService:badLink`, saved as a link row) comes from a leading kind word (todo, task, note, event…; whole word), `t:`, a note line ahead (below) or a repeat. A leading `add` before a kind word is dropped; `add` alone stays text. note/event cues keep the line whole (`KIND_CUE`). "for Sam"/"@Sam" match `context.members`. The runner writes it through `plannedTodo` in one transaction; Undo removes it. Edit opens `todos/new` prefilled. See [todos](todos.md).
- ✅ **Repeats** (`quickEntryRepeat.ts`, pure, no rrule or `@caretook/data/series`): daily, every (other / N) day(s), weekdays alone or listed ("every mon, wed and fri", "mondays"), "every weekday", "every other monday", weekly / every N weeks "on <days>", monthly "on the 15th"; 1–99; not "every 4 hours", "everyone". The first day can be today; a month lacking the date is skipped (as rrule). A line with a repeat is a repeating todo (0.85) unless, less the repeat words, it reads as a vital, dose, pass or symptom at ≥ 0.5, tells what happened, or opens with a new medication/provider. A strong event (≥ 0.8) stays first (`REPEATING_EVENT_MESSAGE`), the todo second.
- **Notes are past-only.** A line with `noteAhead` ("tomorrow", "in 2 hours"; a time by a non-visit appointment word; a time still to come today, like "tonight"; beyond the 5-minute skew) gives `addTodo`: the line less its time words, with `dueOn` (and `dueTime`). Cards: Todo, Note (now), Event. A forced `n:` line ahead is a blocked note; a bare time ahead, only an event alternative. The server twin refuses a note ahead through `isTooFarAhead`.
- **Open after save:** one saved note or event opens its page (`openAfterSave`).
- **The draft:** the first new medication or provider (`quickEntryNewItem.ts`, `newItemPreview` in `@caretook/data/schema`; its Add sheet filled in, writers only), else the first event with a provider (`markDraft`, `draftCardOf`). Save writes the other cards as one batch (with Undo), then pushes `entries/new?kind=event` with an `EventDraft` in history state. A draft alone writes nothing. See [live-notes](live-notes.md).
- **Runner result** is `{ ids, byAction }` (a pass: one per medication). **Undo after Save** (`passUndo.ts`, 10 s) soft-deletes it.
- **The due pass** is the popover's first row ("Give evening meds (4)": one tap is Given all, with Undo); the button gets a dot; not in easy mode.
- **Commands** (`readCommand`, `quickEntryGoTo.ts`, pure; not actions): read whole before splitting; device only, never the runner or recent lines. go to / jump to / show + a day (**viewer's** zone; future blocked) or + a page (`QUICK_ENTRY_PAGES`); `NEW_TAB_PHRASES` set `newTab`. One `QuickEntryCommandCard`, Go not Save: `runCommand` (`lib/assistant/`) opens the page's `appUrls` URL, a new tab via `window.open(…, "noopener")` (in place on native), then closes the sheet.
- **The sheet** (`QuickEntrySheet`, group layout): the box in a kit `Sheet`, opened by `openQuickEntry`; stays open after Save (box's Undo). Keys (`useQuickEntryShortcut`): `/` outside a field, Cmd/Ctrl+K; only where the button shows (`useOfferQuickEntry`), not in another dialog. **Readers** (`!canLog`): no cards, only `READER_REFUSAL`.
- **Page context** (`pageContextFor(params)` → `QuickEntryPageContext`, as `context.page`): a provider's page links a note or event naming none; a medication's page makes a dose line naming none ("gave 1", "skipped") its dose. A named one wins.
