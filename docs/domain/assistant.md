# Assistant (quick entry and its actions)

The assistant area's rules and decisions. An orchestrator folds a landing's lasting decisions for this area in here.

PRD: [`plans/assistant-prd.md`](../../plans/assistant-prd.md); plan: [`plans/assistant-plan.md`](../../plans/assistant-plan.md). **No remote AI, no new vendor, no new dependency:** everything runs on the device from local data, and voice is the keyboard's dictation. English only.

- **Actions** (`packages/data/src/db/schema/assistant/assistantActions.ts`, client-safe through `@caretook/data/schema`): `assistantActionZSchema`, a discriminated union `logVital | logSymptom | logDose | addNote | addEvent | givePass | addTask`, built from the existing content schemas and limits. Every action but `addTask` has `occurredAt`; `ACTION_KINDS` gives each action's kind (a timeline kind, or `task`); `addEvent` also carries `timeZone`, `providerIds`, `allDay`, `place`, `endsAt`. **Actions carry no ids and nothing device-only**, so the server runner (`assistantActionService.run`, [connectors](connectors.md)) carries out the same shapes.
- **The parser** (`schema/quickEntry.ts`, pure): `parseQuickEntry(text, context)` → `{ parts: [{ text, readings: [{ kind, label, actions, confidence, warnings }] }] }`. Context: units, medications, providers, `now`, the recipient's time zone.
  - Splits on `,` `;` "and" "then" and new lines (not inside `1,000`). `n: e: s: v: d:` force a kind; a line starting `n:` or `e:` stays whole.
  - Every part has at least a note reading. Hard limits, the BP order rule and a future time on a past-only kind (beyond the 5-minute skew) are **blocking** warnings; unusual values only warn.
  - Medication names match by prefix, folding, a word in the directions or reason, and edit distance; providers by last or practice name. `HONORIFICS` lives here (`lib/providers/providerSuggestions.ts` re-exports it).
  - Time phrases (`schema/quickEntryTime.ts`, DST-safe, in the recipient's zone): clock times, relative (`30 min ago`, `in 2 hours`), named days (`yesterday 9pm`, `last night`, `tonight`), weekdays and month dates.
  - The table-driven test is `quickEntry.test.ts`; add a row for every new rule.
- **The runner** (`lib/assistant/quickEntry.sync.ts`): `runActions(db, groupId, actions)` validates the whole batch first (schemas, `futureRefusal`, writer role, live medication and providers in the group), then writes it in **one local transaction** through the timeline's building blocks (notes and events get their document and one `note_update` from `noteDocFromText`; provider links by `entryProviderId`). It returns the ids in order, or `{ ok: false, index, error, issues }`; a refused action leaves nothing.
- **Preview wording** (`actionPreview`, `whenText`) is in `@caretook/data/schema` (`assistant/quickEntryPreview.ts`; the web path re-exports it), shared with the connector's write tools.
- **The box** (`components/quick-entry/`, `QuickEntryBox` via its index; `useQuickEntry` owns state, `useQuickEntryData` reads medications and providers live, `quickEntryCards.ts` the pure card rules):
  - A growing textarea; Enter saves, Shift+Enter adds a line. A card per part with alternatives as chips ("Note instead"), Edit and Remove. Save writes every card and says "Saved 3 entries" (polite status); the cards are read out by a separate polite region after typing stops.
  - **Edit:** vitals and symptoms open the add sheet filled in, doses the Dose sheet (drafts in history state, `lib/assistant/quickEntryDraft.ts`; `EntryForm` and `DoseForm` take an optional `draft`). Notes and events have no sheet, so Edit saves that card and opens its entry page.
  - Name matches arrive a moment after mount (live queries); the box re-reads the line when they do, so tests wait for the expected kinds.
- **Suggestions:** nothing shows under an empty box. A Sparkles button inside the field's border (`QuickEntrySuggestButton`, only while the box is empty and some row has something) opens a `ui/Popover` (`QuickEntrySuggestions`): the due pass (below), "Usual around now" (`lib/assistant/quickEntryPredictions.ts`, `usualAtHour`: ±60 min of now in the recipient's zone on ≥ 3 of the last 14 days, today excluded), then "Your recent lines" (`lib/assistant/recentLines.ts`); a chip fills the box and closes it. While typing, "Matching names" (`QuickEntryCompletions`; `lib/assistant/quickEntryCompletion.ts`, `completeName`: medications then providers, by word prefix, titles skipped) floats under the field on `SURFACE` and never moves the layout; Escape or leaving the field hides it. No help ? or examples: a static placeholder (`QUICK_ENTRY_PLACEHOLDER`, `quickEntryCopy.ts`), and the full rules are the box's screen-reader description (`QUICK_ENTRY_RULES`). **A chip only fills the box; nothing saves until Save.**
- **Recent lines** are the last 8 distinct saved lines per user and group, in localStorage (`caretook:recentLines:<userId>:<groupId>`, every access in try/catch), recorded when Save succeeds as `recentLineFor(line, parsed)` gives it (nothing for notes and events, a vital's keys only: "bp hr "; stored lines are reduced the same way when read), cleared by `wipeDevice()` at sign-out (`session-end.mjs` asserts it).
- **Tests:** the box, cards, runner and suggestions are component tests (`timeline/timelineQuickEntry.browser.test.tsx`, `timelineQuickEntrySuggestions.browser.test.tsx`); there is no assistant browser check.
- **Passes** (slice 7): `givePass` (`{ passId, occurredAt }`, kind dose) logs a pass as Given all does. The parser reads "gave evening meds", "evening meds given", "gave meds" / "gave all" with `context.passes` (`QuickEntryPass`): the longest pass name wins; "gave meds" picks a pass with something left, then the one nearest a time phrase, else due first, then nearest by the clock (up to 3 alternatives); `open: 0` blocks ("Nothing is left to give in X today."). The runner's `givePass` plans from `duePasses` and `givenAllWrites` (open slots only, one round) inside the same transaction, and refuses a gone pass, a pass with no medications, or nothing left. Two `givePass` actions for one pass in a batch aren't deduplicated.
- **Tasks** (tasks PRD): `addTask` (`{ title, assigneeId?, dueOn?, dueTime?, providerId?, medicationId?, eventId? }`, a time only with a day) is only ever asked for, by a `t:`, `task:`, `todo:` (or `todo` alone) or `to-do:` prefix. The parser matches "for Sam" or "@Sam" against `context.members` and reads a due day forward ("Friday" is the next one). The runner writes it through `plannedTask` (`lib/tasks/tasks.sync.ts`) in the same transaction, and `removeEntries` (Undo) removes tasks too. The Saved line counts both ("Saved 2 entries and 1 task"). A task card's Edit opens `tasks/new` with `title`, `assigneeId`, `dueOn` and `dueTime` prefilled. See [tasks](tasks.md).
- **Open after save:** a line that saved exactly one note or event opens its entry page (`openAfterSave`, pure; a push, so Back returns to the timeline). Its Undo goes with the box; the page has Delete.
- **The runner's result** is `{ ids, byAction }`: every entry written (a pass writes one per medication) and each action's entries. **Undo after Save** uses the shared offer (`lib/medications/passUndo.ts`, 10 s; offers carry `entryIds` and a `place`): "Saved 3 entries · Undo" on the box's line, and Undo soft-deletes the whole batch through `removeEntries(db, ids)`; `[data-quick-status]` holds only errors.
- **The due pass** is the popover's first row ("Give evening meds (4)", one tap is Given all with Undo and closes it; `useQuickEntryPasses` over `useDueDoses` and `duePasses`), and the button reads "Suggestions, a pass is due" with a dot; not in simple mode (`passChips={false}`), where Upcoming offers it. Pass names complete while typing (after medications, before providers). A pass card reads "Evening medications · Given all · 4 medications"; Edit opens the Dose sheet on that pass.
