# Security headers

The security headers area's rules and decisions, moved out of AGENTS.md (whose core rules still apply). An orchestrator folds a landing's lasting decisions for this area in here.

- One builder, `app/.server/securityHeaders.ts` (tested), applied in four places: documents and `.data` requests in `entry.server.tsx` (a fresh 128-bit nonce per request, passed to `ServerRouter`, React's stream and `CspContext` in `lib/security-headers/csp.ts`); web-only resource routes through the pathless `web` layout route's `middleware` (`routes/web/route.ts`; root can't hold middleware in SPA mode); and files the host serves itself through `apps/web/vercel.json` (`HOST_HEADERS`, kept equal by a test; `serve.sh --built` preloads `scripts/project/host-headers.mjs` to do the same for check builds).
- **The CSP:** `default-src 'self'`; `script-src 'self'` + the hash of `THEME_SCRIPT` (computed at start) + the nonce + `'wasm-unsafe-eval'` (PowerSync's SQLite); `style-src 'self' 'unsafe-inline'` (React Aria, Tiptap and Vite write styles); `img-src 'self' data: blob:` (avatars on another host need adding); `connect-src 'self'` + the PowerSync origin + `VITE_API_ORIGIN` (+ dev websockets); `worker-src 'self' blob:`; `object-src 'none'`; `base-uri`, `form-action 'self'` (so `/connect`'s redirect back to an assistant needs JS: a native post's cross-origin 302 is blocked); `frame-ancestors 'none'`. Every document also carries it as a `<meta http-equiv>` (without `frame-ancestors`), which is what protects prerendered pages and the native SPA. `root.tsx` uses `nonce=""` on the client and `<Links nonce="" />` (browsers hide nonce values).
- **Fonts** are same-origin files (the vendored typeface, [app-shell](app-shell.md)) under `font-src 'self' data:`: never a font CDN, so no CSP change.
- Also: HSTS (`NODE_ENV=production`), `X-Frame-Options: DENY`, `Referrer-Policy: no-referrer` (keeps `/invite/:token` and `/join/:code` private), `nosniff`, `Permissions-Policy` off for camera, microphone, geolocation and payment.
- **The check fixtures (`fixtures.mjs`'s `device`) fail a check on any CSP violation.** A new inline script, third-party origin or `style` attribute outside React needs the policy changed, not worked around.
- **Staging:** `X-Robots-Tag: noindex` on every response (the builder's `noindex` option, from runtime or build `APP_ENV=staging`), and on host files through `vercel.json`'s second block, conditioned on the `staging.caretook.com` host. `HOST_HEADERS` and `host-headers.mjs` use only the `/(.*)` block without `has`.
- **`/api/webhooks/resend`** has no CSRF or Origin check (the Svix signature is the check); the CSP needed nothing. The calendar feed (`/api/calendar/:token.ics`, `private`) and Google's Connect and callback (`/api/google/*`) are web layout middleware resource routes with no CSP change. Connect is a plain GET link, not a form post, so `form-action 'self'` doesn't block its redirect to Google.
- ✅ Checked on staging (B-33): a function's own headers win over `vercel.json`'s (one CSP, the full policy, on `/app` and `/sign-in`); host-served and prerendered files (`/`, `/features/`) get `vercel.json`'s block plus the `<meta>` CSP; `vercel build` from the repo root follows the Root Directory `apps/web`.
- **The service worker** (`/sw.js`, [app-shell](app-shell.md)) needs no CSP change (`worker-src 'self' blob:`). The shell it caches keeps its `Content-Security-Policy` header and the `<meta>` with the same nonce, reused on that device only; a CSP change reaches it with the next build's worker. `/sw.js` returns 200 on staging (checked, B-33).
