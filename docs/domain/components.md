# Components (`apps/web/app/components/`)

The components area's rules and decisions. An orchestrator folds a landing's lasting decisions for this area in here.

## Layout

- **`ui/`** holds primitives that import nothing from feature folders: `Menu` (with `SEPARATOR`), `Sheet`, `Popover`, `ConfirmDialog`, `Field`, `ChipGroup`, `ChipList`, `UserAvatar`, `AvatarStack`, `IconButton`, `ChoiceGroup`, `BackLink`, `ComboBox`, `Highlight`, `Toast` (`role="status"`, above the tab bar), `ViaTag` ("via X", `data-via`; nothing when empty). **Only `ui/` imports `react-aria-components`.**
  - `ui/tooltip/` and `ui/date/` (`DateTimeField`, which clamps a month or year step onto a shorter month to its last day) have their own indexes, so the date picker (~42 KB) and tooltip stay off pages that don't use them.
  - `ui/plain` is the light entry for pages that must not load React Aria (below); it exports `ChoiceGroup` (`/connect`).
  - `ComboBox` takes data in (`options`, a controlled `inputValue`, `onSelect`, an optional `onCreate` last option); the caller filters.
- **Feature folders:** `brand/`, `contact/`, `entry/` (shared by the timeline and Upcoming), `groups/`, `medications/`, `notes/` (the Tiptap editor, kept apart so it never reaches the timeline through an index), `providers/`, `quick-entry/`, `schedule/`, `settings/`, `shell/`, `tasks/`, `visitPrep/`.
- **Import through each folder's `index.ts`**, never a file inside it, and a route never imports another route's folder. An index brings its folder's whole chunk, so keep heavy pieces (the editor, the date picker) out of indexes that light routes use.
- **When a component moves:** it lives beside its route until a second route needs it, then moves to the matching feature folder (or `ui/` if it's feature-free) and is exported from that index.
- `components/tasks/` holds what the task list (`routes/app/groups/tasks/`) and the task page (`routes/app/groups/task/`) share: `TaskTick`, `useTaskTick`, `TaskUndoStatus`, `LinkedTasks`, `useLinkedTasks`.

## Rules

- **Callers pass data, labels and callbacks**, never React Aria parts or render props, and at most a `className` for the outer element (`Field` and `ChoiceGroup` callers also style the control). Primitives own ARIA naming, press handling, focus on open and return on close, and the layers (sheets and modals `z-50`, tab bar `z-40`, sticky headers `z-10`). Styling is daisyUI classes and tokens only. Menus and popovers share one surface class (`ui/styles.ts`).
- **Every menu is `ui/Menu`**: callers pass `label`, `menuLabel`, `items` (`menuModel.ts`, pure). An item has a label, description, icon, danger tone, disabled, and `onAction` or `href` (links navigate through React Router; a link's optional `state` goes through `linkOptions`). Sections can have a title, a non-interactive `header`, and `selection` (`menuitemradio`).
- **Every labelled form control is a `Field`**; **every one-of-a-few choice is a `ChoiceGroup`** (native radios in a named `radiogroup`); every icon-only button is an `IconButton` (it requires a `label`, which is its name and tooltip; with `to` it's a link that looks the same); a page's back link is a `BackLink`. **Add a primitive only for a pattern the app repeats.**
- **One entry actions menu** (`entry/EntryActions`, items from the pure `entryActionItems(kind, { canEdit })`): Edit then Delete for symptoms and vitals, Delete only for notes and events, on rows, cards and the entry page alike.
- **Primitive contracts:**
  - `Sheet` is full screen below `sm` and a centred modal from `sm`, above the tab bar, and returns focus to its opener.
  - `ConfirmDialog` waits for an open menu to close before `showModal()` (so focus returns to the ⋯ button), and Escape closes only the dialog.
  - `Field` gives its control the `id`, `aria-invalid` and `aria-describedby`, and shows an optional `warning` line (never `aria-invalid`) while there's no error. `Field` ids come from `useId`, so browser checks select inputs by `input[name=…]`.
  - `ChipGroup` link chips are a `nav` with `aria-current="true"`; button chips are a `ul`, with `aria-pressed` when they toggle.
  - `Highlight` renders a search's matches as `<mark>` (`MARK_CLASS`, `bg-warning text-warning-content`, contrast 5.2:1 in both themes).
- **Hooks own state; components own markup.** Hooks return data and callbacks, never JSX (`useTimelineData`, `useLiveEntry`, `useEntryFormSave`, `useProviderNotes`). Live data comes through hooks over `useLiveQuery`; components don't call `getSync()` while rendering. Pure logic goes in plain modules beside its feature, with `web:unit` tests.
- **Size guideline** (not enforced by lint): a route module about 100 lines (loader, action, `shouldRevalidate`, `meta`, and a short composing component); a component about 150. Split a large route into a `load<Thing>.ts`, a `use<Thing>` hook and region components beside it. (`ProviderForm` is the known exception.)
- **Settings pages** use `SettingsPage` (heading, plus `offlineNotice` for online-only writes), `SettingsCard` (a titled `section` with `data-section`) and `SaveRow`.
- **Light pages** (sign-in, the account forms, the marketing site) import `Field`, `FieldControl` and `IconButton` from `~/components/ui/plain`, never `~/components/ui` (whose chunk carries React Aria: the marketing layout went from 143 to 380 KB). `PROVIDER_SHEET_STATE` lives in `lib/providers/providerSheetLink.ts`.

## Component tests

- **The project** `web:components` (in `pnpm check`): Vitest browser mode, headless Chromium through `@vitest/browser-playwright` 5.1.0, `playwright` 1.65.1 and `vitest-browser-react` 2.3.0. It loads apps/web's Vite config (React Router's plugin is off under `VITEST`). Files are `*.browser.test.tsx` beside their subject. Install Chromium once per machine with `pnpm test:components:install`; run `pnpm test:components`, or `--changed <base>` while building. Defaults: 420×900, America/Los_Angeles, en-US. Its globalSetup (`apps/web/test/browserLease.ts`) holds the machine-wide `browser` lease.
- **The primitives' behaviour** is tested in `components/ui/primitives.browser.test.tsx` and as the screens use them in `components/ui/inScreens.browser.test.tsx`; settings in the settings route folders' `*.browser.test.tsx`. Component tests need no browser checks, nor does `apps/web/test/` (rules in `check-areas.d/`).
- **The test device** (`apps/web/test/`) is the only way tests get data. `renderWithDevice({ route: { path, module } | element, url, role, fixtures: [fx.note({ text }), …], width, theme, frame, api })` renders real route modules on a local-only PowerSync database that never connects (`frame: true` adds the `/app` header and tab bar). The device is offline unless `api` answers oRPC calls; `connected: true` or `device.connect(bool)` sets the connected status for online-only controls. It returns the screen and the database, plus `location()`, `sync()` (another device's change arriving), `unsync()`, `queued()` (uploads) and `query()`. `renderInRouter` is for primitives. The seam is `installTestDatabase` in `lib/sync/index.ts`, which throws outside test mode.
- **Settle:** `device.settle()` waits until every live query whose tables changed has rerun and the DOM has stayed still for 2 frames (`settle(db, { timeout })` in `test/database.ts`). Call it after every stored write, `sync()` or `unsync()` before reading the screen. `renderWithDevice` settles before it returns (`settle: false` for a first-paint test). It covers database-driven updates only, not lazy imports, timers or scroll anchoring; after a click that saves, keep polling (`expect.element`).
- **Server-loaded and auth routes:** a `DeviceRoute` with a server `loader` or `action` takes `loaderData` and `actionResult` (a value, or a function); without one it throws, naming what to give. Paths outside `/app` mount beside it. `~/.server/*` resolves to throwing stubs in `apps/web/test/server/` (add one per module a route imports). An `api` key starting with `/` answers that path with plain JSON, for Better Auth calls.
- **Fixtures:** the `fx` builders cover groups, people, every entry kind, documents, providers, links, medications, passes and periods (tasks through `task({ … })`), with fictional defaults (`TEST_USER`, `TEST_GROUP`, `TEST_RECIPIENT`); overrides are camelCase and checked against the device schema. Shared worlds sit beside their routes (`timelineWorld.tsx`, `periodWorld.tsx`, `upcomingWorld.tsx` with `fixClock()`, `profileWorld.tsx`, `medicationWorld.tsx`, `providerWorld.tsx`). Helpers in `apps/web/test/`: `refusal(code)` and `apiCalls()` (`api.ts`), `commands.colorScheme(...)`, `commands.media("print" | "screen" | null)` (`commands.ts`; reset after the test).
- **Parallelism:** `web:components` runs with `maxWorkers: 4` and `sequence.groupOrder: 1`, so it runs after the other projects (9 workers timed out under load).
- **Gotchas:**
  - Test Back with a `BackProbe` that captures `navigate(-1)`; under `createRoutesStub` never call `history.back()`.
  - On a route whose `clientLoader` calls the `api`, or before the first rows, wait on an element, since settle covers the database only: `await found(() => X()?.querySelector(…))` (`test/found.ts`, 5 s, names what it waited for) before acting on it, never `X()!`; `expect.poll` for values.
  - `getByText("…")` matches whole text. A closed native `<dialog>` drops out of `getByRole` (assert `dialog.open`; poll `dialog[open]` after a `ConfirmDialog`).
  - Click a row's text with `userEvent.click(el, { force: true })` (its stretched link covers it). Pass a locator to `userEvent.hover`; a tooltip shows on hover only after the next pointer press.
  - A menu's accessible name comes from its trigger. A `DeviceRoute` child that reuses its parent's path needs an explicit `id`.
  - After a dependency change the first run can fail every file while Vite re-optimizes ("Vite unexpectedly reloaded a test"): rerun once.
