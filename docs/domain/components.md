# Components (`apps/web/app/components/`)

## Layout

- **`ui/`** holds the primitives, the only importers of `react-aria-components`; what's there, which to use and their contracts are in [ui-kit](ui-kit.md). **The guard** (`caretook/no-kit-classes` and a restricted import; lists in `scripts/eslint/kit-guard.mjs`) fails lint on React Aria or a raw `btn`, `card`, `badge` or `alert` class outside `ui/`, marketing, printed sheets and `/dev/ui`. `KIT_CLASSES_NOT_SWEPT` holds only `ui-kit-5`'s group.
- **Feature folders:** `brand/`, `contact/`, `entry/` (shared by the timeline and the Planner: `RepeatMark`, `SeriesScopeDialog`, `RemindMeSheet`), `groups/`, `medications/`, `notes/` (the Tiptap editor), `providers/` (contact pieces and the provider pickers, [providers](providers.md)), `quick-entry/`, `repeat/` (`RepeatField`, `RepeatSheet`, `SeriesEditSheet`), `schedule/`, `settings/`, `shell/`, `todos/`, `visitPrep/`.
- **Import through each folder's `index.ts`**, never a file inside it; a route never imports another route's folder. An index brings its whole chunk: keep heavy pieces out of indexes light routes use.
- **A component lives beside its route** until a second route needs it (then a feature folder or `ui/`).
- `components/todos/`: what todo screens share (`TodoTick`, `useTodoTick`, `TodoUndoStatus`, `LinkedTodos`, `useLinkedTodos`, `TodoTreeMarks`; `TodoRow`, looks `list` and `context`; `TodoQuickAdd`, `compact` or `full`).

## Rules

- **One look, one way, everywhere** (the user's rule): one shared display per record kind and one shared control per job (tags, quick add, ticking), varied slightly per place. Reuse it; an exception needs a reason in the plan.
- **Callers pass data, labels and callbacks** (no React Aria parts or render props), at most an outer `className` (`Field` and `ChoiceGroup` callers also style the control). Primitives own ARIA naming, presses, focus and the layers (sheets and modals `z-50`, tab bar `z-40`, sticky headers `z-10`). Styling is daisyUI classes and tokens only. **Surfaces:** `base-200` is the page (`body`), `base-100` a card on it, `base-300` a card's border, its dividers and a quiet fill (dark: 23%, 30%, 40%, hue 270). Every `input`, `select` and `textarea` takes `--color-field` (light 94%, dark 18%, white in print), quick entry's box included; the notes editor's frame and toolbar take it by hand; ghost inputs stay transparent, disabled ones `base-200` with a `base-300` edge, placeholders at `text-faint`; overlays share `SURFACE`, tool buttons `TOOL_CIRCLE` (`ui/styles.ts`).
- **Every menu is `ui/Menu`**: callers pass `label`, `menuLabel` (the menu's own name), `items` (`menuModel.ts`, pure); the trigger takes `title` and `data-*`. An item has a label, description, icon, danger tone, disabled, and `onAction` or `href` (a link's `state` goes through `linkOptions`). Sections can have a title, a non-interactive `header`, and `selection` (`menuitemradio`). A group (`MenuGroup`) expands its items in place, indented: `aria-expanded`, keeps the menu open, closed on each open; no flyouts.
- **Every list's filters are `FilterMenu`** (a `TOOL_CIRCLE` button with a count, a `Menu` of single-choice sections, Clear filters) **and `FilterMenuChips`**, in `ui/SearchFilterBar` on lists (one ✕ chip per filter on, then extra chips), both `{ label, sections, clear, chips? }`. The caller builds every search; a section on its `defaultId` counts for nothing (`filterModel.ts`); `?q=` is never a filter.
- **Use the kit** ([ui-kit](ui-kit.md#which-to-use)): a control is a `Field`, `CheckField` or `ToggleField`, a button a `Button` or `IconButton`, a message a `Message` or `Notice`, a card a `Card`, a list box a `List`.
- **Toasts** (`toast()`): done actions, Undo, background news, one-time nudges; never errors to fix, medical facts, an action's only path or the only sign of unsynced changes.
- **One entry actions menu** (`entry/EntryActions`, pure `entryActionItems(kind, { canEdit })`): Edit then Delete for symptoms and vitals, Delete only for notes and events.
- **Hooks own state (data and callbacks, never JSX); components own markup.** Live data: hooks over `useLiveQuery`, never `getSync()` while rendering. Pure logic: plain modules, `web:unit` tests. Cache `Intl` formatters per zone (B-793).
- **A main page's add control is the header's `+`** (`PageHeader` `add`, writers only); other actions go left of it.
- **Motion:** `--motion-fast` (120 ms), `--motion` (240 ms) and one ease-out curve, at the end of `app.css`. Every animating rule is under `prefers-reduced-motion: no-preference` (reduce also drops `.btn`'s transition); buttons fade on hover and press to 0.97, link rows fade their fill; no bounce, no scale above 1. Overlays fade on `--motion`: menus and popovers (`motion-overlay`, a transition, never keyframes: React Aria waits for it on exit), `.modal`s, backdrops, toasts, `Sheet`, `Collapse`, `Chevron`; tooltips don't. Tests emulate reduced motion per file (`cdp()`, reset after).
- **Size:** a route ~100 lines, a component 150 (split out a loader, a hook, regions).
- **Settings pages:** `SettingsPage` (heading; `offlineNotice`, a `Notice`), `SettingsCard` (a `Card`, `data-section`), `SettingsFrame` (`Page width="wide"`), `SaveRow` (`FormFooter align="start"` with `Message`s).
- **Light pages** (sign-in, account forms, `/connect`, marketing) import `~/components/ui/plain`, never `~/components/ui` ([ui-kit](ui-kit.md)).

## Component tests

- **The project** `web:components` (in `pnpm check`): Vitest browser mode, headless Chromium. Files: `*.browser.test.tsx` beside their subject; `pnpm test:components` (`--changed <base>`; once: `test:components:install`). Defaults: 420×900, America/Los_Angeles, en-US, and one test clock: 2027-06-09 (a Wednesday) at 12:00, set before imports, reset before each test, ticking (`test/setup.ts`; `VITE_TEST_CLOCK=HH:MM` sets the time). A world's fixed clock stays on that day (fixtures read it at load). globalSetup holds the `browser` lease. CI: three shards balanced by `scripts/ci/component-durations.json` (`node scripts/ci/shards.mjs refresh <run-id>`), on a Linux Chromium with no `BarcodeDetector`, `maxWorkers: 4`, after the rest.
- **A second zone:** `web:components:ny` runs the files importing `test/zone.ts` (`NY_INCLUDE`, held by `zones.test.mjs`) on a New York device (recipients in Los Angeles); release's `zone-components-N` run every file there; node projects pin `TZ`. `test/zone.ts`: worlds build the recipient's day with `recipientTime`, viewer-zone expectations come from `deviceTime`, and `inSecondZone("B-n")` is the only New York skip (a `fixes-bug` item, not the quarantine).
- **Primitives** are tested in `ui/primitives.browser.test.tsx` (new ones in their own file beside them) and as screens use them in `ui/inScreens.browser.test.tsx` (its probe block first). Tests of the frame, the harness and the primitives mount `PROBE` (`apps/web/test/probe.tsx`: a group line, a live entry list, a writer-only Add, a menu opening a `Sheet` or `ConfirmDialog`), never a timeline world. They and `apps/web/test/` need no browser checks.
- **The test device** (`apps/web/test/`) is tests' only data source. `renderWithDevice({ route: { path, module } | element, url, role, fixtures: [fx.note({ text }), …], width, theme, frame, api })` renders real route modules on a local-only PowerSync database that never connects (`frame: true` adds the `/app` header and tab bar). Offline unless `api` answers oRPC calls; `connected: true` or `device.connect(bool)` for online-only controls. It returns the screen, the database, `location()`, `sync()` (another device's change), `unsync()`, `queued()` and `query()`. `renderInRouter`: primitives. The seam is `installTestDatabase` (`lib/sync/index.ts`; test mode only).
- **Settle:** `device.settle()` waits until every live query whose tables changed has rerun and the DOM has stayed still for 2 frames (`settle(db, { timeout })` in `test/database.ts`). Call it after each write, `sync()` or `unsync()`, before reading. `renderWithDevice` waits for the first load and mount (a stuck load stops at `WAIT_TIMEOUT`), then settles (`settle: false` for a first-paint test). Database only (not lazy imports, timers or scroll): after a click that saves, keep polling.
- **Server-loaded and auth routes:** a `DeviceRoute` with a server `loader` or `action` takes `loaderData` and `actionResult` (a value, or a function); without one it throws, naming what to give. Paths outside `/app` mount beside it. `~/.server/*` resolves to throwing stubs in `apps/web/test/server/` (one per module). An `api` key starting with `/` answers that path with plain JSON, for Better Auth calls.
- **Fixtures:** the `fx` builders cover groups, people, every entry kind, documents, providers, links, medications, passes and periods (todos through `todo({ … })`), with fictional defaults (`TEST_USER`…); overrides are checked against the device schema. Shared worlds (`*World.tsx`) sit beside their routes. Helpers in `apps/web/test/`: `refusal(code)` and `apiCalls()` (`api.ts`), `commands.colorScheme(...)`, `commands.media("print" | "screen" | null)` (`commands.ts`; reset after the test).
- **Gotchas:**
  - Test Back with a `BackProbe` capturing `navigate(-1)`, never `history.back()` under `createRoutesStub`; pending navigation needs one with loaders.
  - On a route whose `clientLoader` calls the `api`, or before the first rows, wait on an element, since settle covers the database only: `await found(() => X()?.querySelector(…))` (`test/found.ts`: `found`, `waitUntil`, `stopsMoving`, `fixClock`, one 5 s `WAIT_TIMEOUT`; no copies) before acting on it, never `X()!`; `expect.poll` for values. For a `data-` hook, `getByCss(sel, { within? })` (`test/locators.ts`, also `page.getByCss`) is a strict, retrying locator.
  - **Lint (`caretook/*`, `scripts/eslint/plugin.mjs`; errors):** `no-call-timeout`, `no-non-null-user-event`, `no-non-null-in-expect`, `no-fixed-sleep`, on `*.browser.test.tsx`, `test/` and `*World.tsx`. A real exception: `// eslint-disable-next-line caretook/<rule> -- <reason>`.
  - A closed native `<dialog>` drops out of `getByRole` (assert `dialog.open`; poll `dialog[open]` after a `ConfirmDialog`). A menu popover is a `dialog`: find sheets by name.
  - Click a row's text with `{ force: true }` (a stretched link is over it). Pass a locator to `userEvent.hover`; a tooltip shows on hover only after the next pointer press.
  - A `DeviceRoute` child on its parent's path needs an `id`.
