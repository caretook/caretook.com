# Components (`apps/web/app/components/`)

## Layout

- **`ui/`** holds the primitives, the only importers of `react-aria-components`; their contracts and which to use are in [ui-kit](ui-kit.md). **The guard** (`caretook/no-kit-classes` and a restricted import) fails lint on React Aria or a raw `btn`, `card`, `badge` or `alert` class outside `ui/`, marketing, printed sheets, `/dev/ui`.
- **Feature folders:** `brand/`, `contact/`, `entry/` (`RepeatMark`, `SeriesScopeDialog`, `RemindMeSheet`), `groups/`, `medications/`, `notes/`, `providers/` ([providers](providers.md)), `quick-entry/`, `repeat/` (`RepeatField`, `RepeatSheet`, `SeriesEditSheet`), `schedule/`, `settings/`, `shell/`, `todos/`, `visitPrep/`.
- **Import through a folder's `index.ts`**, never a file inside it; a route never imports another route's folder. An index brings its whole chunk: keep heavy pieces out of indexes light routes use.
- **A component lives beside its route** until a second route needs it (then a feature folder or `ui/`).
- `components/todos/` (`TodoTick`, `useTodoTick`, `TodoUndoStatus`, `LinkedTodos`, `useLinkedTodos`, `TodoTreeMarks`; `TodoRow` (looks `list`, `card`, `easy`, `context`), `TodoTree` (`adding`: quick add per row), `TodoQuickAdd` (a parent, a `link`, or both), `LinkToBox`).

## Rules

- **One look, one way, everywhere:** one shared display per record kind, one shared control per job (tags, quick add, ticking), varied slightly (the Planner's event card is `entry/UpcomingEntryCard`). An exception needs a reason in the plan.
  - **Shared displays** (shared-displays): entries `entry/TimelineEntryRow` (`look`; `elsewhere` off the timeline: search, a provider's or todo's links; `trailing`: a link's Remove), medications `medications/MedicationCard` with `MedicationIcon`, providers `providers/ProviderCard` (`look: "full" | "condensed"`, `contact` and `actions` slots; `ProviderListItem` is the directory's and setup page's thin caller), todos `todos/TodoRow` (`search` marks the title, `footer`). The cards share optional `title` (a node), `open` (omitted: its page; a callback: a button, the easy roles' sheets; `null`: plain text), `removed` (greyed "(removed)", no link or actions; `trailing` kept), `label` (a quiet line above the name) and `trailing` (above the stretched link). Pickers use their icons. Every display passes `data-*` through to its row and takes `tagsReadOnly`; tags come from one `useGroupRecordTags` per list. Exceptions: `MedicationHistory`, quick-entry drafts, the Today card and easy Now/Next, the easy result sheet, an entry's With chips.
- **Callers pass data, labels and callbacks** (no React Aria parts or render props) and at most an outer `className` (`Field`, `ChoiceGroup`: the control's too). Primitives own ARIA naming, presses, focus, layers (sheets, modals `z-50`; tab bar `z-40`; sticky headers `z-10`). daisyUI classes and tokens only. **Surfaces:** `base-200` is the page (`body`), `base-100` a card on it, `base-300` a card's border, its dividers and a quiet fill (dark: 23%, 30%, 40%). Every `input`, `select` and `textarea` takes `--color-field` (light 94%, dark 18%, white in print), as do the notes editor's frame and toolbar by hand; ghost inputs stay transparent, disabled ones `base-200` edged `base-300`, placeholders `text-faint`; overlays share `SURFACE`, tool buttons `TOOL_CIRCLE`.
- **Every menu is `ui/Menu`**: callers pass `label`, `menuLabel` (the menu's own name), `items` (pure `menuModel.ts`); the trigger takes `title`, `data-*`. An item has a label, description, icon, danger tone, disabled, and `onAction` or `href` (a link's `state` goes through `linkOptions`). Sections take a title, a non-interactive `header`, `selection` (`menuitemradio`). A group (`MenuGroup`) expands in place, indented (`aria-expanded`, menu stays open, closed on each open), no flyouts.
- **Every list's filters are `FilterMenu`** (a `TOOL_CIRCLE` button with a count, single-choice sections, Clear filters) **and `FilterMenuChips`**, in `ui/SearchFilterBar` on lists (a ✕ chip per active filter, then extras), both `{ label, sections, clear, chips? }`. Callers build every search; a section on its `defaultId` counts nothing (`filterModel.ts`); `?q=` is no filter.
- **Use the kit** ([ui-kit](ui-kit.md#which-to-use)): `Field`, `CheckField` or `ToggleField` for a control, `Button` or `IconButton`, `Message` or `Notice`, `Card`, `List` for a list box.
- **Toasts** (`toast()`): done actions, Undo, background news, one-time nudges; never errors to fix, medical facts, an action's only path or the only sign of unsynced changes.
- **One entry actions menu** (`entry/EntryActions`, pure `entryActionItems(kind, { canEdit })`): Edit, Delete for symptoms and vitals; Delete only for notes and events.
- **Hooks own state (data, callbacks, never JSX); components own markup.** Live data: hooks over `useLiveQuery`, never `getSync()` in render. Pure logic: plain modules (`web:unit`). Cache `Intl` formatters per zone.
- **A main page's add control is the header's `+`** (`PageHeader` `add`, writers only); others go left of it.
- **Motion:** `--motion-fast` (120 ms), `--motion` (240 ms) and one ease-out curve. Every animating rule sits under `prefers-reduced-motion: no-preference` (reduce also drops `.btn`'s transition); buttons fade on hover and press to 0.97, link rows fade their fill; no bounce, no scale above 1. Overlays fade on `--motion`: menus and popovers (`motion-overlay`, a transition, never keyframes: React Aria waits for it on exit), `.modal`s, backdrops, toasts, `Sheet`, `Collapse`, `Chevron`; tooltips don't. Tests emulate reduced motion per file (`cdp()`).
- **Size:** route ~100 lines, component 150 (split out a loader, hook, regions).
- **Settings pages:** `SettingsPage` (heading, `offlineNotice`), `SettingsCard` (a `Card`), `SettingsFrame`, `SaveRow`.
- **Light pages** (sign-in, account forms, `/connect`, marketing) import `~/components/ui/plain`, not `~/components/ui` ([ui-kit](ui-kit.md)).

## Component tests

- **Project** `web:components`: Vitest browser mode, Chromium. Files `*.browser.test.tsx` sit beside their subject; `pnpm test:components` (`--changed <base>`; first `test:components:install`). Defaults: 420×900, America/Los_Angeles, en-US, one ticking test clock (2027-06-09 12:00, set before imports, reset before each test) (`test/setup.ts`; `VITE_TEST_CLOCK=HH:MM`). A world's fixed clock stays on that day. CI: three shards (`scripts/ci/component-durations.json`), on a Linux Chromium without `BarcodeDetector`.
- **A second zone:** `web:components:ny` runs files importing `test/zone.ts` on a New York device; release's `zone-components-N` runs every file there; node projects pin `TZ`. `test/zone.ts`: worlds build the recipient's day with `recipientTime`, viewer-zone expectations from `deviceTime`, and `inSecondZone("B-n")` is the only New York skip.
- **Primitives** are tested in `ui/primitives.browser.test.tsx` and as screens use them in `ui/inScreens.browser.test.tsx`. Tests of the frame, harness and primitives mount `PROBE` (`apps/web/test/probe.tsx`: a group line, a live entry list, a writer-only Add, a menu opening a `Sheet` or `ConfirmDialog`), never a timeline world.
- **The test device** (`apps/web/test/`) is tests' only data source. `renderWithDevice({ route: { path, module } | element, url, role, fixtures: [fx.note({ text }), …], width, theme, frame, api })` renders real route modules on a local PowerSync database that never connects (`frame: true` adds the `/app` header and tab bar). Offline unless `api` answers oRPC calls; `connected: true` or `device.connect(bool)` for online-only controls. It returns the screen, the database, `location()`, `sync()` (another device's change), `unsync()`, `queued()`, `query()`. `renderInRouter` is for primitives.
- **Settle:** `device.settle()` waits until every live query on changed tables has rerun and the DOM is still for 2 frames. Call it after each write, `sync()` or `unsync()`, before reading. `renderWithDevice` waits for the first load and mount, then settles (`settle: false` for a first-paint test). It covers the database only (not lazy imports, timers or scroll): after a click that saves, keep polling.
- **Server-loaded and auth routes:** a `DeviceRoute` with a server `loader` or `action` takes `loaderData` and `actionResult` (a value or function); without one it throws. `~/.server/*` resolves to throwing stubs (`apps/web/test/server/`). An `api` key starting with `/` answers that path with plain JSON, for Better Auth calls.
- **Fixtures:** the `fx` builders cover groups, people, every entry kind, documents, providers, links, medications, passes, periods, with fictional defaults and overrides checked against the device schema. Shared worlds (`*World.tsx`) sit beside their routes. Helpers: `refusal(code)`, `apiCalls()`, `commands.colorScheme(...)`, `commands.media("print" | "screen" | null)` (reset after the test).
- **Gotchas:**
  - Test Back with a `BackProbe` capturing `navigate(-1)`, not `history.back()` under `createRoutesStub`; pending navigation needs a stub with loaders.
  - On a route whose `clientLoader` calls the `api`, or before the first rows, wait on an element, since settle covers the database only: `await found(() => X()?.querySelector(…))` (`test/found.ts`: `found`, `waitUntil`, `stopsMoving`, `fixClock`, one 5 s `WAIT_TIMEOUT`) before acting, never `X()!`; `expect.poll` for values. For a `data-` hook, `getByCss(sel, { within? })` (`test/locators.ts`) is a strict retrying locator.
  - **Lint (`caretook/*`, `scripts/eslint/plugin.mjs`):** `no-call-timeout`, `no-fixed-sleep`, `no-non-null-user-event`, `no-non-null-in-expect`, on `*.browser.test.tsx`, `test/` and `*World.tsx`. Exception: `// eslint-disable-next-line caretook/<rule> -- <reason>`.
  - A closed native `<dialog>` drops out of `getByRole` (assert `dialog.open`; poll `dialog[open]` after a `ConfirmDialog`). A menu popover is a `dialog`: find sheets by name.
  - Click a row's text with `{ force: true }` (a stretched link is over it). Give `userEvent.hover` a locator; a tooltip shows only after the next pointer press.
  - A `DeviceRoute` child on its parent's path needs an `id`.
