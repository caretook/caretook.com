# Components (`apps/web/app/components/`)

The components area's rules and decisions. An orchestrator folds a landing's lasting decisions for this area in here.

## Layout

- **`ui/`** holds primitives that import nothing from feature folders: `Menu` (with `SEPARATOR`), `Sheet`, `Popover`, `PageHeader` (a page's `h1` and actions), `TabNav` (a page's linked tabs), `ConfirmDialog` (`useShowModal`, `confirmClassName`), `Field`, `ChipGroup`, `ChipList`, `UserAvatar`, `AvatarStack`, `IconButton`, `ChoiceGroup`, `BackLink`, `ComboBox`, `Highlight`, `Toast` (`role="status"`, above the tab bar), `ViaTag` ("via X", `data-via`; nothing when empty). **Only `ui/` imports `react-aria-components`.**
  - `ui/tooltip/` and `ui/date/` (`DateTimeField`, which clamps a month or year step to a shorter month's last day) have their own indexes, so the date picker (~42 KB) and tooltip stay off other pages.
  - `ui/plain`: the light entry for pages without React Aria (below), plus `ChoiceGroup` (`/connect`).
  - `ComboBox` takes `options`, a controlled `inputValue`, `onSelect`, optional `onCreate` (last) and `sections`; the caller filters.
- **Feature folders:** `brand/`, `contact/`, `entry/` (shared by the timeline and the Planner: `RepeatMark`, `SeriesScopeDialog`, `RemindMeSheet`), `groups/`, `medications/`, `notes/` (the Tiptap editor, kept apart from the timeline's indexes), `providers/` (contact pieces and the provider pickers, [providers](providers.md)), `quick-entry/`, `repeat/` (`RepeatField`, `RepeatSheet`, `SeriesEditSheet`), `schedule/`, `settings/`, `shell/`, `todos/`, `visitPrep/`.
- **Import through each folder's `index.ts`**, never a file inside it, and a route never imports another route's folder. An index brings its folder's whole chunk, so keep heavy pieces (the editor, the date picker) out of indexes that light routes use.
- **When a component moves:** it lives beside its route until a second route needs it, then moves to its feature folder (or `ui/`) and that index.
- `components/todos/` holds what the todo list (`routes/app/groups/todos/`) and the todo page (`routes/app/groups/todo/`) share: `TodoTick`, `useTodoTick`, `TodoUndoStatus`, `LinkedTodos`, `useLinkedTodos`.

## Rules

- **Callers pass data, labels and callbacks**, never React Aria parts or render props, and at most a `className` for the outer element (`Field` and `ChoiceGroup` callers also style the control). Primitives own ARIA naming, press handling, focus on open and return, and the layers (sheets and modals `z-50`, tab bar `z-40`, sticky headers `z-10`). Styling is daisyUI classes and tokens only. **Surfaces:** `base-200` is the page (`body`), `base-100` a card on it, `base-300` a card's border, its dividers and a quiet fill; `app.css` tunes the three bases in both themes (`daisyui/theme`) so cards stand apart. Menus, popovers and overlays share `SURFACE` (`ui/styles.ts`).
- **Every menu is `ui/Menu`**: callers pass `label`, `menuLabel`, `items` (`menuModel.ts`, pure). An item has a label, description, icon, danger tone, disabled, and `onAction` or `href` (links navigate through React Router; a link's optional `state` goes through `linkOptions`). Sections can have a title, a non-interactive `header`, and `selection` (`menuitemradio`). A group (`MenuGroup`) expands its items in place, indented: `aria-expanded`, keeps the menu open, closed on each open; no flyouts.
- **Every labelled form control is a `Field`**; **every one-of-a-few choice is a `ChoiceGroup`** (native radios in a named `radiogroup`; a controlled `value` may be null: none chosen yet); every icon-only button is an `IconButton` (requires a `label`: its name and tooltip; with `to` it's a look-alike link); a page's back link is a `BackLink`. **Add a primitive only for a repeated pattern.**
- **One entry actions menu** (`entry/EntryActions`, items from the pure `entryActionItems(kind, { canEdit })`): Edit then Delete for symptoms and vitals, Delete only for notes and events, on rows, cards and the entry page alike.
- **Primitive contracts:**
  - `Sheet` is full screen below `sm` and a centred modal from `sm`, above the tab bar, and returns focus to its opener.
  - `ConfirmDialog`/`useShowModal` wait for an open menu to close before `showModal()`; Escape closes only the dialog.
  - `Field` gives its control the `id`, `aria-invalid` and `aria-describedby`, and shows an optional `warning` line (never `aria-invalid`) while there's no error. `Field` ids come from `useId`, so browser checks select inputs by `input[name=…]`.
  - `ChipGroup` link chips are a `nav` with `aria-current="true"`; button chips are a `ul`, with `aria-pressed` when they toggle.
  - `TabNav` (`{ label, tabs: [{ label, to, match? }] }`): a `nav` of links, not a tablist. A tab claims its path and below (`match` replaces that); the first claimant gets `aria-current="page"` from the pending navigation. Prefetches on render; `tabs-box`, full width on phones.
  - `Highlight` renders a search's matches as `<mark>` (`MARK_CLASS`, `bg-warning text-warning-content`, 5.2:1 in both themes).
- **Hooks own state; components own markup.** Hooks return data and callbacks, never JSX (`useTimelineData`, `useLiveEntry`). Live data comes through hooks over `useLiveQuery`; components don't call `getSync()` while rendering. Pure logic goes in plain modules beside its feature, with `web:unit` tests.
- **Size guideline** (not enforced): a route about 100 lines, a component 150; split a large route into `load<Thing>.ts`, a `use<Thing>` hook and regions.
- **Settings pages** use `SettingsPage` (heading, plus `offlineNotice` for online-only writes), `SettingsCard` (a titled `section` with `data-section`) and `SaveRow`.
- **Light pages** (sign-in, the account forms, the marketing site) import `Field`, `FieldControl` and `IconButton` from `~/components/ui/plain`, never `~/components/ui` (its chunk carries React Aria). `PROVIDER_SHEET_STATE` lives in `lib/providers/providerSheetLink.ts`.

## Component tests

- **The project** `web:components` (in `pnpm check`): Vitest browser mode, headless Chromium (`@vitest/browser-playwright`, `vitest-browser-react`). Files are `*.browser.test.tsx` beside their subject. Install Chromium once (`pnpm test:components:install`); run `pnpm test:components` (`--changed <base>`). Defaults: 420×900, America/Los_Angeles, en-US, and today at 12:00 (`test/setup.ts` offsets the real `Date`, so milliseconds still move; `VITE_TEST_CLOCK=HH:MM` sets another time). Its globalSetup (`apps/web/test/browserLease.ts`) holds the `browser` lease.
- **The primitives' behaviour** is tested in `components/ui/primitives.browser.test.tsx` and as the screens use them in `components/ui/inScreens.browser.test.tsx`; settings in the settings route folders' `*.browser.test.tsx`. Component tests and `apps/web/test/` need no browser checks (`check-areas.d/`).
- **The test device** (`apps/web/test/`) is the only way tests get data. `renderWithDevice({ route: { path, module } | element, url, role, fixtures: [fx.note({ text }), …], width, theme, frame, api })` renders real route modules on a local-only PowerSync database that never connects (`frame: true` adds the `/app` header and tab bar). The device is offline unless `api` answers oRPC calls; `connected: true` or `device.connect(bool)` sets the connected status for online-only controls. It returns the screen and the database, plus `location()`, `sync()` (another device's change arriving), `unsync()`, `queued()` (uploads) and `query()`. `renderInRouter` is for primitives. The seam is `installTestDatabase` in `lib/sync/index.ts`, which throws outside test mode.
- **Settle:** `device.settle()` waits until every live query whose tables changed has rerun and the DOM has stayed still for 2 frames (`settle(db, { timeout })` in `test/database.ts`). Call it after every stored write, `sync()` or `unsync()` before reading the screen. `renderWithDevice` settles before it returns (`settle: false` for a first-paint test). It covers the database only (not lazy imports, timers or scroll): after a click that saves, keep polling.
- **Server-loaded and auth routes:** a `DeviceRoute` with a server `loader` or `action` takes `loaderData` and `actionResult` (a value, or a function); without one it throws, naming what to give. Paths outside `/app` mount beside it. `~/.server/*` resolves to throwing stubs in `apps/web/test/server/` (add one per module a route imports). An `api` key starting with `/` answers that path with plain JSON, for Better Auth calls.
- **Fixtures:** the `fx` builders cover groups, people, every entry kind, documents, providers, links, medications, passes and periods (todos through `todo({ … })`), with fictional defaults (`TEST_USER`…); camelCase overrides are checked against the device schema. Shared worlds (`*World.tsx`; `plannerWorld`'s `fixClock()`) sit beside their routes. Helpers in `apps/web/test/`: `refusal(code)` and `apiCalls()` (`api.ts`), `commands.colorScheme(...)`, `commands.media("print" | "screen" | null)` (`commands.ts`; reset after the test).
- **Parallelism:** `maxWorkers: 4`, `sequence.groupOrder: 1` (after the other projects).
- **Gotchas:**
  - Test Back with a `BackProbe` capturing `navigate(-1)`, never `history.back()` under `createRoutesStub`; pending navigation needs a `createRoutesStub` with loaders.
  - On a route whose `clientLoader` calls the `api`, or before the first rows, wait on an element, since settle covers the database only: `await found(() => X()?.querySelector(…))` (`test/found.ts`, 5 s; `stopsMoving()` for a row that shifts) before acting on it, never `X()!`; `expect.poll` for values.
  - `getByText("…")` matches whole text. A closed native `<dialog>` drops out of `getByRole` (assert `dialog.open`; poll `dialog[open]` after a `ConfirmDialog`).
  - Click a row's text with `{ force: true }` (its stretched link covers it). Pass a locator to `userEvent.hover`; a tooltip shows on hover only after the next pointer press.
  - A menu's accessible name comes from its trigger. A `DeviceRoute` child that reuses its parent's path needs an explicit `id`.
  - After a dependency change the first run can fail every file while Vite re-optimizes ("Vite unexpectedly reloaded a test"): rerun once.
