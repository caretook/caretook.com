# Components (`apps/web/app/components/`)

The components area's rules and decisions, moved out of AGENTS.md (whose core rules still apply). An orchestrator folds a landing's lasting decisions for this area in here.

**Components** (`app/components/`, from the `components` PRD):

- `ui/`: primitives that import nothing from feature folders: `Menu` (with `SEPARATOR`), `Sheet`, `Popover` (children may be a function of `close`), `ConfirmDialog`, `Field`, `ChipGroup`, `UserAvatar` (`size`, from `xs` 20 px), `AvatarStack`, `IconButton`, `ChoiceGroup`, `BackLink`, `ComboBox` (data in: `options`, a controlled `inputValue`, `onSelect`, an optional `onCreate`/`createLabel` last option, `onClose("blur" | "escape")`; the caller filters) and `ChipList` (a `ul` of link or plain chips, with `muted` and an optional × remove). `ui/tooltip/` (its own index, about 2 KB gzipped, loaded by the timeline, entry and provider pages): `Tooltip` (`content`, one focusable child such as a `Link`, optional `placement`; React Aria's `TooltipTrigger` with `Focusable`; a portal on `body`, `z-50`, the shared surface). `ui/date/` (its own index, so the ~42 KB date picker stays off every page): `DateTimeField`, a RAC `DatePicker` with typed segments and a "Pick a date" calendar popover, with an `error` prop. **Only `ui/` imports `react-aria-components`.** Feature folders: `brand/` (`LogoMark`, `Wordmark`), `entry/` (`EntryActions`, `KindIcon`, `EntryBody`, `OlderEntries`, `MedicationEntryText`, `CancelEventDialog`, `useEventCancel`, `useEventReschedule`; shared by the timeline and Upcoming), `schedule/` (`ScheduleFields`: start, end and all-day; `RescheduleSheet`, loaded lazily by `useEventReschedule`), `groups/` (`NewGroupFields`, `newGroupFromForm`), `notes/` (`LiveNotesEditor`, `EditorAvatars`; kept apart so Tiptap never reaches the timeline through an index), `providers/` (`ContactActions`, `ContactDetails` (visible phone, address and email links, from `contactDetails()`; the directory rows), `ProviderTypeIcon`), `settings/` (`SettingsFrame`, `SettingsPage`, `SettingsCard`, `Details`/`Detail`, `SaveRow`), `shell/` (`FirstSyncPending`). **Import through each folder's `index.ts`**, never a file inside it, and a route never imports another route's folder. A route that imports an index gets that folder's whole chunk, so keep heavy pieces out of indexes light routes use.
- **Every menu is `ui/Menu`**: callers pass data (`label`, `menuLabel`, `items`, optional `className` on the trigger), never React Aria parts. Items (`menuModel.ts`, pure, tested) have a label, description, icon, danger tone, disabled, and `onAction` or `href` (links navigate through React Router; a link item's optional `state` is passed as history state through React Aria's `routerOptions`, via the pure `linkOptions`). Sections can have a title, a non-interactive `header`, and `selection: { selected, onChange }` (`menuitemradio`, a check on the right). No feature file imports `react-aria-components` for a menu.
- **One entry actions menu** (`entry/EntryActions`, items from the pure `entryActionItems(kind, { canEdit })`): Edit then Delete for symptoms and vitals, Delete only for notes and events, on rows, cards and the entry page alike.
- **Primitives' contracts:** `Sheet` covers the full screen below `sm` (scrolling inside itself, safe-area padding, no grab handle; B-73) and is a centred modal from `sm`, above the tab bar, and returns focus to its opener on close. `ConfirmDialog` waits for an open menu to close before `showModal()` (so focus returns to the ⋯ button), and Escape closes only the dialog; an optional `message` is linked by `aria-describedby`, and `confirmDisabled` disables the confirm button (a delete that's refused). `Field` gives its control the `id`, `aria-invalid` and `aria-describedby` (`labelHidden` for the entry title), and shows an optional `warning` line (described by `<id>-warn`, never `aria-invalid`) while there's no error. `ChipGroup` link chips are a `nav` with `aria-current="true"`, and a link chip can carry an optional `leading` and `trailing` node and a `name` (its accessible name); button chips are a `ul`, with `aria-pressed` when they toggle. `AvatarStack` shows up to N, then "+N"; each avatar has `data-person`. `IconButton` requires a `label` (its name and tooltip); with `to` instead of `onPress` it's a link that looks the same (`prefetch="render"`), and `expanded`/`controls`/`ref` make it a disclosure that focus can return to. `Highlight` renders a search's matches as `<mark>` (`MARK_CLASS`, `bg-warning text-warning-content`, 5.2:1 in both themes). Menus and popovers share one surface class (`ui/styles.ts`).
- **Where the UI is tested:** the primitives' behaviour (tap and keyboard, 420 and 1280, light and dark, focus return) is in `components/ui/primitives.browser.test.tsx`, the primitives as the screens use them in `components/ui/inScreens.browser.test.tsx` (every menu, sheet, confirm, chip row, popover, tooltip and the date field at 360–1280), and settings in `routes/app/settings/settings.browser.test.tsx` and `routes/app/groups/settings/groupSettings.browser.test.tsx`. `ui.mjs` is a short pass on the check build (the user menu, the add sheet and its calendar, at 420 dark and 1280 light), in the suite and run by changes under `components/ui/`, `components/settings/` and both settings route folders (`check-areas`). It turns on `Emulation.setFocusEmulationEnabled` (headless Chrome otherwise loses page focus after a native `<dialog>` closes).
- **Rules for the building blocks:**
  - Only `ui/` imports `react-aria-components`, and `ui/` imports nothing from feature folders. Callers pass data, labels and callbacks, never React Aria parts or render props, and at most a `className` for the outer element (`Field` and `ChoiceGroup` callers also style the control they render). Primitives own ARIA naming, press handling, focus on open and return on close, and the layers (sheets and modals `z-50`, tab bar `z-40`, sticky headers `z-10`). Styling is daisyUI classes and tokens only.
  - **Every labelled form control is a `Field`**; **every one-of-a-few choice is a `ChoiceGroup`** (native radios in a named `radiogroup`, controlled or uncontrolled, with `error`); every icon-only button is an `IconButton`; a page's back link is a `BackLink`. **Add a primitive only for a pattern the app repeats**; a one-off styled link or button stays in its file.
  - **Hooks own state; components own markup.** Hooks return data and callbacks, never JSX (`useTimelineData`, `useLiveEntry`, `useEntryFormSave`, `useProviderNotes`). Live data comes through hooks over `useLiveQuery`; components don't call `getSync()` while rendering. Pure logic moves into plain modules beside its feature, with `web:unit` tests.
  - **Size guideline** (not enforced by lint): a route module about 100 lines (loader, action, `shouldRevalidate`, `meta`, and a short component that composes); a component about 150. Split a large route into a `load<Thing>.ts`, a `use<Thing>` hook and region components beside it. (`ProviderForm`, about 235 lines, is the known exception.)
  - **When a component moves:** it lives beside its route until a second route needs it, then moves to the matching feature folder under `components/` (or `ui/` if it's feature-free) and is exported from that folder's index. Keep heavy pieces (the editor, the date picker) out of indexes light routes import.
  - **Settings pages** use `SettingsPage` (heading, plus `offlineNotice` for online-only writes), `SettingsCard` (a titled `section` with `data-section`) and `SaveRow`.
  - **Light pages** (sign-in, the account forms, the marketing site) import `Field`, `FieldControl` and `IconButton` from `~/components/ui/plain`, never `~/components/ui` (whose chunk carries React Aria: the marketing layout went from 143 to 380 KB). `IconButton` has `size` (`sm`, default, or `md`, 24 px icon). `Field` ids come from `useId`, so checks select account inputs by `input[name=…]`. `PROVIDER_SHEET_STATE` lives in `lib/providerSheetLink.ts`.

## Component tests

- **The project** `web:components` (in `pnpm check`): Vitest browser mode, headless Chromium through `@vitest/browser-playwright` 5.1.0, `playwright` 1.65.1 and `vitest-browser-react` 2.3.0. It loads apps/web's Vite config; React Router's plugin is off under `VITEST`. Files are `*.browser.test.tsx` beside their subject. Chromium is installed once per machine with `pnpm test:components:install`. Run them with `pnpm test:components`, or `pnpm test:components --changed <base>` while building. 420×900 by default, the zone America/Los_Angeles, the locale en-US. Its globalSetup (`apps/web/test/browserLease.ts`) holds a machine-wide `browser` lease while Chromium runs.
- **The test device** (`apps/web/test/`) is the only way tests get data. `renderWithDevice({ route: { path, module } | element, url, role, fixtures: [fx.note({ text }), …], width, theme, frame, api })` renders real route modules (`clientMiddleware`, `clientLoader`, `clientAction`, the real `app` and `group` routes; `frame: true` adds the `/app` header and tab bar) on a local-only PowerSync database that never connects. The device is offline unless `api` answers oRPC calls. It returns the screen and the database, plus `location()`, `sync()` (another device's change arriving), `unsync()`, `queued()` (uploads) and `query()`. `renderInRouter` is for primitives.
- **Fixtures:** the `fx` builders cover groups, people, every entry kind, documents, providers, links, medications and periods, with fictional defaults (`TEST_USER`, `TEST_GROUP`, `TEST_RECIPIENT`); overrides are camelCase and checked against the device schema.
- **The seam** is `installTestDatabase` in `lib/sync/index.ts`, which throws outside test mode.
- **Helpers:** `apps/web/test/api.ts` has `refusal(code)` (an AppError as the API sends it) and `apiCalls()` (records `api` calls); `commands.colorScheme("dark" | "light" | null)` (from `vitest/browser`, defined in `test/commands.ts`) sets `prefers-color-scheme` (reset it after the test); `fx.medicationPass` builds a pass. The timeline's tests share a fictional world in `timeline/timelineWorld.tsx`.
- **Gotchas:** `getByText("…")` matches whole text (use a regex for part); a closed native `<dialog>` drops out of `getByRole`, so assert `dialog.open`. Click a row's text with `userEvent.click(el, { force: true })`: its stretched open link covers it, as a real tap does. Pass a locator to `userEvent.hover`, not an element. After keyboard use, React Aria shows a tooltip on hover only after the next pointer press. A `DeviceRoute` child that reuses its parent's path needs an explicit `id`. A menu's accessible name comes from its trigger, so assert `aria-label` for `menuLabel`. The first run after a dependency change can fail every file while Vite re-optimizes ("Vite unexpectedly reloaded a test"): rerun once. Each run picks a free browser port (`vitest.config.ts`), so worktrees can run them at once.
- **check-areas:** component tests and `apps/web/test/` need no browser checks.
