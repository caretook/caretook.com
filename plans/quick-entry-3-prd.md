# PRD: Quick entry everywhere, a way to use the whole site

Topic `quick-entry-3`, the first of four. Backlog items B-1038 (quick entry on every page), B-1039 (go to a page and open in a new tab). The follow-ons carry the rest (_The whole plan_): `quick-entry-find` (B-1044 go to a record by name; B-1043 find, switch, call), `undo-first` (B-1040 act first, Undo after, app-wide; B-1041 undo and fix commands) and `quick-entry-4` (B-1042 acting on existing things; B-896 what can I say and the cheat sheet, last, so it lists every command).

From the user (2026-11-28): "The ez entry box is very close to graduation from a 'timeline feature' to a 'alternative primary interface to the site'. As such, it should probably be easy to get to no matter where you are on the site. We should also probably add a 'goto' command to navigate to new pages along with 'goto new tab' that opens a new tab with some alternative language." … "I'd like to eventually move away from 'confirmations' and into 'default action taken let me know if you want to roll back' so a user can use the site as much as possible hands free." … "Lets plan 'BIG' and then slice into manageable steps".

Asked in the backlog session (2026-11-28): which command groups (undo and fix, act on existing things, find/switch/contact/help chosen; read back aloud not chosen), act-first scope (app-wide, as recommended), planning (inline, as recommended), and after two skeptic send-backs on slice size, splitting into two topics (as recommended).

## The whole plan

What the four topics add up to, so each planner works toward the same box. Only `quick-entry-3` is sliced here; the others get their plans when they come first, from this section and their items.

- **`quick-entry-3` (this PRD):** the sheet on every group page, the keyboard shortcut, the page context, "go to <page>" in place or in a new tab, and running commands from the box.
- **`quick-entry-find`** (B-1044, B-1043), after this topic:
  - **First, a pure move:** the parser's provider and medication matchers (`matchProvider`, `matchMedication`) move into the assistant domain folder with what they need: the tokenizer (`tokenize`, `Token`, with `VITAL_SINGLE_WORDS` and `UNIT_WORDS`), `wordsOf`, `NameMatch`, `HONORIFICS` and `editDistance`. One import path per name, no shims: the schema and domain export lists (`schemaExports.test.ts`, `DOMAIN_EXPORTS` in `domain.test.ts`) and the app's importers (`lib/assistant/quickEntryCompletion.ts`, `lib/providers/providerSuggestions.ts`) follow. The domain imports only types from the schema (data-layer).
  - Then "go to Dr. Lee" and "open metoprolol" (a record command, one card per candidate); "find …", "search …", "look up …"; "switch to <group>"; "call <provider>" (`QuickEntryProvider` gains `phones`). Call follows the move.
- **`undo-first`** (B-1040, B-1041):
  - **Act first, Undo after, app-wide.** Every reversible action runs at once and shows Undo; no confirm. Confirms that go: delete an entry, a planner entry, a todo, a medication, a pass, a pass log, a provider, a care period, an allergy, a condition, and Remove your last entry (all soft deletes today). Confirms that stay: remove a member or leave a group, invites and join requests, sign out a device or everywhere, disconnect an assistant or Google Calendar, regenerate the feed link, turn off assistants, delete or merge a tag (a hard delete), copy a provider to another group, the as-needed "log anyway" warning, discard changes.
  - **One Undo for everything:** today's Undo stores (quick entry and passes in `passUndo`, todo ticks, toasts) become one recent-actions store on the device (per user and group, cleared by `wipeDevice`), with a longer window and a list of recent actions to roll back from. An undo of an edit restores the values it replaced; last write wins as everywhere. The quick entry sheet then closes on Save with the toast Undo.
  - **Commands:** "undo", "undo that" (the last action), "delete that", "change that to …" (edit the last saved entry: a vital's numbers, a time, a dose's amount). "That" is the last action on this device, else the page's record.
- **`quick-entry-4`** (B-1042, B-896): "done <todo>" ticks it, "skip <pass or medication>" logs skipped, "tag that <tag>" (a new tag is made), "move <event> to <time>" reschedules. Each acts at once and offers Undo. Matching an existing record uses the moved matchers: by words, with a card per candidate. Last, help (B-896): "help" and "what can I say" give a card, and a cheat sheet page lists every word and command, linked from the box and onboarding, built from and tested against the parser's tables.
- **Later, not planned:** reading answers aloud with the device's own voice (`speechSynthesis`); Siri and Shortcuts through App Intents once the Capacitor app ships (as push notifications wait for it).

## Problem

Quick entry already logs nearly everything a caretaker does, but only from the timeline. On a provider's page, the medications list or the planner, logging means going back to the timeline or finding the right form. Moving around takes taps through menus, which is slow one-handed and impossible hands free.

## Solution

- A quick entry button sits in the header on every group page; `/` or Cmd/Ctrl+K opens it on a keyboard. It's the same box as the timeline's, in a sheet.
- Opened on a provider's page, "called back, refill sent" is a note about that provider; on a medication's page, "gave 1" is a dose of it.
- "go to medications" and "open the planner in a new tab" do what they say, with one card and a Go.

## User stories

1. As a caretaker on any page of a group, I want a quick entry button in the header, so that I can log without going back to the timeline. (B-1038)
2. As a caretaker at a keyboard, I want `/` or Cmd/Ctrl+K to open quick entry, so that I never reach for the mouse. (B-1038)
3. As a caretaker, I want Undo right after saving from the sheet, so that a wrong line costs one tap. (B-1038)
4. As a caretaker on a provider's page, I want a note or event I type to link that provider, so that I don't have to name them. (B-1038)
5. As a caretaker on a medication's page, I want "gave 1" or "skipped" to be a dose of that medication, so that I don't have to name it. (B-1038)
6. As a caretaker, I want "go to medications", "go to todos", "go to settings" and other pages, so that I can move around by typing or dictating. (B-1039)
7. As a caretaker, I want "open the planner in a new tab", "new tab timeline" or "pop out medications" to open it in a new tab, so that I can keep my place. (B-1039)
8. As a viewer, I want the box and its go to commands, so that I can move around even though I can't log. (B-1039)

## Implementation decisions

- **The sheet:** a quick entry sheet component in the shared quick entry folder, mounted once in the group layout (under the group's provider, which the box needs). A tiny open-state store (module state with subscribe, like the toast queue) lets the frame's header button (beside the search button, a filled region) and the keyboard hook open it. The hook ignores keys typed in an input, textarea, select or contenteditable, and does nothing outside a group route or in the easy frame. The button shows for anyone in the group; readers' write cards are refused as on the timeline. The sheet stays open after Save with the box's Undo.
- **Page context:** a pure function in the assistant domain folder maps route params (a plain record) to a page context (`{ providerId?, medicationId? }`, more kinds later); `useQuickEntry` passes it to the parser's context. The parser uses it only as a default: a named provider or medication always wins, and a line about something else reads as today.
- **The command reader:** `readGoTo` (assistant domain folder) grows into `readCommand(text, context) → Command | null`, read whole before the parser splits the line: go-to-day (today's rule), go-to-page, each with `newTab`. Its vocabularies (page names, new-tab phrases) are named row sets like `QUICK_ENTRY_VOCABULARY`, so help can list them later; `quick-entry-find` adds records, find, switch and call.
- **Running a command** is a device-side function that turns a command into a URL through `appUrls` and navigates, or opens a new tab (`window.open` with `noopener`; in place on the native build). It writes nothing and adds no recent line.
- **One command card:** the go-to card grows into a command card (what it will do, then Go).
- **Docs:** the orchestrator folds the sheet, page context and commands into the assistant and app-shell area docs at landing; loops don't edit docs.

## Testing decisions

- The command reader and page context are pure: unit tests, table-driven, a row per page name and wording and per neighbour that must stay an entry ("show of hands at church", "open wound looks better", "go to dr lee at 3"). Prior art: `quickEntryGoTo.test.ts`.
- The sheet, the shortcut and running a command: component tests (prior art: `timelineQuickEntry*.browser.test.tsx`), with a stubbed `window.open`.
- No integration test, no browser check: nothing crosses the server or sync.

## Out of scope

- Everything under `quick-entry-find`, `undo-first` and `quick-entry-4` (_The whole plan_).
- Reading aloud, speech recognition, Siri.
- Other languages (B-378 keeps Spanish quick entry).
- Commands in the connector's tools.
