## Problem

The marketing site works but looks like a first draft: a narrow column, flat grey bands, the same small cards everywhere, a long features page with no way to jump around. The hero still reads like an ad. The features page buries quick entry in the middle and doesn't mention easy mode at all, which is one of the things the user most wants families to know. There's no accessibility statement, though privacy and terms are there. And nobody has looked at how Caretook compares with Caring Village, the closest app a family is likely to try.

## Solution

One pass over the shared section components gives every page a modern look at once, from a single module of class constants: more room, clear bands, cards with depth, a bigger type scale, a gentle gradient behind each page's opening, a sticky header and a footer in columns. The hero lead becomes one plain sentence. The features page opens with jump links, puts "Log it in seconds, typed or spoken" right after the timeline, follows it with easy mode, and gives every block the same shape. A draft accessibility statement goes in the footer beside the legal pages, saying only what's true. A short research note compares Caretook with Caring Village, for the user's positioning.

## User stories

1. As a family member sent the link, I want the site to look current and calm, so that I trust it's a real, cared-for product (B-836).
2. As a visitor on a phone, I want each section clearly set apart, with readable type and room to tap, so that I can scan the page with one thumb (B-836).
3. As a visitor, I want the home hero to tell me in one plain sentence what Caretook keeps track of, so that I'm not reading slogans (B-855).
4. As a visitor on the features page, I want to jump straight to the part I care about, so that I don't scroll past seventeen blocks (B-836).
5. As a busy caregiver, I want to read near the top of the features page that I can log something in seconds by typing or speaking, so that I know it fits a hard day (B-887).
6. As someone caring for a person who finds apps hard, I want to read that Caretook has an easy mode, and easier roles for family, so that I know they can use it too (B-888).
7. As a visitor who relies on assistive technology, I want an accessibility statement saying what standard the site works to, what's known not to work yet and how to report a barrier, so that I know what to expect and who to tell (B-563).
8. As the founder, I want a note comparing Caretook with Caring Village (where they overlap, where we already do better and where we could), so that I can position Caretook honestly (B-829).

## Implementation decisions

- **The look module** (`sections/look.ts`, new): exported class strings, and nothing else: the container (wider than today's `max-w-5xl`), the section's vertical rhythm, the two band tones (page and alternate), the card, the opening gradient, and the h1/h2/h3 sizes. Every marketing section, the legal page and the header and footer read their spacing and surfaces from it instead of each file's own `CONTAINER`. Theme tokens only (`base-*`, `primary`), so light and dark both work and the stored app theme still applies. Animation only under `prefers-reduced-motion: no-preference`, at the app's `--motion` tokens ([components](../docs/domain/components.md)).
- **Home sections** (`Sections.tsx`: `Hero`, `FeatureGrid`, `Steps`, `PromiseSection`, `CtaBand`; `WaitlistBand`): restyled from the look module; their props and the content types don't change. The hero keeps its one `h1` (the lockup) and its two buttons on one row from 360 px.
- **Inner-page sections** (`PageSections.tsx`: `PageIntro`, `Showcase`, `Gallery`, `Prose`, `FaqList`; `LegalPage`): restyled from the look module. `Showcase` without an image renders its icon, large, in the image's column (decorative, `aria-hidden`). A new `JumpLinks` component takes `{ id, heading }[]` and renders a labelled `nav` of hash `Link`s; the features route passes its showcases.
- **Layout** (`MarketingHeader`, `MarketingFooter`): the header is sticky with a translucent, blurred background (an opaque one when transparency is reduced) and marks the current page with `aria-current`; the footer lays out the site pages, the legal pages and the brand in columns from `sm`. Both still read `MARKETING_PAGES`.
- **Copy** stays in the content modules. Features: the block order is timeline, quick entry (renamed), easy mode (new, icon from `sections/icons.tsx`, a lucide icon already installed), then the rest as today. Home: only `hero.lead` changes.
- **The accessibility page**: an entry in `MARKETING_PAGES` (`accessibility`, area `legal`), a route in `routes.ts`, and a folder with `route.tsx` and `content.ts` (a `LegalPageContent`, `draft: true`). The sitemap and prerender pick it up from the page list.
- **The research note** (`docs/research/caring-village.md`, new): a feature table (Caring Village, Caretook, a verdict: overlap, we're ahead, they're ahead), then where Caretook could pull ahead, each line pointing to the area doc or a public Caring Village page it rests on. It's read from public web pages only; nothing about the user, the project or its data goes into a search.

## Testing decisions

- **Content modules** (unit, the existing files): `features/content.test.ts` holds the block order (timeline, quick entry, easy mode first) and that the easy mode block exists with points; `home/content.test.ts` holds the hero lead to one sentence of at most 25 words. Never the wording.
- **The accessibility page** (unit): it joins `legal.test.ts`'s page list, so it gets the same shape checks (title, description length, h1, date, draft, unique anchors, internal links that resolve), and one assertion that it's in the footer's legal group and absent from `LEGAL_VERSIONS`.
- **Sections** (component, `marketingWorld.tsx`'s `openMarketing`): `pages.browser.test.tsx` checks the features page's jump links (one per block, each pointing to an existing id) and that each block keeps one `h2`; `layout.browser.test.tsx` checks `aria-current` on the header link and the footer's groups. The restyle itself isn't asserted (classes aren't behaviour); the `marketing` browser check runs once at the end of the wave that restyles.
- Prior art: marketing-2's content tests and `openMarketing` component tests.
