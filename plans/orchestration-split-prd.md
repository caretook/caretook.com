## Problem Statement

The orchestration tooling (about 52k lines in `scripts/loops`, `scripts/backlog`, `.githooks`, half of it tests) lives inside Caretook and is wired to it both ways: about 120 `CARETOOK_*` variables, app paths in about 40 files, Caretook's stack in its stack scripts, Caretook's browser checks in its gates, and Caretook's CI and checks importing it. The user wants one tool that runs Claude across all their repos. Today it can't be pointed at another repo, every tooling change lands in Caretook's history, and Caretook carries code that isn't Caretook.

## Solution

First, inside Caretook and with no change in behaviour, every Caretook fact moves out of the core into one config file and a project folder, Caretook's checks and CI stop calling the core, a lint rule proves the line, and the tool's names become Risa's. Then, in one hand session with nothing running, the clean core moves to `~/git/risa` with its history, and Caretook keeps its config, plans, docs and scripts. From then on the user runs `risa` and it manages Claude in Caretook as one configured repo.

## User stories

1. As the user, I want every Caretook fact the tooling uses to live in one config file and one project folder, so that I can see what a repo must provide.
2. As the user, I want a lint rule that fails when the core names Caretook or an app path, or when Caretook's code imports the core, so that the line stays drawn.
3. As the user, I want Caretook's stack, test DB, browser checks, check areas, budgets and test gates to be Caretook's own scripts and data that the tool calls, so that another repo can bring its own.
4. As the user, I want the tool's knobs named `RISA_*`, so that nothing about the tool says Caretook.
5. As the user, I want the host calls (iTerm2, launchd, nvm, the CLIs) in one place, so that they're easy to find and swap later.
6. As the user, I want Caretook's checks, tests and GitHub CI to run with no tool present, so that Caretook doesn't depend on Risa.
7. As the user, I want the move done in one drained session with history kept and a one-commit undo, so that it can't strand running work.
8. As the user, I want to run `risa` against Caretook as a configured repo, with its prompts and hints naming `risa`, so that Caretook is a plain repo.

## Implementation decisions

- **The project config** is one module at Caretook's root with a small, validated shape: name, the command names, paths (backlog, inbox, archive, plans, docs, agents doc, browser checks, CI lists), branch names (trunk, protected, prefixes), commands (check, quick check, project tests, typecheck, typegen, datastore start, reset and seed), hooks (stack up, down, status, ready; test DB; lease; check areas for a diff; doc budget), and the Risa version expected. It is JSON (`risa.json`); a core loader validates it in Node and a `config get` helper reads it from bash; nothing else knows where it lives.
- **The core manifest** lists every file in `scripts/loops`, `scripts/backlog`, `scripts/ci` and `.githooks` with its owner, core or Caretook, tests included. The boundary lint and the move's `filter-repo` both use it.
- **The boundary lint** works both ways: it fails on a Caretook name, an app path (`apps/`, `packages/`, `powersync/`, `docs/domain/`, `ops/`) or a `CARETOOK_` variable in a core file, on a core file importing a Caretook file, and on any Caretook file (anywhere in the repo) referring to a core path in any form (import, spawn, path string, `--import`), minus an allowlist each slice shrinks; stage 1 ends with only the named residual list (_Decisions_). The core-to-Caretook rule covers spawns and path strings too, not only imports.
- **The CI split:** core and Caretook CI modules exchange facts through files and config (the tier data, the check plan's output, notices), never imports.
- **The host layer** is one core module for tabs, autostart, Node, notifications and running `claude`, `codex` and `gh`.
- **The renames** (variables, command names) are scripted and mechanical; the lint confirms nothing is missed.
- **Tests:** a sample project config and fixture repo for the core's tests; generic tests with Caretook-like sample paths get neutral ones; Caretook's tests sit beside Caretook's scripts under a Caretook test script; the prompt golden splits in two.

## Testing decisions

Tooling unit and CLI tests, as today, plus the config loader and its validation, the boundary lint, the lease from both sides, the CI split's file exchange, and the split goldens. Each slice keeps the whole tooling suite green with no behaviour change, and `pnpm test`, `test:tooling` and `test:browser-harness` run exactly today's test sets until the move. Before the move, a throwaway GitHub CI run on a branch with the core files deleted must be green. Slices touching the app's test helpers, `vitest.config.ts`, `package.json` or `.github/` take the tier the check gate asks for (named per wave in the plans).

## Out of scope

Risa's multi-repo features; moving tool state out of `.loops/`; Caretook's history cleanup; other hosts; a remote for Risa; releasing it. Each is a `risa-next` item.
