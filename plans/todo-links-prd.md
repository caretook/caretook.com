## Problem

Linking a todo to what it's about is rough. The todo sheet has three separate pickers (provider, event, medication), each searching only names in its own list; notes can't be picked there at all; the todo page has its own "Link an entry" for notes and events; and none of them find a provider by practice or phone, or a medication by its brand name. Before typing they show nothing helpful. Adding a todo from the record it's about (a provider's page, an event) means opening the full sheet.

## Solution

One "Link to…" box, the same on the todo sheets and the todo's page, searches everything a todo can link to (providers, medications, notes and events) through the group's site search, so it matches what site search matches and ranks the same way. Each result shows its type's icon and a second line (an event's date, a provider's specialty, a medication's dose). Tappable type chips, or a type word typed with the search, narrow it. Before typing, it suggests where you came from, the next events and what you looked at recently. Each provider, medication, note and event page gets the same quick add the Todos list uses, so a todo (or a subtask under one listed there) is added in place and linked to that page.

## User stories

1. As a writer, I want one "Link to…" box on a todo instead of three pickers, so that I link a provider, medication, note or event the same way (B-944).
2. As a writer, I want each result to show what it is (its icon) and a second line (an event's date, a provider's specialty, a medication's dose), so that I pick the right one (B-944).
3. As a writer, I want the same box on the todo's page and in its sheets, so that I learn it once (B-944).
4. As a writer, I want to tap a type chip (All, Providers, Events, Meds, Notes) to narrow the results, so that a common name doesn't bury what I want (B-945).
5. As a writer, I want typing "provider lee" or "med" to turn on that type's chip and keep searching the rest, so that I don't have to tap (B-945).
6. As a writer, I want the box to find a provider by practice, specialty or phone, a medication by brand name or what it's for, an event by place or provider, a note by its text, and anything by its tag, ranked like site search, so that I find it however I remember it (B-946).
7. As a writer, I want the empty box to suggest the record I came from, the next events and what I viewed recently, so that the usual pick is one tap (B-947).
8. As a writer on a provider's, medication's, note's or event's page, I want to quick add a todo there, linked to it, without leaving the page (B-948).
9. As a writer on such a page, I want to quick add a subtask under a todo listed there, the same way as on the Todos list, so that I break a step down in place (B-948).
10. As a reader (no write role), I see no link box, no Remove and no quick add, as today.

## Implementation decisions

### The link search (new, device)

- **A deep module over the search index**: given the group, the typed text, a type filter and limits, it returns ranked link candidates of the four linkable types. It parses the text with the shared parser, pulls a leading or trailing type word out first, calls `searchGroup` with the group's named tags (`matchingTagIds`), over-fetches entries and keeps only notes and events (live; an event cancelled or deleted is left out), drops todos and conditions, and merges the types into one list by site search's order (`compareHits`).
- **A pure options part** turns the candidates and their rows into options: `{ id, type, label, description }`. Description: an event's when (`eventWhen`), a provider's specialty or type and practice (and "Past"), a medication's strength or dose line, a note's day. Already linked ones are left out. Tested as a unit.
- **The type word parser** is pure: the word list in _Decisions_, case and accents folded, only as the first or last word, never the only word ("med" alone turns the chip on and searches nothing, which shows that type's suggestions).
- While the index is preparing or unavailable, the box says so ("Preparing search…") and still shows suggestions.
- It lives in the todos area (`lib/todos/`), using `lib/search`'s exports unchanged, so it stays out of the `fixes-bug` topic's hot files except where B-946 needs the index.

### The box (new shared component)

- `LinkToBox`: the type chips (`ChipGroup`, as the search page's tag filter), then a combo box over the link search; each option shows its type icon (the provider type icon, `Pill`, `CalendarClock`, `NotebookPen`) and its description line. Props: the group, what's already linked (left out), `onPick({ type, id })`, and the suggestion context (where it was opened from). Writers only; the caller decides.
- **Suggestions** (pure, tested): with no text, the came-from record, the next three upcoming events and the last five recently viewed, deduplicated, already linked ones left out, narrowed by the chip that's on.
- **Recently viewed** (new, `lib/` per user, like `recentSearches`): `recordView({ type, id })` from the provider, medication and entry pages when they show a live record; `recentlyViewed()` newest first, at most 10 stored; storage that throws means none; `forgetRecentlyViewed()` in `forgetUserData`.

### The sheets and the todo page

- **The sheets** (`TodoForm`): `LinkToBox` replaces `TodoLinkFields`' three pickers. Chosen links show as chips with ×, as today: one provider, one medication (a new pick replaces), any number of notes and events. The form posts `providerId`, `medicationId` and `entryIds` (repeated); the old `eventId` and `entryId` prefills become initial `entryIds`.
- **Device writes:** `createTodo` takes `entryIds` (each live note or event in the group gets a link row in its transaction; others ignored, as `entryId` today; `eventId` and `entryId` stay accepted for old callers and quick entry). `updateTodo` takes an optional `entryIds` and, only when given, writes the difference with `entryTodoRow`/unlink in its transaction; it still never sends `eventId`. No server change: link rows already upload through `linkTable`.
- **The todo page** (`TodoLinks`): `LinkToBox` replaces `LinkEntryPicker`; a pick links at once (`linkTodo`, or `updateTodo` for the provider or medication slot). Provider and medication rows get writers' Remove (`updateTodo` with null).

### Quick add from linkable pages

- `TodoQuickAdd` takes a parent todo (today's subtask add), a link (a provider, a medication, or an entry id), or both. With a link it adds a top-level todo with that link (`providerId`, `medicationId` or `entryIds`); with a parent it also carries the page's link, so the subtask shows on the page. Who may: a writer (`isTodoWriter`); with a parent, `canHaveSubtask` as today. Same field, Enter adds and keeps the field, errors inline.
- `LinkedTodos` (provider and medication pages) and `EntryTodos` (note and event pages): the full quick add replaces "Add todo"; each open todo row gets the compact subtask quick add.

### Search index (B-946)

- `providerSearchDocument` gets the provider's phone numbers in its body, as stored and as digits only, so "555 0134" and "5550134" both match; `readProviders` selects them.
- `medicationSearchDocument` gets its linked conditions' names in its body; `readMedications` selects them, and a change to a medication's `medication_condition` rows (a new `SOURCES` table in the index's triggers) or to a linked condition's name re-indexes it.
- `SEARCH_INDEX_VERSION` 5 → 6. Site search gains both too (same index).

## Testing decisions

- **Unit:** the options part (descriptions, leaving out linked, types), the type word parser, the suggestions, recently viewed (like `recentSearches.test.ts`), `todoFormData` (`entryIds`), `providerSearchDocument` (phone), `medicationSearchDocument` (conditions).
- **Component** (`renderWithDevice({ search: true })`, prior art `search.sync.browser.test.tsx`, `todoLinks.browser.test.tsx`): the box over a real index (finds by practice, brand, place, tag, note text, phone; ranks a title match first; chips and type words narrow; suggestions before typing); the sheets save and edit links; the todo page links and removes; quick add on a provider page and an event page writes a linked todo and a linked subtask; readers see none of it.
- **Integration:** none new: no service or server change.
- **End to end:** none: no new flow across the server; link rows already ride `roundtrip`.

## Out of scope

- Many providers or medications per todo (a join table): a follow-up if the user wants it.
- Linking todos to todos, conditions or other entry kinds.
- The split view (B-964): the follow-on topic `todo-links-2`.
- A brand name for a medication whose stored name lacks it.
- Undo for removing a link (today's Remove has none; a fixes-ui item if wanted).
- The server's `search.query` (unused by the app).
