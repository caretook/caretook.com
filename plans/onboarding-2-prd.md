## Problem

A new care group's creator gets a small card on the Timeline with links that leave the page, and no step for providers or a care period, though medications, care periods, events and notes link to providers. Once the card is dismissed or 14 days pass, an "Invite someone" card takes its place and stays. Nothing brings a creator back to a half-finished setup.

## Solution

When a creator first opens a group they set up, they go straight to its setup pages: providers, profile basics, medications and a care period, each with its form on the page. **Later, take me to Caretook!** leaves at any point. While setup or the first steps of using the group are still missing, toast nudges come back, one at a time, at most once an hour while the app has attention: **Want help onboarding?** (back to the pages) and **log a first entry** (and later, in `onboarding-3`, **invite someone** and **connect your AI assistant**). Each can be retired with **Don't ask again**, on every device. The Timeline loses the setup card's steps (the Invite someone card stays until `onboarding-3`), and invited members get a short welcome. All of it works offline and on the native target.

## User stories

1. As a group's creator, I want my first open of a new group to take me to its setup pages instead of the Timeline, so that I set it up while I'm here. (B-670)
2. As a creator, I want providers as the first step, with the provider form on the page, so that later steps can link to them. (B-670)
3. As a creator, I want to record allergies and conditions (or "none known") on the setup page, the same way Profile does, so that the profile basics are done without leaving. (B-670, B-594)
4. As a creator, I want to add medications on a setup page, picking a provider I just added as prescriber, so that the list is ready. (B-670)
5. As a creator, I want a care period step, where I can add a new place, so that the Timeline knows where care is happening. (B-670)
6. As a creator, I want to skip any step and to leave the flow with **Later, take me to Caretook!**, so that setup never blocks me. (B-670)
7. As a creator, I want the redirect to happen only once per group, on whichever device, so that Later is never undone by the next visit. (B-670)
8. As a creator of a second or third group, I want the same setup for each new group, so that every group starts set up. (B-670)
9. As a creator who left setup unfinished, I want a **Want help onboarding?** toast, on opening the app and then at most hourly while I'm using it, so that I can come back to it. (B-670)
10. As a creator, I want a nudge to log a first entry after the page flow, one toast at a time, so that I learn the rest of the app. (B-670)
11. As a creator, I want **Don't ask again** to stop one nudge for this group on all my devices and move on to the next shortly after, so that nudges respect my choice. (B-670)
12. As a creator, I want a nudge to stop once its work is done (by me or anyone else), so that I'm never asked to do what's done. (B-670)
13. As an invited member, I want a short welcome on the Timeline and no setup steps or nudges, so that I'm not asked to set up someone else's group. (B-670)

## Implementation decisions

- **The setup record (data, API, device):** `user.preferences` gains `groupSetup`, a map from group id to `{ opened?: true, retired?: NudgeId[] }`, capped like `setupDismissed`. It only grows: `opened` never unsets and `retired` is a set, so `mergeGroupSetup` combines two devices' copies without losing either. The service merges it on save, `me.get` returns it, and the device's settings cache and pending path carry it as they carry `setupDismissed`, offline included.
- **The setup rules (pure, client-safe):** one module answers from the group's facts, the member list and the stored record. It decides whether this person sets the group up (the earliest member, while an owner), which page steps are done (`hasProvider`, `hasProfileBasics`, `hasMedication`, `hasCarePeriod`), whether the flow is finished, whether to redirect on open (the settings are known, sets it up, not finished, not `opened`, not in `setupDismissed`) and the first unfinished step. Today's `gettingStarted` facts query grows the provider, care-period and earliest-member facts. The old step list for the Timeline card goes when the card does.
- **The setup pages:** a shared route under the group, `/app/groups/:groupId/setup/:step` (`providers`, `profile`, `medications`, `period`), in the app-shell area's route list, with a URL helper. A client-only layout (no server loader) shows progress, the step's inline form, **Next** and **Later, take me to Caretook!**. Opening it stores `opened` for the group. Each step reuses its area's form, form-data parser and local write (`ProviderForm`, the Profile allergy and condition sections, `MedicationForm`, `PeriodForm` with a new place), posting to the step's own client action, so it all works offline. A member who doesn't set the group up, or a role that can't write, is sent to the Timeline.
- **Known settings only:** the device's settings say whether they're known (a cached copy, or a `me.get` that answered). With only the defaults (a new or wiped device, offline or before the server answers) there's no redirect and no nudge, so the redirect never repeats on another device.
- **Tests and seeds start set up:** the seeds and the test device give their groups a record that's `opened` with every nudge retired, so existing tests and browser checks meet no redirect or toast. Setup tests opt in.
- **The redirect:** the group route's client loader asks the setup rules before any group page renders and sends a creator's first open to the first unfinished step. It reads only the local database and the cached settings, so it works offline and on native.
- **The nudges (pure plus one hook):** a pure scheduler takes the facts, the record, the role, the last time this device showed a nudge and whether this session has shown one. It returns the nudge due now or the time of the next check. The order is help (flow not finished), then entry (no entry anyone logged): a list `onboarding-3` appends invite and connect to. Nothing shows before the flow is `opened` (or the old card dismissed), or while a setup page is open. One hook in the group layout runs it on open, on visibility and focus changes, and on its own timer, shows the toast and records **Don't ask again** through the settings path. Constants: `SETUP_NUDGE_INTERVAL_MS` (1 h), `SETUP_NUDGE_FOLLOW_UP_MS` (30 s), `SETUP_NUDGE_TIMEOUT` (15 s). The device's last-shown time is local storage. The session flag is session storage.
- **The toast:** `toast()` takes an optional second action, shown after the first (the view already renders a list). Screens still use only `ui/`.
- **The Timeline:** the setup steps leave both timelines. The welcome card shows for everyone who doesn't set the group up (with welcome text for every role). The setter sees no setup card, and `InviteSomeoneCard` keeps showing for a lone manager as today until `onboarding-3`.

## Testing decisions

- **Unit:** `mergeGroupSetup`; the setup rules (who sets up, steps, finished, redirect, first step); the nudge scheduler (order, the hourly slot, the session's first nudge, follow-up after a retirement, done work skipped, a setup page suppresses). Prior art: `gettingStarted.test.ts`, the `userPreferences` merge tests.
- **Integration:** `me.update` and `me.get` carry `groupSetup` and refuse a malformed one; two saves merge. Prior art: `me.int.test.ts`.
- **Component** (the test device): the setup pages offline (add a provider, then pick it as prescriber; profile basics; a period with a new place; Next; Later lands on the Timeline); the redirect (a creator's first open goes to setup, the second doesn't, an invited member never does); the nudges with a fake clock; the two-action toast. Prior art: `gettingStarted.browser.test.tsx`, `newGroup.browser.test.tsx`, `Toast.browser.test.tsx`.
- **e2e:** no new check. `first-sync` and `invites` pass through the setup pages with Later, in the slice that adds the redirect.
