## Architectural decisions

- **CI checks, the Mac decides.** The workflow only runs checks and uploads a verdict file. Every write happens on the Mac, through `pnpm prd ci`, the dispatcher's tick and `pnpm backlog`: backlog items, quarantine entries, notices, the mode. CI reads no GitHub secret.
- **One verdict format**, versioned (`version: 1`): the commit, the run id, the push range, the culprit landings, the kind (`green`, `brake`, `file`, `flake`, `infra`), and the failing jobs, files and tests before and after the rerun. The verdict module is pure; the workflow and `pnpm prd ci` share it.
- **Committed lists** sit beside the workflow under `scripts/ci/`: the brake list, the quarantine and the mode file. Each has a comment header saying who writes it.
- **A commit CI must see is pushed by the tool that writes it** (quarantine entries, the mode), with the existing fast-forward-only push of dev.
- **One new action:** `actions/upload-artifact`, pinned to a commit SHA. No other new action or dependency (no `actionlint`). The setup reuses `.github/actions/setup`.
- The test env in CI is fictional and generated in the workflow (AGENTS.md, _Working rules_).

## Slice 1: CI runs the full check on every push to dev and every PR

Stack: no · Reads: docs/agents/machinery.md, docs/agents/loop.md, ops/runbook.md · Tests: unit

**User stories:** US 2, 3.

**Build:** `ci.yml`, triggered by a push to dev (with `paths-ignore` for Markdown-only and backlog-only pushes) and by pull requests into dev, staging and main.

- Setup: `.github/actions/setup`, a Postgres service container on the test port with `DATABASE_URL` pointing at it (so the integration `globalSetup` never falls back to docker compose), `playwright install --with-deps chromium`, `CARETOOK_LEASES=off`, a git identity for the tooling tests, and a fictional env generated by a small script under `scripts/ci/`.
- Jobs:
  - static: format, lint, typecheck; the docs budget as a warning.
  - tests: one job per Vitest project, `tooling:unit` included, with the JSON reporter; a project that runs past 10 minutes is sharded.
  - build: the build budget, `build:native`, and B-341's grep of the built client for `caretookSync`.
  - verdict: writes `green` or `file` (the other kinds come in slice 2) and uploads it as the `verdict` artifact.
- Concurrency: a newer PR run cancels the older one; a dev push run never cancels.
- `scripts/deploy/workflows.test.mjs` and its YAML reader learn the new workflow and its shapes (services, matrix, concurrency, `paths-ignore`).
- `ops/runbook.md` says what CI runs and that it reads no secrets.

**Acceptance criteria:**

- The env script's unit test: every variable the test projects and the builds read is set, and every value is generated and marked fictional.
- `workflows.test.mjs` passes with `ci.yml` in its list and reading no `secrets.*`.
- A draft PR from the slice branch into dev runs every job green and uploads a `green` verdict. The hand-off links it with each job's time and any shard it needed.
- A throwaway commit with a failing test (on a second draft PR, never merged) fails its job and uploads `file`. The hand-off links it.
- `pnpm test:tooling` passes.

**Blocked by:** nothing. **Blocks:** 2.

## Slice 2: The rerun, the verdict's kinds and the quarantine

Stack: no · Reads: docs/agents/machinery.md, docs/agents/loop.md · Tests: unit

**User stories:** US 4, 5, 6, 11.

**Build:**

- **The verdict module** (the PRD's _The verdict module_): the five kinds and attribution from the push range, using dev's first-parent merges between the push event's `before` and `after`.
- **The rerun:** a test job that fails reruns its failed files once, in the same job.
- **The brake list:** globs and named files for the sync and offline tests, the role-by-action matrices and permissions tests, the privacy and connector-leak tests, and the migration and seed tests.
- **The quarantine list,** starting empty.
- **A Vitest setup** that skips quarantined tests unless `CARETOOK_QUARANTINE=run`. CI's quarantine step sets it and can't fail the run; its results go into the verdict as `quarantined`.

**Acceptance criteria:**

- Verdict unit tests:
  - a failed static or build job is a brake;
  - a job that failed before any test ran is infra;
  - a failing test on the brake list is a brake, even when another failure is file;
  - a failure that passes on the rerun is a flake, and a mix of flake and file is file;
  - a quarantined failure leaves the verdict green;
  - a push range with one first-parent merge names it, and one with three names all three;
  - every failing file and test is named.
- The quarantine setup's test: a listed test is skipped by default and runs under `CARETOOK_QUARANTINE=run`. A local `pnpm prd check --quick` skips it too.
- A draft PR with a test forced to fail once and then pass uploads `flake`. The hand-off links it.
- `pnpm test:tooling` passes.

**Blocked by:** 1. **Blocks:** 3.

## Slice 3: `pnpm prd ci`, filing on a transition, and the brake at landing

Stack: no · Reads: docs/agents/machinery.md, docs/agents/orchestrator.md, docs/agents/backlog.md · Tests: unit

**User stories:** US 4, 5, 10.

**Build:**

- `pnpm prd ci [--json]` reads the latest dev push run, its verdict and its culprit landings through `gh`. A running run reads as `pending` and the previous verdict holds; an unreachable `gh` reads as unknown.
- **Filing on a transition:** a test that newly fails gets one item, of the kind in the PRD's Decisions table. The note carries the culprit landings, the failing tests and the run link. While that test keeps failing, later runs only add a note to the open item.
- **`land`** calls it first. On a brake it refuses unless `--fixes B-<n>` names the brake's item (a revert of the culprit counts), and the refusal names the run, the item and how to land the fix. On unknown it warns and lands.
- **`pnpm prd status`** prints the CI line.

**Acceptance criteria:**

- Unit tests with `gh` fixtures:
  - each kind files what the table says;
  - the same failure across three runs files once and notes twice;
  - `pending` keeps the last verdict;
  - unknown is never green.
- `land.test.mjs`:
  - a brake refuses with the run and the item named;
  - `--fixes` with the brake's item lands;
  - `--fixes` with any other item refuses;
  - unknown warns and lands.
- Docs fold: machinery.md (the CI verdict and filing) and orchestrator.md (the brake).
- `pnpm test:tooling` passes.

**Blocked by:** 2. **Blocks:** 4, 5.

## Slice 4: The dispatcher keeps the quarantine and reruns outages

Stack: no · Reads: docs/agents/machinery.md · Tests: unit

**User stories:** US 6, 7, 11.

**Build:** on each tick, through `pnpm prd ci`, the dispatcher:

- adds a quarantine entry for a new flake, except one on the brake list;
- prunes entries whose item is done;
- pushes dev after each quarantine commit;
- reruns an infra run's failed jobs once (`gh run rerun --failed`);
- posts a brake's notice on the board, and withdraws it when dev is green again.

**Acceptance criteria:**

- Unit tests (fixtures):
  - a flake adds one entry with its item, and a flake on the brake list adds none;
  - a done item's entry leaves in one commit, and each commit is followed by a push;
  - an infra run is rerun once and never twice;
  - a brake posts one notice, and green withdraws it.
- Docs fold: machinery.md (the tick's quarantine and the infra rerun).
- `pnpm test:tooling` passes.

**Blocked by:** 3, and agent-autonomy wave 1 in dev (the notice board). **Blocks:** 6.

## Slice 6: Two modes, rapid and pre-deployment

Stack: no · Reads: docs/agents/machinery.md, docs/agents/backlog.md, docs/orchestration.md · Tests: unit

**User stories:** US 8, 9.

**Build:**

- The committed mode file (`rapid` by default), and `pnpm prd mode [rapid|pre-deployment]`, which prints the mode, or writes it as one locked commit onto dev and pushes. Slice 5's mode function reads the file.
- The registry gains the `launch` flag, and `doctor` knows it.
- In pre-deployment mode:
  - the dispatcher's pick skips rows without `launch`, with the reason "not a launch topic";
  - `land` waits for its PR's CI run to pass **and** for dev's latest verdict to be green (exit 75 on the timeout, naming the run);
  - the check plan's escalation returns.
- CI reads the file and prints the mode in its summary.
- orchestration.md (the human guide) gains a short _Modes_ section.

**Acceptance criteria:**

- Mode unit tests:
  - a missing file reads as rapid;
  - an unknown word is refused on write, and reads as rapid with a warning;
  - a write is one commit, then a push.
- `dispatch-pick.test.mjs`: in pre-deployment mode a non-`launch` planned row is passed over with its reason, and a `launch` row starts.
- `land.test.mjs`: in pre-deployment mode, landing refuses (or waits, then exits 75) when:
  - the PR's CI run is failing or pending;
  - dev's latest verdict isn't green (file).

  A green PR on a green dev lands.

- `pnpm test:tooling` passes.

**Blocked by:** 4, 5. **Blocks:** test-gates-2.
