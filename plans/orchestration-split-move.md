## Undo

The aim is only a running backlog session in Caretook with the old tooling and its history; that session sorts out the rest (the watchdog, the dispatcher, moved rows, Risa). It must work after the user stops the move session, from a fresh plain `claude`, with no `pnpm prd`.

**The move keeps a log outside the repo,** `~/git/risa-notes/move-log.md`: before step 1, the move session writes `dev`'s and `origin/dev`'s shas and the lane cap (`.loops/.prd-cap`) into it, then a line as each step starts and ends.

**To roll back,** open a plain `claude` in the main checkout and paste this prompt (also kept at `~/git/risa-notes/rollback-prompt.md`, since a reset can revert this file):

> The Risa move (B-543) was stopped. Roll Caretook back to its pre-move tooling so a backlog session can run, and nothing more. Read `~/git/risa-notes/move-log.md` for the start sha and the last step reached, but check the real state rather than trusting the log: does `scripts/loops/prd.sh` exist on `dev`, is `dev` ahead of or pushed past the start sha, is `com.risa.watchdog` loaded (`launchctl list`)? Then:
>
> 1. If `com.risa.watchdog` is loaded: `risa dispatch --pause`, then `risa autostart remove` (or `launchctl bootout` it).
> 2. If `dev`'s removal commit isn't pushed: `git reset --hard <start sha>`. If it's pushed: `git revert` it and push.
> 3. Put nvm's Node 24 first on PATH, run `pnpm install`, then confirm `pnpm prd status` runs.
> 4. Ask me whether to restore the `pnpm prd *` and `pnpm backlog *` permissions in `.claude/settings.json`. That edit is mine.
> 5. Stop there and tell me to run `pnpm prd plan`.
