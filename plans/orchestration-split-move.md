# Runbook: Orchestration split, the move (stage 2)

> B-543. Run by hand in one session after `orchestration-split`, `orchestration-split-2` and `orchestration-split-3` have landed, on the user's word. Not slices: the tool can't land its own removal. Decisions: [the PRD](orchestration-split-prd.md).

## Before

- All three stage-1 topics are in `dev`; the boundary lint passes with only the named residual list.
- **Hooks run from the project, not the tool's checkout** (B-846): today `stack_hook` (`lib.sh`) and `hooks.mjs` run a hook from the top of the checkout the tool's files are in, which is Caretook's until the move. Risa's copy must run it from the configured project's root (the repo the command runs for), or every stack and test-db hook misses its scripts. Change it in step 2's layout commit, with a test on the sample project from outside it.
- **Write the removal commit first and rehearse it:** on a throwaway branch of `dev`, the commit of step 5 (delete the manifest's core files, exactly the residual list's lines, and any line of CI's two lists, `scripts/ci/quarantine.txt` and `brake-list.txt`, that names a core test: the boundary lint reads those lists as data and doesn't show them). Push it and run GitHub CI (all jobs); it must be green; then delete the branch and keep the commit to reuse.
- `pnpm prd dispatch --pause`; every PRD, slice, plan and hotfix worktree landed or removed (`pnpm prd status` shows none); no managed sessions (the backlog captain, the inbox session and every helper closed; the dispatcher paused, so its keep-alive reopens none); no open asks that need the tooling. Save `pnpm prd status` and `pnpm prd dispatch --dry-run` output to compare.
- **Unload the launchd watchdog** (label `com.caretook.prd-watchdog`, runs `<main>/scripts/loops/prd.sh watchdog`): `pnpm prd autostart remove`.
- **Run the move from a plain `claude` session** in the main checkout, not one the tool opened: a tool-opened session's status line and hooks point at files step 5 deletes.
- The user says go. Each step that touches Caretook's `dev` is shown to the user first.

## Steps

1. **Install the history tool:** `brew install git-filter-repo`, with the user's OK at this step.
2. **Make Risa with its history.** From a fresh clone of Caretook, `git filter-repo` keeping the manifest's core files **and their earlier names** (from `git log --follow --name-only` per file), into `~/git/risa` (local, no remote). Then one commit there for Risa's layout: `loops/`, `backlog/`, `ci/` (the core's CI parts) side by side, so relative imports such as `../ci/` and `../backlog/` still resolve; `test/sample-project/`; the generic role docs (`loops/docs/`) and their budget check; its own `package.json` (no runtime dependencies; vitest, eslint and prettier at Caretook's pinned versions, with their configs and the pnpm settings); a `risa` bin; a short README. Its tests pass there on the sample project.
3. **Make Risa a configured repo of its own** (PRD _Decisions_): its own `risa.json` (its check rules, no stack hooks), a short AGENTS.md, an empty backlog and inbox, and `plans/`; its sessions read the generic role docs with no additions. Then move the tooling items and rows (`fixes-tooling`'s items, `self-recovery-2`, `staging-ship`, `asks-relay`, `usage-aware-drain`, `risa-next` but for B-795, Caretook's history cleanup, and any other topic whose hot files are all core, read from the registry on the day) with their plans from Caretook's backlog to Risa's, each renumbered `B-n` to `RISA-n` (the same number) with a "was B-n" note; Risa's counter starts above Caretook's highest id. Show the list to the user first, with both ids.
4. **Install a pinned release and put it on PATH:** tag Risa (`v0.1.0`), check the tag out to `~/.risa/releases/v0.1.0`, and symlink `~/.local/bin/risa` to its bin (the PATH agent shells get; the watchdog's plist uses the absolute path). The machine config lists Caretook and Risa, command names `risa`; on this machine Risa's `work` switch stays off (stage 1c slice 8), so nothing here starts work on Risa's backlog; on the work machine the user sets it on. `risa status` and `risa dispatch --dry-run` against Caretook match the saved output.
5. **Remove the core from Caretook:** the rehearsed commit on `dev` (`chore(orchestration-split)!: move the orchestration core to Risa (B-543)` with a `BREAKING CHANGE:` footer), plus setting `risa.json`'s command names to `risa` and changing every doc that names the commands to say `risa …`: AGENTS.md (its _Checks_ rule and _Area index_ too), Caretook's role additions and `preferences.md` in `docs/agents/`, `docs/layout.md`, `docs/domain/data-layer.md`, `ops/runbook.md` and README (`git grep -n 'pnpm \(prd\|backlog\)'` must then find only plans and the backlog's history). Caretook's own scripts' hints follow the config. `pnpm check` and `pnpm test:project` pass; push, and **GitHub CI on `dev` is green** before step 7. The removal also drops `scripts/project/test-projects.test.mjs`'s read of the core's manifest (its allowlisted `project-to-core` line), so `pnpm test:project` needs no core file, and drops `_global`'s `scripts/backlog/` default from `scripts/loops/check-areas.d/` (it then matches no file, and `scripts/project/check-areas.test.mjs`'s lint of the real tree calls it dead; the only rule that does, checked on stage 1's tree without the manifest's core files).
6. **Permissions, the user's change:** `.claude/settings.json` allows `pnpm prd *` and `pnpm backlog *`; the user adds `risa *` (and drops the old ones when ready). Agents don't edit it. Risa's repo gets its own settings the same way.
7. **Try it.** `risa plan` makes and removes one plan worktree in each repo; `risa backlog list` reads each backlog; `risa doc loop` prints the generic doc and Caretook's additions; `risa autostart install` (label `com.risa.watchdog`, running the release's script); `risa dispatch --resume`, and the backlog and inbox sessions reopen with a working status line.
8. **Close out.** B-543 done with a note; the three stage-1 rows flagged `done`; the memory notes that name `pnpm prd` updated.

## Undo

Before Caretook's history is cleaned (`risa-next`): `risa dispatch --pause` and `risa autostart remove` first (never two watchdogs); revert the removal commit on `dev`; move back any rows step 3 moved; `pnpm install`; the user restores the `pnpm prd *` and `pnpm backlog *` permissions if they dropped them; `pnpm prd autostart install`; `pnpm prd dispatch --resume`. Risa's repo can stay; nothing in Caretook depends on it.
