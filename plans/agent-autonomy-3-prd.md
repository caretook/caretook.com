## Problem

Agents still ask the user things they could settle, and the user answers almost every question with the recommendation. Two overnight stalls (a31, a33) waited hours for answers already recommended. Defaults after 30 minutes (agent-autonomy wave 1) shorten the wait but still spend it. And the riskiest steps, a forced landing or one without review, wait for the user even when the evidence is plain.

## Solution

Before a session asks the user or takes a risky landing, a fresh, skeptical second opinion on Fable reads the evidence. It either decides (when the choice is reversible and within the rules) or confirms the question is really the user's. For `--force` and `--no-review`, its go is enough, and the user reads what it said in the landing report. Planners get the same check, which can send a plan back, and a design-heavy topic can plan on Fable.

## User stories

1. As the user, I want a session's question checked by a fresh skeptic first, so that I only see questions that are really mine. (B-511)
2. As an orchestrator, I want the skeptic to decide a reversible question within the rules, so that I carry on without waiting. (B-511)
3. As the user, I want every question the skeptic decided listed with what it chose and why, so that I can veto it. (B-511)
4. As the user, I want questions on the never list always to reach me, so that the skeptic never decides money, data, deploys or compliance. (B-511)
5. As an orchestrator, I want a skeptic's go to let me land `--force` or `--no-review` without asking, so that a plain case doesn't wait for the user. (B-512)
6. As the user, I want the landing report to say what the skeptic said, so that I can veto after. (B-512)
7. As an orchestrator, I want a skeptic to check my reasons before I decline a Codex finding, so that a real bug isn't waved away. (B-512)
8. As a planner, I want the skeptic able to send my plan back once, so that a weak plan is redone before it lands. (B-513)
9. As the user, I want a `design` flag that plans a heavy design topic on Fable, so that the strongest model plans where it matters. (B-513)

## Implementation decisions

- **The skeptic store** is one small file per verdict in the main checkout's `.loops/.skeptic/`: id, kind, verdict (`decide`, `ask`, `go`, `no`, `send-back`), why, the option it chose, the session and topic, the tip for a land verdict, when. `pnpm prd skeptic record --kind … --verdict … --why "…" [--option <a>] [--tip <sha>]` prints the id; `pnpm prd skeptic [--topic t] [--json]` lists. A pure checker answers "does this record allow this action": the right kind, verdict and action, the same topic, for a landing the same tip, for an ask the same question hash and not used before, and recorded within `CARETOOK_SKEPTIC_MAX_MIN` (60). It also holds the set an ask accepts: an ask `ask`, a land `no`, a plan `send-back`. `skeptic record --kind ask` takes the asker's class, and a `decide` on `--waits` is refused.
- **The brief:** `pnpm prd prompt skeptic ask|land|plan --evidence <file>` prints a short brief: be skeptical, read the evidence and the named files, the rules (the never list from the preferences doc, the planner's _What to ask_, the fixes rules), and answer with the verdict on the first line and one line of why. For `ask`: `decide <option>` only when reversible and within the rules, else `ask`; for the never list always `ask`. For `land`: `go` or `no`. For `plan`: the planner's existing skeptic list, plus `send-back`.
- **Asking:** `pnpm prd ask --question …` needs `--skeptic <id>` with an `ask` verdict unless the session is the dispatcher; without it it files nothing and names the steps. `pnpm prd ask --decided --skeptic <id> --question … --option … --chose <a>` files a settled record ("decided by the skeptic"), listed under "decided for you" with the defaulted ones and dismissed the same way; it is never pushed. `--wait` is unchanged.
- **Landing:** `land --force` and `land --no-review` need `--skeptic <id>` (a `go` for this topic, tip and action) or `--by-user`; `--no-review` on an out-of-credits Codex state needs neither; on a brake, in pre-deployment mode or on an unsynced tip, `--force` needs `--by-user`. A `no` refuses with its why. The landing report and the run-through report print the verdict and why, and every Codex-decline verdict recorded for the topic since its last landing.
- **Codex declines:** the orchestrator handbook's Codex step: before replying "not a bug" or "won't fix" on a thread, run a land skeptic on the finding; a `go` (agree to decline) is quoted in the reply; a `no` makes it an item as today.
- **Planner:** the planner handbook's skeptic pass runs from the `plan` brief; `send-back` → rework, then once more; a second `send-back` → a question with `--skeptic` from that record, or the unattended report.
- **The `design` flag:** `registry.mjs` accepts it (beside test-gates' `launch`); the dispatcher's plan action, the opener's planner line and `pnpm prd plan <topic>` pass `--model fable` for a row flagged `design`, else opus.
- **Prompts and docs:** the run-through orchestrator's and unattended planner's asking paragraphs; the hotfix handbook and prompt (`--force` with `--by-user` on the user's word); the orchestrator's landing rule ("never `--force` unless the user says so" becomes "unless the user says so or a skeptic's go"); the preferences doc's never list.

## Testing decisions

- Tooling unit tests beside the code, against temporary directories and stub binaries; never the real asks queue, skeptic store, backlog or `origin`. Prior art: the asks store and command tests, the landing tests (the PR seam), the dispatcher pick tests, the registry tests, the prompt tests.
- Pure parts alone: the checker (kind, verdict, topic, tip, age), the brief's text per kind.
- No app code: no component, integration or browser checks; each landing runs `pnpm test:tooling` and `pnpm exec eslint scripts`.

## Out of scope

- A skeptic for loops' questions to their orchestrator, and for attended sessions.
- Letting a skeptic approve anything on the never list.
- Verifying that a subagent really ran: the record is the agent's word.
- Opus for backlog and planner sessions: already done (2af650f7).
