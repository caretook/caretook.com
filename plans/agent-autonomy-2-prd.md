## Problem

fixes-bug's orchestrator ran to 208k tokens of context without handing off. A session that large is slower, costs more per step and loses track. Nothing told it, or the user, how big it had grown, and the rule was only "one session per wave".

Backlog sessions grow too: the user runs one for hours from the phone, and the only way to start clean is to close it at the Mac. They aren't recorded, so `pnpm prd status` doesn't show them and nothing reopens one that died.

## Solution

A session past 160k tokens of context is told to hand off to a fresh one and does so at its next safe point without asking. `pnpm prd status` shows every session's size. The dispatcher follows up on one that doesn't rotate.

Every session is recorded, so status shows backlog, hotfix and recovery sessions too. Saying "hand off" in a backlog session, from the phone, opens a fresh one under the same name, with a short brief or with nothing. The dispatcher keeps a backlog session running and reopens it when it dies.

## User stories

1. As the user, I want an orchestrator past 160k tokens of context to rotate at its next safe point without asking, so that sessions stay small. (B-507, B-509)
2. As an orchestrator, I want to be told when I cross the limit, with what to do, so that I don't have to watch my own size. (B-507)
3. As a loop, I want to be told when I cross the limit, so that I hand off what I have and a fresh agent continues. (B-507)
4. As an orchestrator in a step that can't resume from _Status_ (a landing under way), I want to say so and finish it, so that a rotation never cuts a landing in half. (B-509)
5. As the user, I want `pnpm prd status` to show each live session's context size, so that I can see who is large. (B-508)
6. As the user, I want the dispatcher to nudge a session that stays over the limit, and then to ask me (rotating it if I'm silent), so that a session that ignores its reminder still gets handed off. (B-508)
7. As the user, I want backlog, hotfix and recovery sessions recorded like orchestrators, so that `pnpm prd status` shows them and a dead one can be reopened. (B-437)
8. As the user on my phone, I want to say "hand off" in a backlog session and get a fresh one under the same name, so that I can start clean without the Mac. (B-514)
9. As the user, I want to choose each time whether the new session gets a short brief of the old one or nothing, so that I control what carries over. (B-514)
10. As the user, I want the dispatcher to keep one backlog session running and reopen it when it dies, outside the three PRD slots, so that one is always there to talk to. (B-515)
11. As the user, I want the context watch to rotate a large backlog session too, with a brief, so that it never grows past the limit. (B-515)
12. As the user, I want a backlog session I opened by hand counted as the live one, so that the dispatcher never opens a second. (B-515)

## Implementation decisions

- **The size** of a session is the usage of the last assistant message in its transcript: input plus cache read plus cache creation tokens. One pure function reads it from transcript text, and returns nothing for a transcript with no usage yet.
- **The hook** is a Claude Code hook that runs after each tool call in sessions the session wrapper starts for an orchestrator (the wrapper passes `claude` a settings file from the tooling; the repo's own settings file is unchanged). It reads the transcript the hook is handed, writes the session's size record, and stays silent under the limit. Over `CARETOOK_CONTEXT_LIMIT` (160,000) it adds a reminder to the agent's context: at the first crossing, then at most every `CARETOOK_CONTEXT_REMIND_MIN` (10). It never blocks a tool call and never fails one: any error in it is swallowed.
- **The reminder's words**, for an orchestrator: its size and the limit; finish the step in hand, commit _Status_, then `pnpm prd rotate --mid-wave --reason "context"` (plain `rotate` with no slice in flight), without asking; only a step that can't resume from _Status_ may finish first, after `pnpm prd context --keep "<why>"` and the reason in _Status_. For a loop (a tool call made by one of the orchestrator's agents, sized from that agent's own transcript, never counted as the orchestrator's): commit, write the hand-off so far and tell the orchestrator to continue the slice with a fresh `--continue` agent.
- **Check the hook's contract first.** The slice that builds this reads the current Claude Code hook documentation before relying on any of it: the hook's input, how context is added for the agent, how a subagent's tool call is told from the session's own and where its transcript is, and how `claude` takes an extra settings file. If a subagent's size can't be read, loops get no reminder and the plan's _Status_ says so; if `claude` takes no extra settings file, the hook goes in the repo's settings file and exits at once in any session the wrapper didn't start.
- **The size record** is one small file per session name in the main checkout's `.loops/`: the session's pid, the size, when it was read, when it was first over the limit, when last reminded, a nudge waiting and when it was delivered, and a keep reason with its expiry. A record whose pid isn't the live session's is stale and ignored.
- **`pnpm prd context`** prints the calling session's size and the limit; `--keep "<why>"` sets the keep for `CARETOOK_CONTEXT_KEEP_MIN` (30), during which the hook and the dispatcher leave the session alone; `--all [--json]` lists every live session.
- **`pnpm prd status`** adds each live session's size to its line, marked when over the limit, with the keep reason when one is set, and "no size yet" for a live session with no record.
- **The dispatcher**, each tick, for each live managed orchestrator over the limit with no keep: `CARETOOK_CONTEXT_NUDGE_MIN` (15) after the first reminder it leaves a nudge in the size record, which the hook delivers at the next tool call in stronger words and marks delivered; the same wait after the delivery, still over, it files a defaulting question ("`<session>` is at `<n>`k context and hasn't rotated", options "rotate it now" (recommended) and "leave it"), with the push sent by its helper. A nudge never delivered (the session is inside one long command) never becomes a question. On "rotate it now" it runs the mid-wave rotation for that topic at the first tick when the session runs no `pnpm prd` command under its process; when rotation refuses (uncommitted plan changes) it files one report. On "leave it" it leaves that session alone until it ends. One question per session. A session that drops under the limit or ends clears everything. `CARETOOK_CONTEXT_WATCH=off` turns the dispatcher's part off.
- **The context question is its own kind:** it carries a marker of its own and its own entry in the dispatcher's state, so the reopen question's matching (any open dispatcher question for the topic) and its "unclear answer: ask again" handling never see it, and both can be open for one topic.
- **This is a pure decision** over the size records, the session records, the asks and "is a command running", like the pick; the tick gathers and acts.
- **The rule** (the orchestrator prompt and handbook): `--mid-wave` on the user's word, or past the limit; the line already on `dev` is reworded to name the hook, the keep command and the dispatcher's follow-up.

### Recorded sessions, hand-off and keep-alive (stories 7 to 12)

- **More kinds:** `session.sh --kind` takes `backlog`, `hotfix` and `recovery` besides `prd` and `plan`. The start sites go through the wrapper with Remote Control under the record's name: `pnpm prd plan` with no topic (the backlog session, today an exec in `prd.sh`), `pnpm prd hotfix`'s `--open` exec and its printed line, and `recover.sh`'s `recover` session (kind `recovery`). The record keeps the model (`--model`) so a rotation reopens on the same one. `pnpm prd status` lists them with their kind. `pnpm prd open <name>` reopens one: a backlog or recovery session fresh in the main checkout, a hotfix with `--continue` in its worktree (the opener learns the main checkout and `hotfix/` branches beside `prd` and `plan`). `tidy` and `end-session` handle worktree-less kinds: an ended backlog record is safe to remove, a live one never.
- **`rotate --self`:** `rotate.sh` finds the caller by matching its ancestor `claude` pid against the live records (not by a `prd-*` name) and, with `--self`, accepts `backlog` (and `inbox` once it exists), and `prd` as plain rotate; other kinds are refused. `rotate-into.sh` reopens by kind: an orchestrator with `--resume` as today, a backlog session with its own prompt in the main checkout, the same name, model and Remote Control. `--brief <file>` puts the file's text at the top of the new prompt under "Brief from the session before"; the file is deleted once read, and any `.loops/.briefs/<name>.md` left from before is deleted when a session of that name starts, so a stale brief never leads a prompt.
- **The prompts:** the backlog prompt (and the inbox prompt, when it exists) gains the hand-off paragraph: on "hand off", ask once which mode, write the brief or not, then `pnpm prd rotate --self [--brief …]`.
- **The keep-alive** is one more pure decision in the dispatcher's tick, beside the pick: when no backlog session is live (no live record, no record `rotating` within `ROTATING_GRACE_MS`, and no `claude` process with `--remote-control backlog`) and the dispatcher isn't paused, open a fresh managed one. It takes no PRD slot. After three quick deaths it files its own question (its own marker and state entry, options "open again" and "stop keeping it alive"), never read as the reopen question. The kinds kept alive are a list (`backlog` now; `inbox` added by whichever of this topic and `inbox-agent` lands second). `CARETOOK_KEEP_SESSIONS=off`.
- **The context watch for backlog sessions:** the hook goes to backlog sessions the wrapper starts, with the backlog words (hand off with a brief at the next pause in the talk, never mid-question). The dispatcher's nudge and question cover managed backlog sessions; its guard is no `pnpm prd` **or `pnpm backlog`** command running under the session (a backlog write commits in the main checkout); its rotation runs `--self` with the brief only if one was written after the nudge's delivery, else none (said in the new prompt).

## Testing decisions

- Tooling unit tests beside the code, against temporary directories and stub binaries; all transcript text is fictional. Prior art: the session wrapper and session record tests, the dispatcher pick and tick tests, the status tests, the prompt tests.
- Pure parts alone: the size read from transcript text, the hook's decision (silent, remind, deliver a nudge, kept), the dispatcher's context decision.
- The hook as a command: a temporary transcript and the hook's input on stdin, asserting its output and the size record; it exits 0 on a missing or unreadable transcript.
- No app code changes: no component, integration or browser checks; each landing runs `pnpm test:tooling` and `pnpm exec eslint scripts`.

## Out of scope

- A hook for planner and hotfix sessions (backlog sessions get it, B-515).
- Keeping hotfix or recovery sessions alive: they are recorded and reopenable, never kept alive.
- Compacting a session instead of rotating it.
- Draining before a usage limit, and cost records (`self-recovery`); stuck workers (`worker-watch`).
